## 1. 문항 길이 가드는 한글 공백·중간점까지 센다

`정답 보기가 최장 오답의 1.4배 이내` 가드에 **2건이 걸렸다**(46자 vs 31자, 37자 vs 25자).
`String.length`라서 공백과 `·`도 한 글자다. 긴 열거형 보기("A · B · C" 형태)가 특히 위험하다.

**예방:** 보기 4개를 **비슷한 길이로 먼저 맞추고** 세부는 해설로 넘긴다. 정답에만 수식어를
붙이면 바로 걸린다. 걸렸을 때는 정답을 줄이는 쪽이 오답을 늘리는 쪽보다 안전하다
(오답을 억지로 늘리면 변별력 없는 보기가 된다).

## 6-b. 라이브 실측 함정 — 워킹카피와 대조하면 전부 MISMATCH로 보인다

릴리스(#231, main `397a13a`) 검증에서 라이브 에셋 바이트를 **로컬 워킹카피**와 대조했더니
12개 파일이 전부 어긋났다. 차이가 **정확히 그 파일의 줄 수**였다(예: `mla-t2-2.md` 56,941 −
56,480 = 461줄). 윈도 체크아웃이라 워킹카피는 **CRLF**인데 git blob과 리눅스 CI 빌드 산출물은
**LF**이기 때문이다. 실제 불일치가 아니다.

**대조는 반드시 blob과 한다:**

```sh
live=$(curl -s "$base/assets/assets/content/mla/$f" | md5sum | cut -c1-8)
blob=$(git show "origin/main:flutter_app/assets/content/mla/$f" | md5sum | cut -c1-8)
```

같은 맥락의 실측 경로 두 가지도 적어 둔다:
- Flutter web 에셋 URL은 **`<base>/assets/assets/content/...`**(`assets/` 가 두 번).
- `AssetManifest.bin.json`은 **base64 문자열 하나**라 grep이 안 먹는다. 앞뒤 따옴표를 떼고
  `base64 -d` 한 뒤 grep해야 `pubspec` 등록 여부를 확인할 수 있다. 자격증별 md 수를 세면
  각 항목이 **2번씩** 잡힌다(키 + variant) — 2로 나눠 읽을 것.

## 6-d. 히어독이 멈춘 진짜 원인 (메모리 `classifier-blocked-git-calls` 보정)

JSON을 일괄 수정하려고 아래처럼 쓴 명령이 2분 타임아웃으로 백그라운드에 넘어갔다.

```sh
python - <<'PY' 2>/dev/null || py - <<'PY'
...script...
PY
```

**분류기 차단이 아니었다.** 출력 파일에 남은 것은
`warning: here-document at line 27 delimited by end-of-file (wanted 'PY')`였다 —
`||` 체인에 **같은 구분자의 히어독을 두 번** 쓰는 바람에 첫 명령이 본문을 다 가져가고
두 번째 `<<'PY'`는 끝나지 않았다. 그래서 `py`가 스크립트 대신 **대화형 REPL**로 떠서
stdin을 기다리며 멈췄다. 스크립트는 **한 줄도 실행되지 않았고** 대상 파일은 무사했다
(`git diff --stat`으로 즉시 확인했다).

교훈 두 가지:
- 히어독은 **한 명령에 하나만**. `cmd1 || cmd2` 폴백이 필요하면 먼저 `command -v python`
  같은 것으로 인터프리터를 정해 변수에 담고, 히어독은 그 뒤 한 번만 쓴다.
- 그래도 **JSON·md 편집은 Edit 도구가 맞다.** 멈춘 명령이 남긴 것은 2분 대기와
  "파일이 깨졌나" 확인 비용뿐이었고, 같은 수정을 Edit으로 하면 바로 끝난다.
- 백그라운드로 넘어간 명령은 **출력 파일을 먼저 읽을 것**. "차단됐다"고 단정하기 전에
  실제 오류 메시지를 보면 원인이 전혀 다른 경우가 있다.
