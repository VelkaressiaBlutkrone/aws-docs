## ⚠️ HANDOFF ②-c의 레시피 한 줄이 틀렸었다 — pubspec

pubspec은 디렉터리를 **개별로** 등록한다(`assets/content/clf/`·`saa/`·`soa/`·`dea/`·`mla/`).
"디렉터리 등록이라 무변경"은 디렉터리가 이미 있을 때만 맞다. **MLA는 #224에서
`- assets/content/mla/`를 추가해 뒀으니 도메인 2~4에서는 다시 건드릴 필요가 없다.**
(새 자격증을 시작할 땐 반드시 추가 — 빠뜨리면 번들 누락으로 라이브 404.)

## 통과해야 하는 가드 7종 (`test/mla_questions_test.dart`)

1. 문항 파일 존재
2. 스키마·밀도 — Task당 **15문항 이상**, options 4개, `correct` 범위, `wrongExplanations`
   키 = 비정답 인덱스 전부, `sources` 비어 있지 않음, **`verified:false`**
3. **문항 `section` ↔ 문서 `{#앵커}` 짝** — 개념 딥링크(`?at=`)가 조용히 죽는 것을 막는다
4. **해설에 마크다운 금지** — 해설·보기·스템은 `Text()` **평문** 렌더(`quiz_widgets.dart:245`·`251`)라
   `**`와 백틱이 화면에 글자로 보인다
5. **정답 보기가 최장 오답의 1.4배 이내** — "가장 긴 보기"를 찍게 만들지 않는다
6. **개념 확인(`foundational`) 문항 Task당 5개 이상** — 전부 시나리오형이면 진입 장벽이 높다
7. **문항 파일 top-level `lastVerified`**(YYYY-MM-DD)

난이도 라벨은 레포 규약 **`foundational`·`applied`**만 쓴다(`associate`는 쓰지 않는다 —
시험 등급명과 겹치고 다른 자격증 파일이 쓰지 않는다).

## 문항 작성에서 반드시 볼 것

조사 노트 **§9 「확인 필요 항목」(G-x-n)이 출제 금지 목록**이다. 문서를 쓰기 전에 읽고,
거기 적힌 것은 **정답 근거로 쓰지 않는다**. 도메인 1에서 걸린 유형:
공식 정의가 없는 용어 · 문서 간 수치 불일치 · 문서에 없는 조합.

**리뷰가 잡은 전형적 결함(같은 실수를 반복하지 말 것):**
- 오답 해설이 "문서에 없다"로 끝남 → **무엇이 맞는지** 긍정문으로 쓴다
- 절대어("항상·반드시·~만")가 붙은 오답 → 시험 요령만으로 지워진다
- 스템이 정답을 흘림(예: 정답 메서드의 산출물 이름을 스템에 적음)
- 공식 문장을 한국어로 옮겨 **작은따옴표**로 감싸 원문 인용처럼 보이게 함 → 의역 서술로
- **문항 논리 결함** — 스템의 전제가 정답을 성립시키지 못하는 경우(예: 부분 결측 열은
  어떤 설정을 해도 "열 전체가 null"이 아니므로 삭제되지 않는다)

## 중복을 만들지 말 것

Task 사이에 같은 표를 반복하면 수치가 바뀔 때 두 곳을 고쳐야 한다. 도메인 1에서
정본을 정했다: **입력 모드 → `mla-t1-1.md` 3)**, **Feature Store 설계 → `mla-t1-2.md` 8)**.
다른 문서는 관점 요약 + "정본은 …" 포인터만 둔다.

## 정답 위치는 신경 쓰지 않아도 된다

앱이 네 출제 경로(통합·약점·Task 시험·연습 퀴즈·오답 복습) 모두에서 보기를 셔플하고
`withOptionOrder`가 `correct`와 `wrongExplanations` 키를 함께 재매핑한다.
JSON의 정답 위치 분포는 화면에 영향이 없다.
