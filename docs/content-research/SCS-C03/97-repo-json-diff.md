## 2. 본문이 다른 2건

### 2-1. `기술 1.2.1` — 낱말 하나가 다르다 (교체 필요)

| | 본문 |
|---|---|
| **공식** | 요구 사항에 따라 로그 수집과 스토리지를 **확보할** 소스 파악 |
| 레포 | 요구 사항에 따라 로그 수집과 스토리지를 **보장할** 소스 파악 |

- 영문은 `Identify the sources to secure log collection and storage based on requirements`다. `secure`를 공식 한국어가 **「확보할」**로, 레포 수집분이 **「보장할」**로 옮겼다.
- ⚠️ **개정 표에는 이 변경이 없다**(버전 1.0 한 줄뿐). 즉 **AWS가 개정 번호를 올리지 않고 한국어 번역을 손본 자리**이거나 수집 당시의 번역이 달랐던 자리다. 어느 쪽이든 **현재 공식 문구가 정본**이다.

### 2-2. `기술 6.2.4` — 마침표 하나 (교체 필요, 사소)

| | 본문 |
|---|---|
| **공식** | `… AWS Resource Access Manager(AWSRAM).` (마침표 **있음**) |
| 레포 | `… AWS Resource Access Manager(AWSRAM)` (마침표 **없음**) |

⚠️ **그런데 공식 쪽에 별 문제가 있다** — `(AWSRAM)`은 **공백이 빠진 오기**다. 같은 가이드의 범위 내 서비스 목록은 `AWS Resource Access Manager(AWS RAM)`로 바르게 적고 영문도 `[AWS RAM]`이다.
→ **교체할 때 공식 문구를 그대로 넣되, 본문·문항에서 서비스를 부를 때는 `AWS RAM`을 쓴다**(98-authoring-decisions **D-05**).

## 3. 교체 범위와 방식

- 바꿀 것은 **기술 본문 2건**뿐이다. 도메인 이름·비중·Task 제목·`overview`·`sourceUrl`은 **손대지 않는다.**
- ⚠️ AIF 교체에서 얻은 규율을 그대로 쓴다 — **① 직렬화 왕복이 원본을 바이트 단위로 재현하는지 먼저 단정** ② **바뀐 경로가 정확히 2개임을 기계로 단정** ③ **서식 변환은 하지 않는다**(레포에 format 게이트가 없어 churn이 리뷰 불가 diff를 만든다).
- 파일 형식 실측: **2칸 들여쓰기 다중 행 JSON**이다(AIF·SAA의 한 줄 compact와 다르다). 따라서 diff가 눈으로 검증된다.
- ⚠️ `sourceUrl`은 `ko_kr` 경로를 가리키고 **실측 `200 r=0`**이다. 교체 PR에서 함께 확인한다.
