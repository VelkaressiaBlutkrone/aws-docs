### 2-2. RDS/Aurora 요금 구조와 비용 증폭 요인 (Knowledge 5·8, Skill 3)
- **Multi-AZ ≈ 2배**: 기본(primary)과 대기(standby) 모두 인스턴스 시간·스토리지 과금(복제 전송 요금은 포함). 비프로덕션은 Single-AZ로 구성해 절감 (F-02).
- **읽기 복제본 = 별도 인스턴스 요금**: 복제본 클래스별 시간 과금, **교차 리전 복제본은 리전 간 전송 요금**(생성 시 스냅샷 전송 + 변경마다 전송). MySQL·MariaDB는 첫 복제본에서 연쇄(cascading) 생성하면 원본→복제본 전송만 과금 (F-03). Aurora 복제본은 클러스터 볼륨을 공유(`3-3.md` F-05).
- **중지(Stop)**: 비프로덕션 DB를 최대 **7일** 중지(이후 자동 재시작) — 인스턴스 시간은 무과금이지만 **프로비저닝 스토리지·PIOPS·백업 스토리지·퍼블릭 IPv4는 계속 과금** (F-04).
- **RDS Extended Support**: 커뮤니티 EOL 이후 메이저 버전을 계속 쓰면 vCPU-시간당(Aurora Serverless는 ACU-시간당) **추가 과금**, 연차가 지날수록 단가 상승(예: PostgreSQL 12·US East(오하이오) $0.100→$0.200/vCPU-시간), Multi-AZ 대기 인스턴스도 과금, 업그레이드·삭제 시 중단 (F-09). → "오래된 엔진 버전 유지" 자체가 비용.
- **스토리지**: 확장은 가능하나 **축소 불가**(`3-3.md` F-09) → 자동 확장 상한이 비용 상한. Aurora 스토리지는 자동 증감(`3-3.md` F-03).

### 2-3. 약정 할인 — RDS RI vs Database Savings Plans (Knowledge 5, Skill 3)
| 항목 | RDS Reserved Instances | **Database Savings Plans** | 비고 |
|---|---|---|---|
| 약정 | 1·3년, No/Partial/All Upfront | **1년만**, 선납 없음 | F-05, F-06 |
| 범위 | 리전·엔진·인스턴스 패밀리(크기 유연) | 엔진·패밀리·크기·AZ·**리전** 무관, 서버리스 포함 | F-05, F-06 |
| 크기 유연성 | MySQL·MariaDB·PostgreSQL·Aurora·Oracle BYOL=같은 패밀리 모든 크기·Single/Multi-AZ 모두 / **SQL Server·Oracle License Included=불가**(속성 변경 시 온디맨드 요금) | 해당 없음 | F-05 |
| 할인 | (RI 요율 — 수치는 가격 페이지) | 서버리스 최대 35%·프로비저닝 최대 20%·DynamoDB 온디맨드 최대 18% | F-06 |
| 제약 | RI는 **인스턴스 요금만**(스토리지·I/O 제외) | 7세대 이상 인스턴스, ElastiCache는 Valkey만, Timestream은 InfluxDB만 | F-05, F-06 |
- **병용 불가**: 같은 워크로드에 Database SP와 RDS RI·DynamoDB 예약 용량 할인을 중복 적용할 수 없음 (F-06).
- **그 밖의 약정**: DynamoDB 예약 용량(프로비저닝·단일 리전·Standard 클래스, 3년 최대 77%·1년 최대 54%), ElastiCache 예약 노드(크기 유연), Redshift 예약 노드·Serverless Reservations (F-11, F-13, F-15). Compute/EC2 Instance Savings Plans는 RDS에 적용되지 않음(`4-2.md` F-02: 적용 범위=EC2·Fargate·Lambda).

### 2-5. DynamoDB 비용 최적화 요약 (Knowledge 5·9, Skill 3)
- **모드**: F-10(35% 기준). **전환 제약·온디맨드 한계(이전 피크의 2배)**는 `3-3.md` F-16.
- **테이블 클래스**: Standard(기본·처리량 단가 낮음) vs **Standard-IA**(저장 비용 60% 절감, 처리량 단가 높음) — **저장비가 테이블 총비용의 약 50% 이상**일 때 유리(로그·이력·오래된 게시물), 코드 변경 없이 전환, 보조 인덱스는 같은 클래스 (F-11).
- **예약 용량·Database SP**: 안정적 프로비저닝 테이블=예약 용량(최대 77%), 서비스·리전 이동이 잦으면 Database SP(최대 18%/12%) — 병용 불가 (F-06·F-11).
- **TTL**: 만료 데이터를 자동 삭제해 저장비 절감, **in-Region 삭제는 추가 비용 없음**(글로벌 테이블 복제 삭제는 복제 WCU 소비) (`3-3.md` F-18).
- **백업**: PITR·온디맨드 백업은 저장 GB-월 과금, 복원은 복원 데이터 GB 과금 (F-12).
- **DAX/캐시**: 읽기 집중 시 RCU 과다 프로비저닝 감소 (`3-3.md` F-14).

### 2-6. 캐싱 전략과 DB 비용 (Knowledge 3)
- **패턴**: 지연 로딩(미스 시 DB 조회·적재; 오래된 데이터 가능)·쓰기 시 갱신(항상 최신; 불필요 데이터 적재 가능)·TTL로 절충 (`3-3.md` F-13).
- **비용 효과**: 읽기 부하를 캐시로 돌리면 DB 인스턴스 다운사이즈·읽기 복제본 감소 가능(AWS 서술: RDS MySQL 앞단 ElastiCache로 최대 55% 비용 절감·80배 빠른 읽기). 반면 캐시 노드 비용이 추가되므로 순효과를 계산 (F-13).
- **저렴한 캐시 선택**: Valkey(Serverless 33%·노드 20% 저렴)로 전환하면 기존 예약 노드 할인 유지, **데이터 티어링**(메모리+SSD, 자주 쓰는 데이터가 20% 이하인 워크로드) (F-13).

### 2-7. 연결 관리·프록시 (Knowledge 6)
- **RDS Proxy**: 연결 풀링·다중화로 DB 연결 한도를 넘는 폭주 흡수(Lambda 등), 장애 조치 단축 — 기능은 `3-3.md` F-10, **요금은 DB 인스턴스 vCPU-시간당(Aurora Serverless는 ACU-시간당)**, 초 단위·10분 최소 (F-14). 즉 *연결 수 때문에 인스턴스를 키우는 비용*과 프록시 비용을 비교한다.

### 2-8. 용량 계획과 복제 (Knowledge 5·8)
- **용량 단위**: DynamoDB RCU/WCU(`3-3.md` F-16)·Aurora ACU(0.5 단위, 범위 설정)·Redshift RPU·RDS 인스턴스 클래스+스토리지/PIOPS(`3-3.md` F-09). 단위가 달라 **서비스 간 직접 가격 비교 전에 사용 패턴(평균/피크 비율)부터** 구한다.
- **크기 적정화**: Compute Optimizer가 Aurora·RDS 인스턴스(MySQL·PostgreSQL·Aurora)·RDS 스토리지·Aurora 클러스터 권고, **유휴 권고**는 RDS·DynamoDB 프로비저닝 테이블·ElastiCache(Redis/Valkey)·MemoryDB 포함 (`4-2.md` F-13); Trusted Advisor는 RDS 유휴 인스턴스·RDS/ElastiCache/Redshift/OpenSearch 예약 최적화를 점검 (F-20).
- **읽기 복제본**: 읽기 확장·다운사이즈에 유용하나 복제본마다 인스턴스 요금(F-03). Aurora 복제본 Auto Scaling(`3-3.md` F-05)으로 수요에 맞춰 복제본 수를 조정.

### 2-10. DB 엔진 선택과 마이그레이션 비용 (Knowledge 7, Skill 2·5)
- **엔진 비용 관점**: 상용(Oracle·SQL Server)은 License Included 모델이 있고 이 경우 RI 유연성이 제한(F-05). 오픈소스(MySQL·PostgreSQL·MariaDB) 호환 엔진·Aurora로 옮기면 SQL Server Enterprise(EC2) 기준 RDS PostgreSQL/MySQL **최대 80%**, Aurora **최대 70%** 절감 사례(지침 서술, 워크로드 의존) (F-18).
- **MySQL vs PostgreSQL**(AWS 비교): MySQL=순수 관계형·읽기 빈번 성능·쉬운 시작, PostgreSQL=객체-관계형·고급 기능(구체화 뷰·다양한 인덱스/데이터 타입)·쓰기 빈번 성능·항상 ACID. 비용 차이보다 *기능·호환성*으로 결정 (F-18).
- **마이그레이션**: 동종은 엔진 네이티브 도구/DMS, 이기종은 **SCT로 스키마 변환 + DMS로 데이터 이전**(`3-3.md` F-20). **비용**: DMS는 복제 인스턴스 시간+추가 로그 스토리지(서버리스는 사용한 만큼), **SCT 무료**, DMS 유입 데이터·같은 AZ 내 RDS/Redshift/EC2 전송 무료, 다른 AZ·리전·AWS 외부는 표준 전송 요금 (F-17).
- **지원 종료 리스크**: RDS Custom for Oracle은 2027-03-31 지원 종료(`3-3.md` F-19) — 신규 설계 선택지에서 제외.

### 2-11. 비용 효율적인 DB 유형 — 시계열·열 기반 (Skill 4)
- **시계열**: 전용 TSDB·관계형 확장(TimescaleDB 등)·열 지향 DB·관리형 TSDB 4유형. AWS 관리형은 **Timestream for LiveAnalytics가 신규 불가**이므로 **Timestream for InfluxDB(3: Parquet 열 저장·컴퓨트/스토리지 분리)** 를 검토 (F-16). 관계형 DB에 시계열을 억지로 넣으면 인덱스·파티션 관리 비용이 커짐(기존 학습 서술).
- **열 기반**: Redshift(열 지향 DW, 컴퓨트·관리형 스토리지 분리 과금, 예약), S3+Athena+Parquet(`3-5.md` F-12: 열 형식·압축·파티셔닝으로 스캔 비용 30~90% 절감) (F-15).
- **키-값/문서/그래프**: DynamoDB·DocumentDB·Neptune은 패턴 특화(`3-3.md` F-01).

### 2-12. 비용 관리 도구 (Knowledge 1·2 — 공통)

## 3. 시험에서 묻는 방식 (패턴)
1. **예측 불가 + 관계형**: → **Aurora serverless(구 Serverless v2)**. 함정: DynamoDB(관계형 불가), 프로비저닝 Multi-AZ.
2. **예측 불가 + NoSQL**: → **DynamoDB 온디맨드**. "활용률이 낮다(<35%)"는 단서가 있으면 온디맨드 우위.
3. **안정·예측 + NoSQL**: → **프로비저닝+자동 확장+예약 용량**. 함정: 온디맨드 고정.
4. **오래된 데이터가 대부분인 DynamoDB**: "저장 비용이 처리량 비용의 절반 이상" → **Standard-IA 테이블 클래스** + TTL.
5. **상시 RDS 비용 절감**: → **RDS RI**(크기 유연 엔진) 또는 **Database Savings Plans(1년)**. 함정: Compute/EC2 Savings Plans는 RDS 미적용, RI와 Database SP 병용 불가.
6. **읽기 폭증**: → **읽기 복제본/ElastiCache**; 비용 질문이면 캐시로 인스턴스 다운사이즈 vs 복제본 인스턴스 요금 비교.
7. **Lambda의 DB 연결 폭주**: → **RDS Proxy**(요금: 인스턴스 vCPU-시간당).
8. **개발 DB 비용**: → Single-AZ, **야간 중지(최대 7일)**, 작은 클래스/서버리스. 함정: 중지해도 스토리지·백업은 과금.
9. **오래된 엔진 버전**: "예상치 못한 DB 비용 증가" → **RDS Extended Support** 과금(메이저 업그레이드로 중단).
10. **이기종 이전**: "Oracle→PostgreSQL, 라이선스 절감" → **SCT(무료)+DMS**, 대상은 Aurora PostgreSQL/RDS PostgreSQL.
11. **시계열/열 기반**: "IoT 시계열" → Timestream for InfluxDB(LiveAnalytics는 신규 불가), "대규모 분석 열 기반" → Redshift/Athena+Parquet.
12. **백업 비용**: "백업 보존 35일, 백업 비용이 큼" → 무료 범위(총 프로비저닝 스토리지) 확인, 불필요 수동 스냅샷 삭제, 보존 기간 조정.

## 4. 흔한 함정·혼동 짝
- **Savings Plans와 RDS**: Compute·EC2 Instance SP는 RDS에 적용되지 않지만, **Database Savings Plans**는 RDS·Aurora 등을 대상으로 존재(1년, 7세대+). "RDS는 RI뿐"은 구식.
- **RDS RI는 크기 유연**(MySQL·MariaDB·PostgreSQL·Aurora·Oracle BYOL): "클래스가 바뀌면 RI가 적용 안 된다"는 SQL Server·Oracle License Included에만 해당.
- **RI는 인스턴스만 할인**: 스토리지·I/O는 할인 대상이 아님.
- **Multi-AZ는 약 2배**: 개발 환경에 쓰지 않기. 읽기 복제본은 HA 대용이 아니며 별도 인스턴스 요금.
- **중지된 DB도 과금**: 스토리지·PIOPS·백업(·퍼블릭 IPv4). 7일 후 자동 재시작.
- **Aurora I/O-Optimized**: I/O 지출이 전체 Aurora 지출의 25% 이상일 때 유리, 미만이면 Standard.
- **DynamoDB 온디맨드 ≠ 항상 싸다**: 활용률이 높고 안정적이면 프로비저닝(+예약)이 유리, 35% 미만이면 온디맨드가 저렴.
- **Standard-IA 클래스**: 처리량 단가가 더 높으므로 *처리량 중심 테이블에는 부적합*.
- **예약 용량의 제외 대상**: 복제 쓰기 용량(rWCU)·Standard-IA 테이블은 예약 용량 대상이 아님.
- **PITR은 추가 요금**: 필요한 테이블만 활성화.
- **백업 무료 범위는 계정·리전 합계**: 인스턴스별이 아님. Aurora는 클러스터별 100%.
- **스냅샷 복사본은 항상 과금**(Aurora): 자동 시스템 스냅샷은 복사하지 않는 한 무료.
- **Extended Support 단가는 해마다 오른다**: 방치 시 비용 폭증.
- **Timestream for LiveAnalytics**: 신규 고객 불가 → 문제 보기에 나오면 InfluxDB 쪽이 현행.
- **SCT는 무료**: 비용은 DMS 복제 인스턴스(또는 서버리스)·로그 스토리지·교차 AZ/리전 전송에서 발생.
- **ElastiCache Valkey 전환**: 가격이 더 낮고(33%/20%) 예약 노드 할인도 유지되지만 엔진 호환(Redis OSS API) 확인 필요.

## 6. 자가 점검 문항 후보 (재료)
1. **서버리스 관계형**: 출시 직후 트래픽 예측 불가, MySQL 호환 필요, 운영 최소. → **Aurora serverless(구 Serverless v2)**(ACU 초 단위, 0 ACU 자동 일시정지). 오답: 프로비저닝 Multi-AZ RDS. 근거 `3-3.md` F-07.
2. **DynamoDB 모드**: 프로비저닝 용량 평균 활용률 약 20%, 야간 거의 무트래픽. → **온디맨드**(활용률 35% 미만이면 저렴). 근거 F-10.
3. **테이블 클래스**: 주문 이력 테이블, 저장 비용이 월 총비용의 70%. → **Standard-IA**(저장 60% 절감, 처리량 단가 상승 감안) + TTL. 오답: 프로비저닝 용량 증액. 근거 F-11.
4. **상시 RDS 비용**: RDS MySQL db.r6g.2xlarge를 3년 운영, 크기를 db.r6g.xlarge로 줄일 수 있음. → **RDS RI(사이즈 유연성)** 또는 필요 시 **Database SP(1년)** — 병용 불가. 오답: "클래스가 바뀌면 RI 소멸". 근거 F-05·F-06.
5. **SQL Server 라이선스 포함 RI**: 인스턴스 크기를 키웠더니 RI 할인이 사라졌다. → License Included SQL Server는 **사이즈 비유연**(속성 일치 필요). 근거 F-05.
6. **개발 DB**: 평일 업무 시간만 쓰는 RDS PostgreSQL 비용을 줄이려면? → **Single-AZ + 야간/주말 중지**(최대 7일 후 자동 재시작 유의, 스토리지·백업은 과금). 근거 F-02·F-04, `4-2.md` F-11.
7. **읽기 가속 비용**: 읽기 집중 RDS가 db.r6g.4xlarge. → **ElastiCache(Valkey)로 캐싱 후 다운사이즈** 또는 읽기 복제본(복제본마다 인스턴스 요금, 교차 리전은 전송 요금). 근거 F-03·F-13.
8. **Lambda 연결 폭주**: → **RDS Proxy**(요금: vCPU-시간당). 오답: 인스턴스만 증설. 근거 F-14, `3-3.md` F-10.
9. **백업 비용 계산**: 계정·리전에 MySQL 100 GB와 PostgreSQL 150 GB가 있다. → 무료 백업 스토리지 250 GB(합계), 초과분만 과금. 근거 F-08.
10. **예상치 못한 DB 비용**: 오래된 PostgreSQL 11/12를 그대로 운영 중. → **RDS Extended Support**(vCPU-시간당, 연차 상승) — 메이저 업그레이드로 중단. 근거 F-09.
11. **이기종 이전 비용**: Oracle EE → Aurora PostgreSQL, 라이선스 제거. → **SCT(무료)로 스키마 변환 + DMS로 이전**; DMS 비용=복제 인스턴스+로그 스토리지, 같은 AZ 전송 무료. 근거 F-17.
12. **시계열 IoT**: → **Timestream for InfluxDB**(LiveAnalytics는 신규 불가). 열 기반 대규모 분석 → **Redshift**(관리형 스토리지 분리 과금)·Athena+Parquet. 근거 F-15·F-16.
13. **Valkey 전환**: Redis OSS 예약 노드를 가진 ElastiCache를 비용 절감하려면? → **Valkey 전환**(노드 20% 저렴, 예약 노드 할인 유지). 근거 F-13.
