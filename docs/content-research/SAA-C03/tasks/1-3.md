| 인증서 | ACM: DNS 검증 인증서는 **완전 자동 갱신**, 이메일 검증은 소유자 조치 필요, 가져온 인증서는 자동 갱신 대상 아님 (F-27~29) |

### 2-4. 암호화 키 접근 정책 (Skill 4)
- **키 정책은 필수 리소스 정책**이다. 다른 리소스 정책과 달리 계정/그 아이덴티티에 **자동 권한을 주지 않는다.** 기본 키 정책의 `"Enable IAM User Permissions"`(Principal=계정 루트, `kms:*`)가 **IAM 정책으로 위임**을 가능하게 한다. 이 문장이 없으면 **IAM 허용 정책은 무효**(IAM Deny는 여전히 유효) (F-10).
  - 흔한 장애: IAM에 `kms:Decrypt`를 허용했는데 AccessDenied → 키 정책이 IAM 위임을 켜지 않았거나 해당 주체를 명시하지 않음.
- **교차 계정**: 키 소유 계정의 키 정책이 외부 계정(또는 주체)을 허용 **+** 외부 계정의 IAM 정책이 위임 (F-11).
- 키 정책에서 외부 **계정**을 허용했다면 그 계정의 어떤 사용자·역할에도 IAM으로 위임 가능, **특정 주체**만 명시했다면 그 주체 범위 안에서만 위임 가능.
- 서비스 통합 접근은 grant·`kms:ViaService` 조건을 쓰는 경우가 많다(세부 조건은 이번 조사에서 공식 문장 미확보 → `99-gaps.md`).

### 2-5. KMS vs CloudHSM (선택 기준 갱신)
| 항목 | KMS | CloudHSM |
|---|---|---|
| 하드웨어 | 관리형 다중 테넌트 HSM, **FIPS 140-3 Level 3 검증** (F-12) | **단일 테넌트 전용** HSM, hsm2m.medium **FIPS 140-3 Level 3** (F-13) |
| 키 통제 | AWS가 서비스를 운영(AWS 직원도 평문 키 접근 불가 설계) | 고객이 HSM 사용자·키를 **단독 통제** |
| 통합 | S3·EBS·RDS 등 네이티브 | KMS **사용자 지정 키 저장소(CloudHSM 키 저장소)** 로 KMS 통합 가능 (F-13) |
| 운영·비용 | 낮음 | 높음(클러스터·HSM 시간당 과금) |
| 선택 단서 | 일반 저장 데이터 암호화, **FIPS 140-3 L3만 요구되면 KMS로 충분** | "**전용 하드웨어**", "**단독 통제**", PKI·DB 암호화 오프로드, 온프레미스 HSM 마이그레이션 |
- 사용자 지정 키 저장소는 2종: **CloudHSM 키 저장소**(고객 소유 클러스터) / **외부 키 저장소(XKS)**(AWS 밖 HSM·KMS) (F-13).

### 2-6. 전송 중 암호화·인증서 (Skill 3·7)
- **ACM 퍼블릭 인증서**: ALB/NLB/CloudFront/API Gateway 등에 부착, 무료(통합 서비스용). **내보내기 가능한(exportable) 퍼블릭 인증서**는 별도 요금(FQDN $7, 와일드카드 $79, 발급·갱신 시) (F-30).
- **리전 규칙**: CloudFront → 인증서를 **us-east-1**에서 요청/가져오기. ELB 등 리전 서비스 → **같은 리전** (F-31).
- **갱신**: DNS 검증 + 서비스에서 사용 중 + CNAME 레코드 존재 → 만료 45일 전 점검·자동 갱신. 신규 공개 인증서는 **198일** 유효 주기 표기(과거 395일 인증서는 60일 전 갱신, 갱신 후 198일) (F-27).

### 2-7. 백업·복제·복구 (Skill 5, Knowledge: 데이터 복구)
| 대상 | 수단 | 핵심 사실 |
|---|---|---|
| **S3** | 버전 관리 · CRR/SRR · **RTC** · Object Lock · MFA Delete | RTC: 대부분 초 단위, **99.99% 15분 이내**, SLA 99.9%/월 (F-17). Object Lock은 **버전 관리 버킷**에서만 (F-16) |
| **EBS** | 스냅샷(증분), 암호화 복사 | 암호화 상태 변경 복사 = **전체 복사**(증분 아님) (F-22). CMK 스냅샷만 공유 가능 (F-21) |
| **RDS** | 자동 백업(PITR) + 수동 스냅샷 | 보존 0~35일(콘솔 기본 7, API/CLI 기본 1), 수동 스냅샷 Region당 100 (F-24·25). **암호화는 생성 시만** → 스냅샷 복사(암호화)→복원 (F-26) |
| **DynamoDB** | PITR(최대 35일, 초 단위) · 온디맨드 백업 · AWS Backup | PITR 복구 기간 1~35일 설정, 새 테이블로 복원 (F-23) |
| **중앙화** | **AWS Backup** | 백업 플랜·볼트·교차 리전/계정 복사, **콜드 전환 후 최소 90일** 보관 (F-32), **Vault Lock** (F-33) |
| **Glacier(레거시)** | Vault Lock 정책 | 잠금 완료 후 변경·삭제 불가 (F-34) |
- **불변성 비교**: S3 Object Lock(compliance=루트도 불가, 계정 삭제가 유일한 예외) / Backup Vault Lock(compliance=유예 ≥72시간 후 불변, AWS도 변경 불가) / Glacier Vault Lock(잠그면 불변) / MFA Delete(루트·CLI·버전 관리 필요; 불변성이 아니라 삭제 인증 강화).

## 3. 시험에서 묻는 방식 (패턴)
1. **키 선택**: "키 로테이션·정책·감사 추적이 필요" → SSE-KMS/CMK. "다른 계정과 암호화 스냅샷 공유" → **CMK** 필요(`aws/ebs` 불가). "대량 S3 KMS 호출 비용" → **Bucket Key**.
2. **전용 HSM 규정**: "단독 통제·전용 하드웨어" → CloudHSM(필요 시 KMS 사용자 지정 키 저장소). "FIPS 140-3 Level 3만" → KMS.
3. **인증서**: "CloudFront 커스텀 도메인 HTTPS" → ACM **us-east-1**. "ALB" → 같은 리전. "자동 갱신, 운영 부담 최소" → DNS 검증.
4. **암호화 전환**: "운영 중 미암호화 RDS를 암호화" → 스냅샷 → **암호화 복사** → 복원(전환 시 DMS로 다운타임 최소화 패턴).
5. **불변·랜섬웨어**: "7년 보존, 루트도 삭제 불가" → S3 Object Lock **compliance** + 버전 관리; 백업은 AWS Backup **Vault Lock compliance** + 교차 계정 복사.
6. **복제 RPO**: "객체 복제 15분 SLA" → S3 **RTC**. "리전 장애 대비 객체 사본" → CRR.
7. **민감 데이터**: "S3에 PII가 있는지 자동 탐지" → Macie.
8. **DB 백업 요건**: "5분 단위 PITR, 35일" → RDS 자동 백업 보존 35일 / DynamoDB PITR.

## 4. 흔한 함정·혼동 짝
- **KMS 접근은 "IAM ∩ 키 정책"이 아니다**: 키 정책이 (a) 주체를 직접 허용하면 IAM 없이 가능, (b) 계정 루트 위임 문장이 있으면 IAM만으로 가능, (c) 교차 계정은 양쪽 필요. 위임 문장이 없으면 IAM Allow는 **무효**.
- **AWS 소유 키 vs AWS 관리형 키 vs 고객 관리형 키**: 이름이 비슷. 계정 간 공유·정책 제어·로테이션 설정이 가능한 것은 고객 관리형뿐.
- **KMS 자동 로테이션 불가 대상**: 비대칭·HMAC·가져온 키 자료·사용자 지정 키 저장소 키. AWS 관리형 키는 로테이션 설정 변경 불가(항상 1년).
- **SSE-C**: 2026-04부터 신규 버킷에서 **기본 비활성** — 쓰려면 `PutBucketEncryption`으로 명시 활성화.
- **S3 Object Lock vs MFA Delete vs Vault Lock**: 불변성(WORM) 제공은 Object Lock·Vault Lock. MFA Delete는 삭제 인증(루트 전용, CLI/API만).
- **Backup 콜드 스토리지**: 전환 후 최소 90일 보관 → 보존 기간 ≥ 전환일 + 90일.
- **RDS 백업 보존 기본값**: 콘솔 7일 vs API/CLI 1일; 0으로 바꾸면 자동 백업 중단(0↔비0 변경 시 중단 발생).
- **ACM 갱신 오해**: 가져온 인증서·이메일 검증은 자동이 아님. ACM 퍼블릭 인증서는 "무료"지만 **exportable**은 유료.
- **CloudHSM이 필요한 이유 착각**: FIPS Level 3 인증만으로는 더 이상 KMS를 배제하지 못함.
- **리전 단위 암호화 기본값**: EBS 기본 암호화는 리전별 설정이며 개별 볼륨 예외 불가.

## 6. 자가 점검 문항 후보 (재료)
1. **교차 계정 스냅샷**: 개발 계정의 EBS 스냅샷(기본 `aws/ebs` 키로 암호화)을 운영 계정과 공유해야 한다. → **고객 관리형 키로 재암호화 복사한 스냅샷 + 키를 상대 계정과 공유**(키 정책+상대 IAM). 오답: 공유 시 `aws/ebs` 키 그대로. 근거 F-21·F-11.
2. **WORM 보존**: 감사 로그를 7년간 어떤 관리자(루트 포함)도 삭제할 수 없게 S3에 보관. → **Object Lock compliance 모드(+버전 관리)**; 오답: governance 모드, MFA Delete 단독. 근거 F-19·F-20.
3. **백업 불변성**: 랜섬웨어 대비, 교차 계정 중앙 백업 계정에서 삭제·보존 단축 불가. → **AWS Backup Vault Lock compliance + 교차 계정 복사**(유예 ≥3일 주의). 근거 F-33.
4. **인증서**: CloudFront 사용자 지정 도메인 HTTPS, 갱신 운영 부담 제로. → **ACM 퍼블릭 인증서를 us-east-1에서 DNS 검증으로 발급**(이메일 검증·가져온 인증서는 수동 갱신). 근거 F-27~31.
5. **키 로테이션**: 규정상 키 자료를 180일마다 교체, 운영 개입 없이. → **고객 관리형 대칭 키 + 로테이션 주기 180일**; AWS 관리형 키는 1년 고정, 가져온 키 자료는 자동 로테이션 불가. 근거 F-04~07.
6. **KMS 접근 거부**: 같은 계정 역할에 IAM으로 `kms:Decrypt` 허용했는데 AccessDenied. → **키 정책에 계정 루트 위임 문장("Enable IAM User Permissions")이 없거나 주체가 명시되지 않음**. 근거 F-10.
7. **HSM 규정**: "AWS도 키에 접근 불가, 전용 하드웨어" vs "FIPS 140-3 Level 3 인증". → 전자는 CloudHSM, 후자만이면 KMS로 충족. 근거 F-12·F-13.
8. **RDS 암호화 전환**: 운영 중 미암호화 RDS(MySQL)를 최소 다운타임으로 암호화. → 스냅샷→암호화 복사→복원, 다운타임 제약 시 DMS로 지속 복제 후 전환. 근거 F-26.
