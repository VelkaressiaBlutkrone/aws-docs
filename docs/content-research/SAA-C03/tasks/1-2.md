## 2. 핵심 개념

### 2-1. VPC 방화벽 계층: 보안 그룹 vs 네트워크 ACL (Skill 1)
| 항목 | 보안 그룹(SG) | 네트워크 ACL(NACL) |
|---|---|---|
| 적용 단위 | 리소스(ENI) | **서브넷** (서브넷당 NACL 1개, NACL은 여러 서브넷 가능) |
| 상태 | **Stateful** — 응답은 규칙과 무관하게 허용 | **Stateless** — 응답용 아웃바운드(임시 포트) 규칙 별도 필요 |
| 규칙 종류 | Allow만 | Allow **+ Deny** |
| 평가 | 규칙 전체 종합 | 번호(1~32766) **낮은 순**, 첫 일치에서 종료 |
| 기본 | 새 SG: 인바운드 없음·아웃바운드 전체 허용 | 기본 NACL: 서브넷에 자동 연결 |
| 비용 | 추가 요금 없음 | 추가 요금 없음 |
| 못 걸러내는 트래픽 | AWS DNS·DHCP·인스턴스 메타데이터(IMDS)·ECS 태스크 메타데이터·Windows 라이선스·Time Sync·VPC 라우터 예약 주소 | 동일 목록 + Route 53 Resolver DNS·IMDS 차단 불가 |

- 특정 IP **차단**은 NACL(Deny, 낮은 번호), 인스턴스 단위 **허용 목록**은 SG. SG 규칙 대상에 다른 SG를 참조할 수 있다.
- DNS 필터링은 NACL이 아니라 **Route 53 Resolver DNS Firewall**; 중앙 정책은 **Firewall Manager**(F-23).
- 관리 모범 사례: SSH(22)·RDP(3389)는 특정 IP 대역만 허용, `0.0.0.0/0` 금지, 큰 포트 범위 개방 금지 (F-38).

### 2-2. 서브넷 분할·라우팅 (Skill 2)
- 퍼블릭/프라이빗은 **라우트 테이블**(IGW 경로 유무)로 결정. 3-tier 예: 퍼블릭(ALB·NAT) / 프라이빗 앱 / 프라이빗 데이터(인터넷 경로 없음).
- IPv4 서브넷 크기 /28~/16, 서브넷마다 5개 주소 예약(첫 4개+마지막) (F-06).
- 외부로 나가는 경로: IGW(양방향), **NAT 게이트웨이**(프라이빗→외부 아웃바운드), Egress-only IGW(IPv6), VPC 엔드포인트(AWS 서비스 비공개 경로).

### 2-3. NAT 게이트웨이 (Skill 1) — 현행 사양
| 구분 | 내용 |
|---|---|
| 용량 | 5 Gbps에서 시작해 **자동으로 100 Gbps**까지; 1M pps → 10M pps (F-07) |
| 연결 수 | IPv4 주소 1개당 목적지(IP+포트+프로토콜)마다 55,000 동시 연결, IP 최대 8개 연결 가능 (F-08) |
| 가용성 | **Zonal(AZ별)** NAT GW는 해당 AZ **내부에서만** 이중화. 여러 AZ가 하나를 공유하면 그 AZ 장애 시 다른 AZ도 인터넷을 잃음 → **AZ마다 NAT GW** (F-09) |
| 신규 | **Regional NAT 게이트웨이**: ENI가 있는 AZ로 자동 확장·축소(확장 최대 60분), 자동/수동 모드, **Private NAT 미지원** (F-10) |
| 종류 | Public(EIP 필요, 퍼블릭 서브넷) / Private(EIP 없음, 사설 연결용) |
- (NAT 인스턴스 비교·비용 구조는 `4-4.md`)

### 2-4. VPC 엔드포인트 (Skill 1·Knowledge: 서비스 엔드포인트)
| 유형 | 대상 | 방식 | 비용 | 제약 |
|---|---|---|---|---|
| **Gateway** | **S3, DynamoDB** | 라우트 테이블 항목(PrivateLink 아님) | **무료** | 온프레미스·타 리전 피어링 VPC·Transit Gateway 경유 접근 불가 |
| **Interface** | 140+ AWS 서비스·SaaS | 서브넷에 ENI(사설 IP), **PrivateLink** | AZ당 시간당 + GB당 처리 요금 | DX/VPN 통해 온프레미스에서 접근 가능 |
- S3/DynamoDB는 gateway·interface **둘 다** 지원. VPC 안에서는 gateway(무료), 온프레미스에서는 interface (F-11·F-12).
- 엔드포인트 정책(IAM 정책 문서)으로 접근 가능한 버킷·작업 제한.
- **공개 서비스 엔드포인트**: 리전 엔드포인트(기본), FIPS 엔드포인트(FIPS 140-3), 듀얼스택(IPv4+IPv6). STS는 리전 엔드포인트 권장 (F-37·40).

### 2-5. 엣지·애플리케이션 보호: WAF · Shield · Firewall Manager · Network Firewall
| 서비스 | 계층 | 하는 일 | 핵심 사실 |
|---|---|---|---|
| **AWS WAF** | L7 | 웹 ACL 규칙으로 SQLi·XSS·IP·지역·**rate-based**·봇 통제 | CloudFront용 웹 ACL은 **us-east-1** 생성 (F-16) |
| **Shield Standard** | L3/L4 | 일반 DDoS 자동 방어 | 모든 고객 **무료**·자동 (F-20) |
| **Shield Advanced** | L3/4/**7** | 유료 DDoS: SRT·자동 L7 완화·비용 보호 | 월 $3,000/조직 + 데이터 전송, 1년 약정 (F-21) |
| **Firewall Manager** | 관리 | 다계정 정책 중앙 배포 | WAF·Shield Adv·SG·NACL·Network Firewall·DNS Firewall (F-23) |
| **Network Firewall** | L3~7 VPC | VPC용 관리형 방화벽/IPS, 상태 저장·비저장 규칙 엔진 | Suricata 호환 규칙 (F-24) |
- WAF 규칙: **우선순위 낮은 번호부터** 평가. Allow·Block은 종료, **Count는 비종료**, CAPTCHA/Challenge는 유효 토큰 유무에 따라 종료/비종료 (F-13·14).
- WAF가 붙는 리소스: CloudFront, API Gateway REST, ALB, AppSync, Cognito 사용자 풀, App Runner, Amplify, Verified Access 등 (F-17). **NLB·EC2는 직접 불가**(목록에 없음).
- WAF 요금: 웹 ACL 수 + 규칙 수 + 요청 수 (F-19). Shield Advanced 구독이 보호 리소스의 표준 WAF 비용 포함 (F-22).
- 위협 벡터 매핑: **DDoS → Shield(+CloudFront·Route 53)**, **SQL 인젝션·XSS·봇 → WAF**, 국가/IP 차단 → WAF 지역·IP 규칙(또는 CloudFront 지역 제한).

## 3. 시험에서 묻는 방식 (패턴)
1. **차단 vs 허용**: "특정 악성 IP 대역을 즉시 차단" → NACL Deny(SG 불가). "웹 서버만 443 허용, DB는 앱 SG에서만 3306" → SG 참조 체인.
2. **프라이빗 서브넷 아웃바운드/비공개 경로**: "OS 패치·외부 API 호출" → NAT GW(AZ별). "S3 접근, 인터넷 금지·비용 최소" → S3 gateway endpoint. "온프레미스에서 S3를 비공개로" → interface endpoint(+DX/VPN).
3. **웹 공격 방어 조합**: "SQLi·XSS + 국가 차단 + DDoS + 다계정 일괄" → CloudFront+WAF(us-east-1)+Shield(+Advanced)+Firewall Manager.
4. **자격증명 보관·교체**: "DB 암호 90일마다 자동 교체, 코드 변경 최소" → Secrets Manager(교체). "설정값 저렴하게" → Parameter Store 표준.
5. **앱 사용자 인증**: "모바일 앱 소셜 로그인 후 S3 직접 업로드" → Cognito 사용자 풀+자격 증명 풀.
6. **하이브리드 암호화**: "Direct Connect로 전송 데이터 암호화" → DX 위 IPsec VPN(또는 MACsec).

## 4. 흔한 함정·혼동 짝
- **SG vs NACL**: Deny·번호 순·서브넷 단위·Stateless는 NACL. 응답 임시 포트 규칙 누락이 NACL 단골 장애.
- **WAF vs Shield**: L7 요청 검사(WAF) vs DDoS 완화(Shield). WAF의 rate-based 규칙은 L7 폭주 완화일 뿐 L3/L4 DDoS 방어가 아님.
- **Shield Standard vs Advanced**: 무료·자동·L3/L4 vs 유료·SRT(Business/Enterprise Support 필요)·L7 자동 완화·비용 보호.
- **Count는 종료 동작이 아님** — "첫 일치에서 종료"는 Allow/Block(및 토큰 없는 CAPTCHA/Challenge)에만 해당.
- **Gateway endpoint 범위**: S3·DynamoDB 한정, PrivateLink 아님, 온프레미스/TGW 경유/타 리전 피어링 불가. 그 외 서비스는 interface endpoint.
- **NAT GW "자동 HA" 오해**: 한 AZ 안에서만 이중화. AZ 장애 내성은 AZ별 NAT 또는 Regional NAT.
- **Cognito 두 풀 혼동**: 사용자 풀=인증(JWT), 자격 증명 풀=AWS 자격증명. 둘 다 있어야 하는 것은 아님.
- **Secrets Manager vs Parameter Store**: "자동 교체" 요구가 있으면 Secrets Manager.
- **GuardDuty/Macie/Inspector/Detective/Security Hub**: 탐지(로그) / S3 민감 데이터 / 취약점(CVE·네트워크 노출) / 조사 / 집계.
- **VPC 피어링 비용**: 연결 생성 무료, **같은 AZ 내 전송 무료**, AZ 간·리전 간은 과금 — "처리 요금"이 아니라 표준 데이터 전송 요금.
- **Direct Connect는 전용선이지만 평문** — 암호화 요구 시 MACsec/IPsec.

## 6. 자가 점검 문항 후보 (재료)
1. **IP 차단**: 서브넷 단위로 `203.0.113.0/24`만 즉시 차단하고 나머지 허용 정책은 유지. → **NACL Deny(낮은 번호)**; SG는 Deny 불가. 근거 F-04.
2. **NAT 설계**: 3개 AZ의 프라이빗 서브넷이 패치 다운로드를 해야 하고 한 AZ 장애가 다른 AZ의 아웃바운드를 막으면 안 됨. → **AZ마다 NAT GW + 같은 AZ 라우팅**(또는 Regional NAT GW). 오답: 단일 NAT 공유, NAT 인스턴스 1대. 근거 F-09·F-10.
3. **S3 비공개 경로**: 프라이빗 EC2→S3, 인터넷·NAT 비용 없이. → **S3 gateway endpoint**(+엔드포인트 정책). 변형: 온프레미스→S3 비공개 → interface endpoint. 근거 F-11·F-12.
4. **웹 공격 방어**: CloudFront 뒤 웹앱에 SQLi·XSS·특정 국가 차단·대규모 DDoS 대비. → CloudFront+**WAF(웹 ACL은 us-east-1)**+Shield Advanced. 오답: Shield만으로 SQLi 차단, WAF를 ap-northeast-2에 생성해 CloudFront에 연결. 근거 F-16·F-20·F-21.
5. **다계정 일괄**: 50개 계정에 동일 WAF 규칙·SG 기준선을 새 계정까지 자동 적용. → **Firewall Manager**. 근거 F-23.
6. **자격증명**: RDS 암호 30일 자동 교체, 앱은 런타임 조회. → **Secrets Manager**(교체) / 오답 Parameter Store(내장 교체 없음). 근거 F-30·F-31.
7. **앱 사용자**: 모바일 앱, Google 로그인 후 S3 업로드. → **Cognito 사용자 풀(소셜) + 자격 증명 풀(임시 자격증명)**. 근거 F-32.
8. **DX 암호화**: 10 Gbps 전용 연결 구간 암호화(L2) vs 종단 간. → MACsec / IPsec VPN over DX. 근거 F-35.
