## 2. 핵심 개념

### 2-1. 엣지 네트워킹 서비스 선택 (Knowledge 1)
| 항목 | CloudFront | Global Accelerator | Route 53(DNS) |
|---|---|---|---|
| 계층·프로토콜 | L7 HTTP/HTTPS(gRPC·WebSocket 포함) | L4 **TCP/UDP** 프록시 | DNS |
| 하는 일 | 엣지 **캐싱**+AWS 백본으로 오리진 전달(정적·동적 모두 가속) | 정적 **애니캐스트 IP** 진입점 → AWS 글로벌 네트워크 → 리전 엔드포인트 | 이름→IP 응답을 정책으로 결정(지연·위치·가중치·장애 조치) |
| 고정 IP | ✗(도메인 기반) | **○(고정 IP 2개)** | — |
| 장애 조치 | 오리진 그룹(상태 코드·타임아웃 기반) | 엣지에서 헬스 체크, **DNS 비의존** 수 초 내 | 헬스 체크+TTL 영향 (`2-2.md` F-15) |
| 대표 사용 | 웹사이트·API·동영상·소프트웨어 배포 | 게임(UDP)·IoT(MQTT)·VoIP, 고정 IP/빠른 리전 장애 조치가 필요한 HTTP | 지연 기반 리전 선택·지역 라우팅 |
(F-06·F-07·F-01. 표준 가속기의 엔드포인트는 공식 문서상 **NLB·ALB·EC2 인스턴스·Elastic IP 4종** — CloudFront는 엔드포인트 유형이 아니다.)
- **CloudFront 캐시 계층**: 뷰어 → **엣지(POP)** → **리전 엣지 캐시(REC)** → (선택) **Origin Shield** → 오리진. REC는 개별 엣지보다 캐시 폭이 커 오래 보관하고 오리진 요청을 통합, Origin Shield는 모든 REC 요청이 거치는 추가 계층, **요청 병합(request collapsing)** 으로 동시 다수 요청을 오리진 1회로. 짧은 TTL이라도 오리진 부하를 크게 줄임 (F-01).
- **CloudFront 오리진 장애 조치**: 오리진 그룹(주/보조), 지정 상태 코드·연결 실패·타임아웃 시 보조로 — **GET/HEAD/OPTIONS만**(POST·PUT·DELETE는 미적용), 상태를 추적하지 않는 stateless 방식이라 느린 정상 응답에는 작동하지 않음 (F-02).
- **S3 오리진 보호**: **OAC 권장**(OAI 대체; SigV4·모든 메서드·SSE-KMS·전 리전), 사용자 지정 도메인 HTTPS용 **ACM 인증서는 us-east-1** (F-03·F-04). Lambda@Edge/CloudFront Functions는 `3-2.md` F-23.
- **Route 53 라우팅 (성능 관점)**: **지연 시간**(DNS 리졸버 또는 edns0-client-subnet 기준 최저 지연 리전 — 지리적 최근접과 다를 수 있음), **가중치**(0–255, 0이면 중단), **지리 근접(bias ±1~99, Local Zone 지원)**, 위치(국가·대륙)·페일오버·다중값·IP 기반 — 8종 전체는 `2-2.md` F-16 (F-07).

### 2-2. 네트워크 아키텍처 설계 — 서브넷 티어·라우팅·IP (Knowledge 2, Skill 1·2)
- **서브넷 = 단일 AZ**, IPv4 서브넷 크기 **/28~/16**, 서브넷마다 **5개 IP 예약**(첫 4개+마지막 1개: 네트워크·VPC 라우터·DNS·예약·브로드캐스트). VPC에 **보조 CIDR** 추가 가능(로컬 라우트 자동 추가) (F-08).
- **공용/사설 서브넷**: 라우트 테이블에 **인터넷 게이트웨이(IGW) 경로가 있으면 공용**, 없으면 **사설**. 사설 서브넷의 IPv4 아웃바운드는 **공용 서브넷의 NAT 게이트웨이**(NAT 상세·Regional NAT은 `1-2.md` F-09·10), IPv6 아웃바운드는 **이그레스 전용 IGW**(NAT과 유사하게 인바운드 개시 차단) (F-08).
- **멀티 티어 토폴로지(전형)**: 공용 서브넷(ALB·NAT) → 사설 앱 서브넷 → (인터넷 경로 없는) 데이터 서브넷, **AZ마다 같은 구조 반복**. S3·DynamoDB는 **게이트웨이 엔드포인트**, 나머지 AWS 서비스/온프레미스 접근은 **인터페이스 엔드포인트**(F-13). 보안 그룹·NACL 설계는 `1-2.md`.
- **VPC 할당량(기본)**: VPC당 라우트 테이블 200, 라우트 테이블당 비전파 라우트 500(증액 시 최대 1,000, 성능 영향 가능), 전파 라우트 100(불가) (F-09).
- **IP 계획**: 현재·미래(리전·사업부·인수합병)와 온프레미스까지 포괄, 계층적·요약 가능한 체계, **중복 CIDR 사전 차단**(TGW·피어링은 중복 CIDR 라우팅 불가), CIDR을 충분히 크게, IPv6/듀얼 스택으로 IPv4 고갈 완화, **VPC IPAM**으로 조직 전체 할당·추적 (F-10).

### 2-3. 로드 밸런싱 전략 (Knowledge 3, Skill 4)
| 항목 | ALB | NLB | GWLB |
|---|---|---|---|
| 계층 | **L7** | **L4** | **L3**(모든 IP 패킷) |
| 프로토콜 | HTTP·HTTPS·gRPC | TCP·UDP·TLS | IP(GENEVE 포트 6081) |
| 대상 | IP·인스턴스·**Lambda** | IP·인스턴스·**ALB** | IP·인스턴스(가상 어플라이언스) |
| 특징 | 경로·호스트 라우팅, **가중 대상 그룹**(예 9:1→90/10), HTTP/2·TLS 오프로딩, 알고리즘 라운드 로빈(기본)/최소 미처리 요청 | **수백만 RPS·초저지연**, 급변 트래픽 최적화, **AZ당 고정 IP(Elastic IP 지정 가능)**, 소스 IP 보존(TLS 종료해도), 흐름 해시 | 방화벽·IDS/IPS·DPI **인라인 어플라이언스** 투명 배치·확장, GWLB 엔드포인트 경유, 프록시하지 않음, 5/3/2-tuple 흐름 고정 |
(F-15~F-17. 스티키 세션·교차 영역 기본값은 `2-1.md` F-24·F-25, ELB 유형 표는 `2-1.md` F-23)
- **선택 규칙**: 웹/마이크로서비스/컨테이너 + L7 라우팅=ALB; TCP/UDP·초저지연·고정 IP·소스 IP 보존=NLB; 트래픽을 보안 어플라이언스로 우회=GWLB. **고정 IP + L7**=NLB(Elastic IP) 앞단+ALB 대상, 또는 **Global Accelerator**, 또는 ALB의 IPAM 연동(BYOIP) (F-15·F-16).
- **자동 확장**: ELB는 트래픽에 맞춰 자동 확장(빠르게 늘리고 보수적으로 줄임), 클라이언트는 DNS(Route 53 Alias 등)로 접근하고 IP 하드코딩은 피함. NLB TCP 리스너는 **Global Accelerator 뒤**에 두면 SYN 플러드 완화 (F-15·F-16).

### 2-4. 네트워크 연결 옵션 (Knowledge 4)
| 요구 | 선택 | 핵심 |
|---|---|---|
| VPC 2~3개 직접 연결 | **VPC 피어링** | 비전이, 중복 CIDR 불가, 리전 간 가능(AWS 백본), 병목·SPOF 아님 (F-11) |
| 다수 VPC+온프레미스 허브 | **Transit Gateway** | 전이 라우팅, 다중 라우트 테이블, TGW당 어태치먼트 5,000, VPC 어태치먼트 AZ당 최대 100 Gbps(각 방향, 공식 쿼터 표), 중복 CIDR 경로 비전파 (F-12) |
| 글로벌 다중 리전 WAN | **Cloud WAN** | 정책(JSON)으로 세그먼트·리전·어태치먼트 매핑, 리전별 코어 네트워크 엣지 (F-21) |
| 서비스 비공개 노출(소비자 CIDR 무관) | **PrivateLink** | 제공자 NLB(또는 GWLB)+엔드포인트 서비스, 소비자 인터페이스 엔드포인트, ≥2 AZ 권장 (F-14) |
| AWS 서비스 비공개 접근 | **VPC 엔드포인트** | 게이트웨이(S3·DynamoDB 전용·무료·온프레미스 불가) vs 인터페이스(ENI+사설 IP·온프레미스/피어링/TGW 경유 가능·과금·보안 그룹) (F-13) |
| 빠르게(수 분) 암호화 연결 | **Site-to-Site VPN** | 연결당 터널 2개(IPsec), 표준 터널 1.25 Gbps, 대용량 터널 5 Gbps, ECMP는 TGW+동적 라우팅 (F-19) |
| 안정적 고대역폭 사설 회선 | **Direct Connect** | 전용 1/10/100/400 Gbps·호스팅 50 Mbps~25 Gbps, 기본 비암호화(MACsec은 10/100/400 Gbps 전용 연결의 일부 위치, 또는 VPN), 복원력 모델 99.99%/99.9% (F-18) |
| 하이브리드 DNS | **Route 53 Resolver** | 인바운드(온프레미스→VPC)·아웃바운드(VPC→온프레미스)+전달 규칙, RAM 공유, 추가 DNS 서버 불필요 (F-20) |
- **DX 복원력**: 최대 복원력(99.99% SLA)=서로 다른 장치·온프레미스 2곳 이상·DX 위치 2곳 이상, 높은 복원력(99.9%)=2개 연결·다른 위치. VPN은 **저비용 백업**이며 단일 VPN 연결(VGW)은 ECMP 불가 → 1 Gbps 초과 백업은 TGW+복수 VPN+ECMP(최대 50 Gbps) (F-18·F-19).

### 2-5. 토폴로지 레시피 (Skill 1)
- **글로벌**: Route 53(지연/지리 근접)·CloudFront(캐시 가능+동적 HTTP)·Global Accelerator(비-HTTP/고정 IP)로 사용자 쪽 가속, 리전 간은 TGW 피어링/Cloud WAN, 데이터 계층은 `3-3.md` §2-9. 오리진 이중화는 CloudFront 오리진 그룹 (F-01·F-02·F-06·F-07·F-12·F-21).
- **하이브리드**: DX(주)+Site-to-Site VPN(백업), 여러 VPC는 **DX 게이트웨이/TGW**로 집선, DNS는 Resolver 엔드포인트, 온프레미스에서 AWS 서비스는 인터페이스 엔드포인트(S3 포함) (F-13·F-18~F-20).
- **멀티 티어**: §2-2 3계층+ALB, 고정 IP가 필요하면 NLB/GA, 인라인 보안 검사는 GWLB.

### 2-7. 리소스 배치 (Skill 3)
- **리전 선택 4요소**: ① **규정 준수**(데이터 거주성이 다른 요소보다 우선) ② **지연**(사용자 근접) ③ **비용**(리전별 가격 상이) ④ **서비스·기능 가용성**(신규 기능은 단계적 확대, SLA는 동일) (F-22).
- **AZ 배치**: 티어마다 ≥2 AZ에 분산, TGW 어태치먼트는 AZ마다 서브넷 지정(어태치먼트 없는 AZ는 TGW 도달 불가) (F-12).
- **엣지·온프레미스 배치**: 최종 사용자 근접=CloudFront/Local Zones/Wavelength, 온프레미스 로컬 처리=Outposts (`3-2.md` F-24). 교차 AZ/리전 데이터 전송 비용은 Task 4.4.

## 3. 시험에서 묻는 방식 (패턴)
1. **전 세계 사용자 콘텐츠**: "정적+동적 웹, 지연 감소, 오리진 부하 감소" → **CloudFront**(+Origin Shield). S3 오리진은 **OAC**. 인증서는 us-east-1 ACM.
2. **UDP/고정 IP**: "게임 UDP 서버, 클라이언트 방화벽에 2개 IP만 허용" → **Global Accelerator**. 함정: CloudFront는 UDP·고정 IP 불가.
3. **리전 선택 DNS**: "최저 지연 리전" → **Route 53 latency**; "국가별 콘텐츠" → geolocation; "트래픽 20%만 신규 리전" → weighted(또는 geoproximity bias).
4. **VPC 연결 규모**: "수십 VPC+온프레미스, 전이 라우팅" → **Transit Gateway**(+DX Gateway/transit VIF). "VPC 2개, 최저 비용" → 피어링.
5. **비공개 서비스 노출**: "고객 VPC(CIDR 겹침 가능)에 서비스 비공개 제공" → **PrivateLink**(NLB 뒤).
6. **AWS 서비스 비공개 접근**: "EC2→S3, 인터넷 없이, 추가 비용 없이" → **게이트웨이 엔드포인트**; "온프레미스(DX/VPN)→S3 비공개" → **인터페이스 엔드포인트**.
7. **하이브리드 회선**: "안정적 10 Gbps+, 장애 시 자동 백업" → **DX + VPN(또는 DX 이중화)**; "암호화 필요" → **VPN** 또는 **MACsec**(10/100/400 Gbps 전용).
8. **로드 밸런서 선택**: "L7 경로 라우팅·Lambda 대상" → ALB; "TCP 수백만 RPS·고정 IP·소스 IP 보존" → NLB; "타사 방화벽 인라인" → GWLB; "ALB인데 고정 IP" → NLB(EIP)→ALB 또는 GA.
9. **서브넷 설계**: "웹 공용·앱/DB 사설, 사설 인스턴스 아웃바운드 업데이트" → 공용 서브넷의 NAT 게이트웨이(IPv6는 이그레스 전용 IGW).
10. **배치 의사결정**: "데이터 거주성 규정 vs 최저 지연" → 규정 준수 우선; 신규 서비스 사용 가능 여부 확인.

## 4. 흔한 함정·혼동 짝
- **CloudFront ↔ Global Accelerator**: 캐싱/HTTP vs 비캐시 TCP·UDP/고정 IP. **GA 표준 가속기의 엔드포인트는 NLB·ALB·EC2·EIP 4종이며 CloudFront는 없다**(→ "GA 앞단에 CloudFront" 구성은 성립하지 않음). 두 서비스는 서로 다른 워크로드에 병행해 쓸 수 있다.
- **VPC 피어링 비전이 + 중복 CIDR 금지**(기본 CIDR뿐 아니라 보조 CIDR이 겹쳐도 불가).
- **TGW도 중복 CIDR 불가**: 겹치는 VPC의 경로는 전파되지 않음.
- **TGW 어태치먼트 AZ 함정**: 어태치먼트가 없는 AZ의 리소스는 TGW에 도달할 수 없음; Local Zone 서브넷은 직접 어태치 불가.
- **게이트웨이 엔드포인트(S3·DynamoDB·무료·라우트 테이블)** vs **인터페이스 엔드포인트(PrivateLink·ENI·과금·온프레미스 가능)**.
- **VPN ↔ DX**: DX는 기본 **비암호화**. MACsec은 1 Gbps 전용 연결·호스팅 연결 불가.
- **Site-to-Site VPN**: 표준 터널 1.25 Gbps, 대용량 터널은 **TGW/Cloud WAN 연결 전용**(VGW 불가). ECMP는 **동적 라우팅+TGW**에서만, 정적·VGW는 불가.
- **Route 53 latency ≠ 지리적 근접**: 리졸버 위치/edns0에 좌우되어 물리적으로 가까운 리전이 아닐 수 있음.
- **GWLB는 L3**(L3/L4 아님)이며 프록시하지 않고 GENEVE로 어플라이언스와 교환.
- **NLB 고정 IP는 AZ당 1개**; ALB는 IP가 바뀔 수 있어 고정 IP가 필요하면 NLB/GA/IPAM.
- **CloudFront 오리진 failover는 GET/HEAD/OPTIONS만**, 느린 정상 응답에는 작동하지 않음.
- **서브넷은 AZ 하나에 속함**, 5개 IP 예약 — /28은 가용 11개.

## 6. 자가 점검 문항 후보 (재료)
1. **UDP+고정 IP**: 전 세계 사용자가 접속하는 UDP 게임 서버, 클라이언트 방화벽에는 소수의 고정 IP만 허용. → **Global Accelerator**(애니캐스트 고정 IP 2개, NLB/EC2 엔드포인트, 엣지 헬스 체크). 오답: CloudFront(UDP·고정 IP 불가). 근거 F-06.
2. **S3 정적 웹**: S3 정적 사이트를 CloudFront로만 접근시키고 버킷 직접 접근은 차단. → **OAC** + 버킷 정책(CloudFront 서비스 주체·배포 ARN 조건) + Block Public Access. 사용자 지정 도메인 인증서는 **us-east-1 ACM**. 근거 F-03·F-04.
3. **전이 라우팅**: 30개 VPC와 온프레미스를 연결하고 VPC 간 통신 필요. → **Transit Gateway**(VPN/DX Gateway 어태치먼트). 오답: 피어링 메시(n(n−1)/2=435개). 단, VPC CIDR이 겹치지 않아야 함. 근거 F-11·F-12.
4. **비공개 서비스 노출**: SaaS 제공자가 고객 VPC(CIDR 중복 가능)에 인터넷 없이 서비스 제공. → **PrivateLink**(제공자 NLB+엔드포인트 서비스, 고객 인터페이스 엔드포인트). 근거 F-14.
5. **하이브리드 대역폭**: 온프레미스↔AWS 10 Gbps 안정 연결, DX 장애 시 백업, 구축 전 임시로 빠르게 연결. → **DX(이중화) + Site-to-Site VPN 백업**; 1 Gbps 초과 백업은 **TGW + VPN 여러 개 + ECMP**. 오답: VGW에 VPN 여러 개(ECMP 불가). 근거 F-18·F-19.
6. **ALB + 고정 IP**: 웹 앱은 L7 경로 라우팅이 필요하지만 파트너 방화벽이 고정 IP를 요구. → **NLB(Elastic IP) 앞단 + ALB 대상 그룹**(또는 Global Accelerator). 근거 F-15·F-16.
7. **인라인 보안 검사**: 모든 VPC 아웃바운드 트래픽을 타사 방화벽 어플라이언스로 투명 검사·확장. → **Gateway Load Balancer**(+GWLB 엔드포인트, GENEVE). 근거 F-17.
8. **엔드포인트 선택**: 사설 서브넷 EC2가 S3에 인터넷 없이 접근, 추가 비용 최소화 → **게이트웨이 엔드포인트**; 온프레미스 서버가 DX로 S3에 사설 접근 → **인터페이스 엔드포인트**. 근거 F-13.
9. **리전 선택**: 개인정보 데이터 국내 보관 의무가 있고 사용자는 해외에도 있음. → **규정 준수 우선 리전**에 데이터, 해외 가속은 CloudFront. 근거 F-22.
