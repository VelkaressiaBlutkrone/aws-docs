## 1. 이 문서가 생긴 이유 — 원래 분할은 복원 불가였다

2026-10-20 세션이 "11개 배치로 쪼갰고 B1 완료"를 HANDOFF §0-2026-10-20에 적었으나 **행 단위 매핑은 커밋되지 않았다.** 2026-10-21 재확인에서 그 서술의 행수 자체도 맞지 않는 것을 확인했다.

| HANDOFF §0-2026-10-20 서술 | 행수 |
|---|---|
| B1 (`#168`, 4항목) | 4 |
| B2~B6 | 32 |
| B7~B10 | 63 |
| B11 (flip 대기) | 13 |
| **합** | **112** |
| 같은 문단의 "실질 열림" | **129** |

**17행이 어떤 배치에도 속하지 않는다.** 또 `[누락]` 50 + `[부분]` 84 = 134행에서 129행을 뺀 **제외 5행(이미 해소 3 · 근거 미확보 1 · 작업 불필요 1)의 행 번호가 어디에도 기록되지 않았다.** 따라서 원래 분할은 재현할 수 없고, 이 문서는 **재도출**이다.

제외 5행을 임의로 지목하지 않는다. 이 맵은 **134행 전수를 배정**하고(미배정 0), "이미 해소 / 근거 미확보 / 작업 불필요" 판정은 **각 배치가 저작 시점에 공식 문서로 확인해 그 PR 본문에 적는다.** 추측으로 미리 빼지 않는다.

## 2. 도출 방법 (재현 가능)

1. **행 추출** — `98-existing-gap.md`에서 `[누락]`·`[부분]` 행만 기계 추출. **134행**(`[누락]` 50 · `[부분]` 84)으로 갭 노트 자체 집계와 일치한다.
2. **해소 확정** — B1·B2가 실제로 저작한 행은 **PR 본문의 항목 표**에서 가져왔다(추정 아님). `#168` 4행 · `#172` 5행.
3. **B11 분리** — `saa-t1-1`·`saa-t1-4`·`saa-t2-5`는 사람 flip 대기 문서다. **저작 대상이 이 세 문서인 행**만 B11로 뺐다.
4. **B3~B10 분할** — 갭 노트가 **공식 Task 14개 단위**로 조직돼 있고 문서↔Task 매핑이 `98-existing-gap.md` §0에 커밋돼 있으므로 **Task 경계로 쪼갰다.** 배치의 저작 대상 문서가 매핑에서 바로 나오고, both-added 충돌을 만든 실제 제약(문서 겹침)이 표에서 눈에 보인다.

### ⚠️ 가드 설계 — 문자열 금지가 아니라 "교정 문맥 요구"를 기본으로

이 세션에서 **같은 실수가 다섯 번** 났다. 전부 *틀린 주장을 바로잡는 올바른 문장*이 금지 문자열을 포함해 가드가 터진 경우다.

|---|---|---|

**그래서 가드를 쓸 때 순서를 이렇게 둔다.**

1. **교정 문맥 요구**를 먼저 쓴다 — `if (본문.contains('무작위화')) expect(본문.contains('옛 지침'), isTrue)` 처럼, 주제가 나오면 교정이 함께 있어야 한다고 요구한다.
2. 행 단위·구간 한정으로 좁힌다 — 쿼터 표의 **그 행**만, `body()`(출처 절 이전)만.
3. 문자열 금지는 **단정형 전체**를 집을 때만 쓴다 — `'3,500 PUT/DELETE'` 처럼 수치와 붙은 형태, `'gp3는 버스트 크레딧'` 처럼 부정어가 끼어들 수 없는 형태.
4. 단어 하나(`'66%'`·`'99.95%'`·`'gp3는 버스트'`)를 금지하지 않는다.

- `httpTokens` = `required` → 세션 토큰 없이는 메타데이터를 가져올 수 없고 **IMDSv1 자격증명은 제공되지 않는다**. `optional` → 토큰 없이 가져가면 IMDSv1 자격증명이 돌아온다.
- 기본값은 AMI의 `ImdsSupport`와 계정 수준 기본값의 조합으로 정해진다 — AMI가 `v2.0`이고 계정 기본값이 `no-preference`면 **`required`**, AMI가 `v2.0`이어도 계정 기본값이 "V1 or V2"면 `optional`. AMI `ImdsSupport: v2.0`은 `HttpPutResponseHopLimit`도 **2**로 둔다.
- 적용 수단 — `run-instances --metadata-options HttpTokens=required,HttpPutResponseHopLimit=1` · 기존 인스턴스는 `modify-instance-metadata-options --http-tokens required`.
- 출처: `AWSEC2` API 레퍼런스의 `ModifyInstanceMetadataOptions`·`Image.ImdsSupport`, FedRAMP 사용자 가이드 EC2 절.
- ⚠️ **Session Manager 쪽 근거는 이번에도 확보하지 않았다** — B11 착수 시 별도로 찾거나, 못 찾으면 쓰지 않는다.

**추가 잔여(B3의 부분 저작에서 넘어옴):** `G-1.2-01`의 **GuardDuty·Detective**(→ `saa-t1-4`) · `G-1.2-02`의 **STS 리전 엔드포인트**(→ `saa-t1-1`). 두 행 자체는 B3가 각자 담당 부분을 저작했으므로 행수에 다시 세지 않는다.

**왜 미루는가:** 이 세 문서는 사람 재검수 → `verified:true` flip 대기 중이다. md를 먼저 바꾸면 **검수자가 본 본문과 어긋난다.** flip 완료 후 착수한다.

## 5. 모든 배치에 걸리는 저작 제약

- **`99-gaps.md` V 목록** — 공식 근거를 확보하지 못한 주장은 쓰지 않는다. 수치·단정이 막힌 항목이 있다(대표: V-72 Cloud WAN 범위 · V-74 열 기반 DB 비용 우열).
- **리전 의존 요율**(`99-gaps.md` G-02) — 구체 요율을 쓰지 않고 **과금 축만** 적는다.
- **md는 라이브 콘텐츠다** — 머지·릴리스되면 사이트에 그대로 노출된다. 드래프트 문항과 달리 노출 0이 아니다.
- **문항 대조 필수** — md에 추가한 용어·서술이 같은 문서의 기존 문항과 어긋나지 않는지 전수 확인한다. 특히 `verified:true` 문서는 라이브 문항이다.
- **md 가드에 금지 문장을 추가했으면** `flutter_app/test/saa_question_propagation_test.dart`의 목록에도 한 줄 추가한다(전파 가드 운영 규칙 — HANDOFF §0-2026-10-20).
  - ⚠️ **구분(2026-10-21 B3에서 확정):** 그 목록은 "**md에서 고친 구식 서술이 파생 문항에 남아 있는 것**"을 잡는 용도다. 갭 보강처럼 **없던 내용을 새로 쓴** 경우에는 전파할 정정이 없으므로 선제 등재하지 않는다 — 가드 파일 자신이 경고하듯, `wrongExplanations`가 틀린 주장을 **인용해 반박**하다 그 문구를 포함해 거짓양성이 나기 때문이다.
  - 대신 **배치마다 금지 주장을 SAA 24개 문항 파일 전수로 대조**하고 그 결과(건수)를 PR 본문에 적는다. 0이 아니면 그것이 실제 전파 결함이므로 그 행을 고치고 **그때** 목록에 올린다. B3는 금지 주장 10종 × 24파일 대조에서 0건이었다.
- **Test-First** — 배치마다 가드 테스트를 먼저 작성한다. **금지할 것만 못박고** 요구는 핵심 키워드 수준으로 느슨하게 둔다. 고쳐 넣은 표현까지 `isTrue`로 고정하면 다음 수정이 막힌다(HANDOFF §0-2026-10-20 "가드가 과잉 수정을 고정한다").
