# T6-D4 (비용) 문서 정확성 스캔

도메인 4 = 비용에 최적화된 아키텍처 설계 (비중 20%). 대상 5개 파일(saa-t4-1 ~ saa-t4-5) 정독 후 AWS 사실 주장 검수.
요금 수치보다 동작·구조 정확성 우선. 불확실 항목은 공식 AWS docs(WebFetch/WebSearch)로 대조.

검수 방법 메모: web 대조로 확정한 핵심 사실 — EFS 스토리지 클래스(Standard/IA/Archive)·EFS Intelligent-Tiering, Aurora 최대 클러스터 볼륨, gp2/gp3 IOPS·처리량, Cost Explorer 13/18개월, Aurora Serverless v2 0 ACU 자동 일시정지. 대부분 문서 주장이 공식 자료와 일치했고, 명확한 오류는 1건(Aurora 최대 스토리지)이다.

---

## saa-t4-1.md

핵심 오류 없음.

검수 중 web로 대조해 **정확함을 확인**한 주요 항목(오탐 방지용 기록):
- §6 EFS 계층: Standard / Infrequent Access(IA) / **Archive** 3계층 + EFS Intelligent-Tiering(접근 패턴에 따라 Standard↔IA↔Archive 자동 전환) — 공식 문서와 일치(EFS Archive는 2023-11 출시, 기본 권장 수명주기가 Standard→IA(30일)→Archive(90일)). 근거: https://aws.amazon.com/efs/storage-classes/ , https://docs.aws.amazon.com/efs/latest/ug/lifecycle-management-efs.html
- §4 gp2/gp3: gp3 기본 IOPS 3,000·기본 처리량 125 MiB/s, gp2 처리량 "128~250 MiB/s", gp2 기본 3 IOPS/GiB(최소 100·최대 16,000) — 모두 공식 문서와 일치. 근거: https://docs.aws.amazon.com/ebs/latest/userguide/general-purpose.html
- §1·§2 검색 요금 구조, Intelligent-Tiering 검색요금 없음·128KB 미만 모니터링 제외, 최소 보관기간(IA 30일/Glacier Instant·Flexible 90일/Deep Archive 180일) — 정확.
- §5 데이터 전송: 인바운드 무료, 아웃바운드 월 100GB 무료, 같은 AZ 프라이빗 IP 무료, S3 Gateway Endpoint로 NAT 처리요금 회피 — 정확.

> 참고(범위밖·비플래그): 자가점검 Q3 "100 GiB gp2 기본 IOPS = 300"은 정확(3×100). 본문 표의 gp2 기본 IOPS "최소 100, 최대 16,000"도 정확.

## saa-t4-3.md

- [오류] (conf 9/10) 위치: §3 "Aurora: 10GB 단위로 자동 확장, **최대 128TB**. 미사용 스토리지는 반환."
  주장: Aurora 클러스터 볼륨 최대 크기가 128TB.
  문제: 현재 Aurora 최대 클러스터 볼륨은 **256 TiB**다(호환 엔진 버전 기준). 128 TiB는 2020년 한때의 상한으로, 이후 256 TiB로 상향됨 — 구식 수치를 현재값으로 단정. AWS 공식 문서가 `AuroraVolumeBytesLeftTotal`로 "256 TiB" 한도를 반복 명시.
  근거: https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/Aurora.Managing.Performance.html (Storage scaling — "256-TiB size limit"), https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/CHAP_Limits.html (Amazon Aurora size limits)
  수정제안: "최대 128TB" → "최대 128 TiB(구버전) / 현재 최대 256 TiB" 또는 단순히 "최대 256 TiB"로 수정. (자동 확장 단위 10GB·삭제 시 공간 회수 서술은 정확.)

그 외 web/지식으로 **정확 확인**한 항목:
- §3 RDS 스토리지 자동 확장 후 수동 다운사이즈 불가 — 정확. Aurora 삭제 데이터 공간 회수(DROP/TRUNCATE 시 동적 리사이즈, 약 10TB/일) — 공식과 일치.
- §4 Aurora Serverless v2: 0.5 ACU 단위 스케일, 최솟값 0 ACU 자동 일시정지/재개(별도 설정) — 공식과 일치(전용 페이지 "Scaling to Zero ACUs with automatic pause and resume" 존재). 근거: https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2.html
- §4 DynamoDB 온디맨드(RRU/WRU) vs 프로비저닝(RCU/WCU), 온디맨드가 예측가능·대량에서 더 비쌀 수 있음, 기본 권장 온디맨드 — 정확.
- §2 RDS RI가 인스턴스 클래스·엔진·리전·Multi-AZ 조합에 결부, §5 자동 백업 0~35일·프로비저닝 스토리지 크기까지 백업 무료·수동 스냅샷 독립 수명 — 정확.
- §1·시험포인트 "Savings Plans는 RDS에 미적용(RDS는 RDS RI로만 절감)" — 정확.

- [모호] (conf 5/10) 위치: §4 DynamoDB 표 "모드 전환: 언제든 전환 가능 (전환 후 24시간 내 재전환 제한)"
  주장: 용량 모드는 24시간 내 재전환이 제한된다(일반적 서술).
  문제: 정확한 규칙은 "온디맨드로 전환은 24시간에 1회 제한"에 가깝고, 프로비저닝으로의 복귀는 더 자유롭다. "언제든 전환 가능"과 "24시간 제한"이 병기되어 다소 모호 — 다만 큰 의미 왜곡은 아님.
  근거: https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/HowItWorks.ReadWriteCapacityMode.html
  수정제안: "온디맨드로 전환 시 24시간당 1회 제한, 프로비저닝으로 복귀는 더 유연" 정도로 명확화(선택).

## saa-t4-4.md

핵심 오류 없음.

web/지식으로 **정확 확인**한 항목:
- §3 VPC 엔드포인트: Gateway Endpoint(S3·DynamoDB만, 무료) vs Interface Endpoint/PrivateLink(200+ 서비스, $0.01/GB + ENI 시간요금, 1PB까지 $0.01/GB) — 정확. 근거: https://docs.aws.amazon.com/vpc/latest/privatelink/gateway-endpoints.html , https://aws.amazon.com/privatelink/pricing/
- §2 NAT GW $0.045/시간/AZ + $0.045/GB, 교차 AZ NAT 사용 시 $0.01/GB 추가 — US 리전 기준 정확.
- §1 전송요금: 인바운드 무료, 교차 AZ 프라이빗 IP $0.01/GB(양방향), 인터넷 아웃 $0.09/GB 수준 — 정확.
- §5 VPC 피어링(데이터 처리요금 없음, 전송요금만) vs TGW($0.05/시간 어태치먼트 + $0.02/GB), 피어링 연결 수 N(N-1)/2 — 정확.
- §6 Direct Connect 아웃바운드 단가가 인터넷의 약 1/4($0.02 vs $0.09 수준), 포트 시간요금 별도 — 정확.
- §4 CloudFront↔AWS 오리진 전송 무료, 캐시 히트율이 절감 핵심 — 정확.

- [모호] (conf 6/10) 위치: §6 Direct Connect 표, line 186 `- 아웃바운드 (AWS → 온프레미스) | $0.02/GB 수준 (US 기준) | $0.09/GB 수준`
  주장: (사실 주장 아님) 표의 한 행이 마크다운 표 구분자(`|`)가 아닌 목록 대시(`-`)로 시작.
  문제: 표 행 파이프 형식이 깨져 렌더링 시 해당 행이 표 밖으로 빠지거나 어긋날 수 있음. 사실 오류는 아니며 **표시(렌더) 결함**. 내용($0.02 vs $0.09)은 정확.
  근거: 파일 line 183~187 표 구조 대조(본 검수, 코드 레벨).
  수정제안: line 186 맨 앞 `- ` → `| `로 교정해 표 행 정합성 복구.

> 참고(비플래그): §1 표 "교차 리전 $0.02/GB 수준 (리전별 상이)"은 단가가 리전쌍마다 크게 다르나 "리전별 상이"를 병기해 과도한 단정은 회피. 동작 서술은 정확.

- §5 Cost Anomaly Detection: ML 기반, Cost Monitor + Alert Subscription, 관리형/고객 관리형(최대 10개 값) — 정확.
- §6 비용 할당 태그: Billing Console 활성화 필요, 활성화 전 기간 기본 미반영이나 **backfill로 최대 12개월 소급**(Cost Explorer·Data Exports·CUR 자동 갱신) — 공식 backfill 문서 반영(게이트 검수 2026-06-12). 정확.
- §7 통합 결제 볼륨 할인 합산·RI/SP 공유, §8 Compute Optimizer(CloudWatch 14일+) vs Trusted Advisor(스냅샷 규칙) 역할 구분 — 정확.

> 참고(비플래그): §9 "소비 모델 채택" 예시 "업무 외 시간 중단 시 최대 75% 절감(주 40시간 vs 168시간)"은 40/168≈76%로 산술적으로 정합하며 Well-Architected 문서의 전형적 예시와 부합 — 오류 아님.
