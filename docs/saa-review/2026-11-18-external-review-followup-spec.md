## 1. 개선 목표

이번 개선의 핵심은 기능을 많이 추가하는 것이 아니라 다음 네 가지를 안정화하는 것이다.

1. **콘텐츠 정확성:** AWS 공식 문서와 시험 가이드에 근거한 정보 제공
2. **콘텐츠 무결성:** 시험 가이드·학습문서·문제은행 사이의 일관성 확보
3. **서비스 품질:** 학습 기록, 시험 결과, 오답 분석의 정확한 저장과 표시
4. **유지보수성:** AWS 정책과 시험 범위가 변경되어도 빠르게 수정할 수 있는 구조 확보

| 우선순위 | 구분 | 의미 |
|---|---|---|
| P0 | 필수 수정 | 정확성·데이터 무결성·출시 안정성에 직접적인 영향 |

| P2 | 일반 개선 | 사용성과 운영 편의성 향상 |
| P3 | 장기 개선 | 향후 확장성과 고도화 |

## 3. P0 — 콘텐츠 정확성 및 검증 체계

### 3-1. AWS 공식 시험 가이드와 콘텐츠 동기화

**문제**

시험 가이드가 개정되면 기존 학습문서와 문제은행이 이전 시험 범위를 기준으로 남을 수 있다.

특히 시험 코드가 변경되는 경우 기존 자격증 카드, 시험 가이드 JSON, 문항 데이터, 콘텐츠 인덱스가 서로 다른 상태가 될 수 있다.

**수정 사항**

- 자격증별 공식 시험 가이드 버전 관리
- 시험 가이드 게시일 및 최종 확인일 기록
- 시험 도메인별 비중과 학습문서의 대응 관계 관리
- 시험 범위에서 제외된 서비스와 새롭게 추가된 서비스 추적
- 시험 코드 변경 시 사이트 카드와 콘텐츠 경로의 동기화

**권장 메타데이터**

```json
{
  "certCode": "SAA-C03",
  "guideVersion": "1.1",
  "guidePublishedAt": "2026-10-29",
  "lastVerifiedAt": "2026-11-18",
  "officialSource": "AWS 공식 시험 가이드"
}
```

실제 JSON 구조와 필드 명명 규칙은 기존 데이터 모델을 확인한 뒤 적용한다.

**완료 기준**

- 모든 공개 자격증의 시험 가이드 버전 확인
- 시험 가이드와 도메인 비중의 일치 확인
- 공식 범위 변경 사항이 콘텐츠 검수 목록에 반영됨
- 자동 테스트에서 가이드 누락과 잘못된 자격증 코드 탐지

### 3-2. AWS 서비스 정보 정확성 재검수

**문제**

이전 콘텐츠 감사에서 다음과 같은 유형의 오류가 확인되었다.

- Savings Plans 할인율을 잘못 설명
- Savings Plans와 Reserved Instances의 추천 기준 혼동
- EBS 부팅 볼륨의 저장장치 유형을 SSD로 한정
- S3 Interface Endpoint 관련 설명 오류
- 내결함성과 무중단 운영을 동일하게 설명
- 시험 범위에 포함되지 않는 서비스의 출제 범위 오분류

**수정 사항**

| 검수 영역 | 수정 방향 |
|---|---|
| AWS 서비스 기능 | 현재 공식 문서 기준으로 기능·제약 확인 |
| 요금 및 할인 | 적용 조건과 최대 할인율을 구분 |
| 서비스 비교 | 유사 서비스의 목적과 선택 기준 명확화 |
| 아키텍처 | 가용성·내구성·내결함성·복구 가능성 구분 |
| 네트워크 | Gateway Endpoint와 Interface Endpoint의 차이 검증 |
| 시험 범위 | 공식 시험 가이드에 근거한 범위만 출제 대상으로 분류 |

Savings Plans는 Compute, EC2 Instance, Database, SageMaker AI 유형을 구분해야 한다. 할인율도 상품 유형에 따라 다르므로 단일 수치를 모든 유형에 적용해서는 안 된다.

**완료 기준**

- 이전 감사에서 지적된 P1 오류를 각각 재검수
- 관련 학습문서와 문제은행 동시 수정
- 수정한 내용에 공식 출처와 확인일 기록
- 수정 후 관련 문항의 정답 및 해설 재검증

### 3-3. 문항 검수 메타데이터 강화

**문제**

현재 `verified: true`만으로는 누가, 언제, 어떤 기준으로 문항을 검수했는지 추적하기 어렵다.

**수정 사항**

문항의 기존 JSON 구조를 유지하면서 검수 이력을 별도로 관리하는 방안을 검토한다.

```json
{
  "verified": true,
  "review": {
    "reviewedAt": "2026-11-18",
    "reviewer": "human",
    "guideVersion": "1.1",
    "sourceChecked": true
  }
}
```

위 구조는 제안안이며 기존 문항 스키마와의 호환성을 확인한 후 적용한다.

**검수 항목**

- 정답이 하나로 명확하게 결정되는가?
- 문제 본문에 필요한 조건이 모두 포함되어 있는가?
- 오답 선택지가 실제로 오답인 이유가 명확한가?
- 해설이 정답뿐 아니라 오답의 문제점도 설명하는가?
- AWS 공식 문서의 내용과 일치하는가?
- 현재 시험 범위에 포함되는 내용인가?
- 학습문서의 설명과 충돌하지 않는가?
- 기존 문항과 중복되거나 지나치게 유사하지 않은가?

**완료 기준**

- 문항 검수 기준 문서 작성
- 검수 이력 관리 방법 확정
- 신규 문항의 공개 전 검수 절차 마련
- 검수 완료 상태와 공개 가능 상태의 의미 명확화

## 4. P0 — 콘텐츠 무결성 및 자동 검증

### 4-1. JSON 문항 데이터 검증

**문제**

JSON 문법이 정상이어도 정답 인덱스, 선택지 수, 설명 누락 등으로 실제 시험 화면에서 문제가 발생할 수 있다.

**수정 사항**

문항 데이터에 대한 자동 검증 도구를 추가한다.

| 검증 항목 | 검증 내용 |
|---|---|
| JSON 파싱 | 모든 문항 파일의 JSON 파싱 성공 |
| 필수 필드 | ID, 질문, 선택지, 정답, 해설 존재 |
| ID 중복 | 동일 문제은행 내 문항 ID 중복 금지 |
| 정답 인덱스 | 선택지 범위를 벗어난 인덱스 금지 |
| 선택지 | 최소 선택지 수와 빈 문자열 검사 |
| 정답 형식 | 단일·복수 정답 형식 검증 |
| 검수 상태 | 공개 문항의 verified 상태 확인 |
| 문항 수 | 선언된 수량과 실제 수량 비교 |
| 도메인 | 시험 가이드의 도메인과 매핑 확인 |

**완료 기준**

- 전체 문제은행에 자동 검증 실행 가능
- 오류 발생 시 파일과 문항 ID를 함께 출력
- CI에서 검증 실패 시 배포 차단

### 4-2. 학습문서와 문제은행의 일관성 검증

**문제**

학습문서가 수정되어도 해당 내용을 기반으로 만들어진 문항의 해설이 이전 내용에 머무를 수 있다.

**수정 사항**

- 문항별 관련 학습문서와 주제 연결
- 학습문서 변경 시 영향받는 문항 목록 생성
- 문항 해설과 학습문서의 핵심 개념 비교
- 출처 링크 및 관련 문서 존재 여부 확인

**완료 기준**

학습문서 수정 시 영향을 받는 문항을 추적할 수 있어야 한다.

### 4-3. 콘텐츠 인덱스 및 자산 일관성 검증

**문제**

실제 파일이 존재하더라도 `content_index.dart`, `pubspec.yaml`, 시험 가이드 데이터에서 누락되면 앱에 노출되지 않을 수 있다.

**수정 사항**

- 콘텐츠 파일과 인덱스 비교
- 시험 코드와 콘텐츠 경로 비교
- `pubspec.yaml`의 자산 선언과 실제 파일 비교
- 시험 가이드 JSON과 자격증 목록 비교
- 존재하지 않는 문서 경로 탐지

**완료 기준**

새로운 자격증 콘텐츠를 추가할 때 누락된 등록 작업을 자동으로 알려준다.

## 5. P1 — 웹 서비스 및 학습 UX 개선

### 5-1. 콘텐츠 현황 표시 개선

**문제**

사용자가 자격증별 학습문서와 문제은행의 실제 제공 범위를 직관적으로 파악하기 어렵다.

**수정 사항**

자격증 상세 화면에 다음 정보를 표시한다.

- 학습문서 수
- 공개 문항 수
- 전체 시험 도메인
- 도메인별 문항 수
- 시험 가이드 버전
- 마지막 콘텐츠 검수일

콘텐츠가 준비되지 않은 자격증은 실제 제공 상태와 구분해 표시한다.

### 5-2. 학습문서와 문제은행 연결 강화

**문제**

학습문서를 읽고 관련 문항을 풀거나, 틀린 문항을 다시 학습하는 흐름이 약하면 학습 효율이 떨어진다.

**수정 사항**

- 학습문서에서 관련 문제로 이동
- 문항 해설에서 관련 학습문서로 이동
- 오답노트에서 관련 학습문서로 이동
- 시험 도메인별 학습문서 목록 제공
- 학습문서 완료 여부와 문제 풀이 기록 연계

**완료 기준**

학습문서 → 관련 문제 → 오답 확인 → 관련 학습문서로 이어지는 흐름을 구현한다.

### 5-3. 시험 화면 사용성 개선

**수정 사항**

- 시험 진행 시간 표시
- 미응답 문항 표시
- 문항 표시 및 검토 상태 구분
- 답안 제출 전 미응답 문항 확인
- 시험 종료 후 도메인별 성적 표시
- 오답과 정답의 설명을 구분해서 제공

**완료 기준**

실제 시험과 유사한 응시 흐름을 제공하고, 결과 화면에서 부족한 영역을 확인할 수 있어야 한다.

### 5-4. 오답 분석 신뢰성 개선

**문제**

문항 수가 적은 상태에서 특정 도메인을 취약 영역으로 단정하면 통계가 왜곡될 수 있다.

**수정 사항**

- 도메인별 응시 수 표시
- 정답률과 응시 수를 함께 표시
- 표본 수가 적은 영역은 잠정 결과로 표시
- 최근 응시 결과와 누적 결과 구분
- 취약 영역에 대응하는 학습문서 추천

**완료 기준**

취약 영역 분석이 실제 응시 데이터에 기반하도록 한다.

## 6. P1 — CI/CD 및 품질 관리

### 6-1. 자동화 테스트 확장

현재 CI의 테스트·정적 분석 흐름에 콘텐츠 검증 단계를 추가한다.

**권장 파이프라인**

```text
Pull Request
    |
    v
JSON Schema Validation
    |
    v
Content Index Validation
    |
    v
Question Integrity Tests
    |
    v
Node Review Tests
    |
    v
Flutter Analyze
    |
    v
Flutter Test
    |
    v
Build Verification
    |
    v
Merge / Deploy
```

실제 워크플로 이름과 필수 체크 이름은 현재 저장소 설정을 유지하면서 확장한다.

### 6-2. 릴리스 및 배포 정보 관리

**문제**

GitHub Pages 배포가 완료되더라도 어떤 소스 커밋과 콘텐츠 버전이 실제 배포되었는지 추적하기 어렵다.

**수정 사항**

- 배포 시 커밋 SHA 기록
- 배포 날짜 기록
- 콘텐츠 버전 기록
- 주요 변경사항을 CHANGELOG에 기록
- 문제은행 변경과 앱 기능 변경을 구분

**완료 기준**

사이트에서 제공되는 콘텐츠와 소스 코드의 배포 기준점을 확인할 수 있어야 한다.

## 7. P1 — Android 제품화와의 연계

2026-11-18 제품화 로드맵과 충돌하지 않도록 다음 항목을 구분한다.

| 항목 | 처리 방침 |
|---|---|
| Android 로컬 저장 | 앱 재시작 후 학습 기록 유지 필수 |
| Firebase 초기화 | Android 앱 등록 및 플랫폼별 옵션 분리 |
| Google 로그인 | 웹 팝업 방식과 Android 인증 방식 분리 |
| 계정 삭제 | 앱 내부 경로와 외부 웹 요청 경로 제공 |
| 개인정보처리방침 | 실제 수집 데이터와 Firebase SDK 항목 반영 |
| Data safety | Google Play 제출 전 실제 동작과 대조 |
| 오디오 | 비공개 테스트 시작의 선행 조건에서 제외하고 테스트 기간에 구현 |
| 공지·피드백 | 운영자 공지와 사용자-운영자 피드백만 우선 구현 |
| 사용자 커뮤니티 | 출시 이후 검토 |

### 별도 주의사항

현재 웹에서 정상 동작하는 기능이 Android에서도 동작한다고 가정해서는 안 된다.

특히 로컬 저장소, 외부 링크, 앱 복귀 신호, 오디오 재생은 플랫폼별 구현과 실기기 검증이 필요하다.

이 항목들은 웹 콘텐츠 정확성 개선과 별도 작업으로 관리한다.

## 8. P2 — 장기 개선 과제

### 8-1. AWS 문서 변경 감지

- 공식 AWS 시험 가이드 변경 감지
- AWS 서비스 문서의 주요 변경사항 추적
- 서비스 이름 변경 및 종료 공지 추적
- 변경된 내용과 연관된 학습문서 탐색
- 변경 영향 문항 목록 생성

자동화는 변경 사항을 발견하고 검수 후보를 만드는 데 사용하며, 자동으로 문항을 수정하거나 공개하지 않는다.

### 8-2. 적응형 학습

- 오답률 기반 복습
- 도메인별 학습 우선순위
- 최근 응시 결과 반영
- 반복 오답 문항 추천
- 학습 완료도 기반 시험 추천

### 8-3. 프레젠테이션 학습 화면

기존 오디오 대본을 그대로 슬라이드에 사용하는 것은 피한다.

대본과 원본 학습문서의 내용이 일치하지 않는 문제가 있으므로 다음 중 하나를 먼저 결정한다.

1. 최신 학습문서를 기준으로 슬라이드 생성
2. 학습문서와 동기화가 완료된 오디오 대본에 한해서 제공

오디오 챕터 단위 타임라인과 텍스트 전용 학습 콘텐츠도 구분한다.

## 11. 작업 진행 원칙

1. 한 번에 여러 Epic을 구현하지 않는다.
2. 작업 착수 전 현재 코드와 테스트를 다시 확인한다.
3. 수정 전 실패 테스트를 먼저 작성한다.
4. 기존 웹 기능의 회귀 여부를 반드시 확인한다.
5. 콘텐츠 수정 시 AWS 공식 출처와 확인일을 기록한다.
6. AI가 문항을 수정하더라도 최종 공개 여부는 사람의 검수를 거친다.
7. 작업 완료 시 변경 파일, 테스트 결과, 미해결 항목을 기록한다.
8. 구조 변경이나 데이터 스키마 변경은 별도 설계 및 승인을 거친다.
