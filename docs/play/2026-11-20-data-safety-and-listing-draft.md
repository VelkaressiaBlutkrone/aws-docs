## 1. Data safety 답안

### 1-1. 개요 질문

| 질문 | 답 | 근거 |
|---|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유합니까? | **예(수집)** | 로그인하면 Firebase Auth·Firestore 로 기기 밖에 전송된다. Play 의 「수집」은 기기 밖 전송이다 |
| 모든 사용자 데이터가 전송 중 암호화됩니까? | **예** | Firebase·R2·GitHub Pages 모두 HTTPS 다 |
| 사용자가 데이터 삭제를 요청할 수 있습니까? | **예** | 앱 안 「계정 삭제」(A7) + 위 웹 URL + 이메일 |
| 계정 생성 방식 | **OAuth(Google 로그인)** | 앱 자체 아이디·비밀번호가 없다 |

### 1-2. 수집 데이터

전부 **선택(optional)** 이다 — 로그인하지 않으면 학습 기록은 기기에만 남고 전송되지 않는다(강의 음성을 재생할 때 음성 파일을 내려받는 요청은 별개다 — 아래 「신고하지 않는 것」).
**공유 없음** — Firebase 는 개발자를 대신해 처리하는 **서비스 제공자**라 Play 정의상 「공유」가 아니다.

| 데이터 유형 | 수집 | 목적 | 근거 |
|---|---|---|---|
| 개인 정보 › **이메일 주소** | 예 · 선택 | 앱 기능, 계정 관리 | Firebase Auth 사용자 레코드 |
| 개인 정보 › **사용자 ID** | 예 · 선택 | 앱 기능, 계정 관리 | Firebase uid 가 Firestore 경로 `users/{uid}` 다 |
| 개인 정보 › **이름** | ⚖️ **예 · 선택 권장** | 계정 관리 | 앱 코드는 이름을 읽지 않지만 Google 로그인 시 Firebase Auth 레코드에 표시 이름이 **담길 수 있다**. SDK 가 수집하는 것도 신고 대상이라 신고 쪽이 안전하다 |
| 앱 활동 › **앱 상호작용** | 예 · 선택 | 앱 기능 | 동기 컬렉션 6종(`attempts`·`checks`·`meta`·`plans`·`progress`·`viewed`, `kSyncedCollections`) |
| 앱 활동 › 기타 사용자 생성 콘텐츠 | **예(수집)** · 2026-11-21 갱신 | 앱 기능 · 고객 지원 | ~~자유 텍스트 입력은 없다~~ → **D2 로 생겼다.** 「의견 보내기」의 본문이 자유 텍스트이고 `users/{uid}/feedback` 로 전송된다. `plans`(학습 계획)는 사용자가 고른 날짜·범위라 「앱 상호작용」으로 볼 수도 있다 |
| 메시지 › 기타 인앱 메시지 | **예(수집)** · 2026-11-21 추가 | 앱 기능 · 고객 지원 | D2 피드백이 사용자 → 운영자 **단방향 메시지**다. ⚠️ 이 분류가 적절한지는 **Console 양식 화면이 최종 근거**다(로드맵 §2 규율 · §8-⑤ 가 미확인으로 둔 자리) — 「기타 사용자 생성 콘텐츠」와 둘 다 해당할 수 있다. 어느 쪽이든 **신고하는 쪽이 안전**하다 |

**신고하지 않는 것(실측)**

| 유형 | 이유 |
|---|---|
| 위치(대략·정확) | IP 를 위치 추정에 쓰지 않는다. Firebase Auth 의 보안용 IP 로그는 위치 용도가 아니다 |
| 기기 또는 기타 ID | Firebase Installations·Analytics·Crashlytics·Messaging·광고 SDK 가 **lock 에 없다** — `legal_pages_test` 가 그 부재를 고정한다(넣으면 테스트가 먼저 깨진다) |
| 앱 정보 및 성능(비정상 종료 로그 등) | 위와 같다. `appLog` 는 콘솔에만 찍는다 |
| 오디오·사진·연락처·금융·건강 | 없음. Android 앱도 강의 음성을 재생하지만(D1) **R2 에서 받아 듣기만** 하고 사용자의 음성을 수집하지 않는다(마이크 권한 없음). 내려받을 때 Cloudflare 가 접속 IP 를 처리하는 것은 처리방침에 적는 전송 처리다 |

> ⚠️ **2026-11-21 정정:** 「메시지」가 이 목록에 있었으나 **D2(의견 보내기)로 수집이 생겼다** — 위 1-2 표로 옮겼다. 이 줄을 고치지 않고 D2 를 내보내면 **신고가 부정확해진다.**

### 1-3. 보안 관행

- 전송 중 암호화: 예
- 삭제 요청 방법: 앱 안 「메뉴 › 기기 간 동기 › 계정 삭제」 · 웹 URL · 이메일
- ⚖️ 독립 보안 검토(MASA): 받지 않았다 → 「아니요」

### 1-4. 이메일 삭제 요청 처리 절차(사람)

웹 페이지가 「본인 확인 뒤 지체 없이 삭제하고 결과를 회신」을 약속하므로 받으면 다음을 한다.

1. 요청 메일의 발신 주소가 로그인 이메일과 같은지 본다(다르면 그 계정에서 다시 보내 달라고 회신).
2. Firebase 콘솔 › Authentication 에서 그 이메일의 **uid** 를 찾는다.
3. Firestore 콘솔에서 `users/{uid}` 아래 6개 컬렉션을 지운다 — ⚠️ **문서를 지워도 하위 컬렉션은 남는다.** 컬렉션 단위로 지운다.
4. Authentication 에서 그 사용자를 삭제한다(**문서가 먼저** — 앱의 A7 순서와 같다).
5. 결과를 회신한다.

## 5. 포그라운드 서비스 선언 답안 초안 (2026-11-23)

Android 14 이상을 타겟팅하는 앱은 Play Console **「모니터링 및 개선 › 앱 콘텐츠」**에서 사용하는 포그라운드 서비스 유형을 선언해야 한다(공식 `answer/13392821`). 이 앱은 `targetSdk 36` 이고 강의 백그라운드 재생에 `mediaPlayback` 유형을 쓴다(`AndroidManifest.xml`).

공식이 요구하는 항목은 **기능 설명 · 지연 시 영향 · 중단 시 영향 · 시연 동영상 링크 · 사용 사례 선택**이다. 콘솔의 실제 문구와 글자 수 제한은 공식 도움말에 없으니 입력할 때 맞춘다.

| 항목 | 입력 초안 |
|---|---|
| 포그라운드 서비스 유형 | `FOREGROUND_SERVICE_MEDIA_PLAYBACK`(공식 표의 `TYPE_MEDIA_PLAYBACK`) |

**재생이 사용자 시작인 근거(실측).** 공식은 앱을 열 때 자동으로 나오는 사운드트랙을 이 사용 사례에서 제외한다. 이 앱의 첫 재생은 재생 버튼·목록 선택·제목 옆 이동 버튼에서만 시작된다(`lecture_playlist.dart` · `study_audio_player.dart` · `lecture_transport_bar.dart` · `study_doc_page.dart`). 강의가 끝난 뒤 다음 강의로 넘어가는 자동 전환은 사용자가 시작한 재생의 연속이다.

**동영상에 담을 순서.** 공식은 사용자가 재생을 시작하는 모습을 보여 달라고 요구한다.

1. 앱을 열고 음성이 있는 학습 문서로 들어간다.
2. **재생 버튼을 누르는 장면**을 보여 준다.
3. 홈 버튼으로 앱을 나가도 소리가 이어지는 것을 보여 준다.
4. 알림 또는 잠금화면의 컨트롤로 일시정지하고 다시 재생한다.

촬영에는 `flutter_app/tool/build_android_release.ps1` 과 같은 `audio_lecture=true` 빌드를 쓴다. 이 플래그가 없으면 재생 화면이 나오지 않는다.
