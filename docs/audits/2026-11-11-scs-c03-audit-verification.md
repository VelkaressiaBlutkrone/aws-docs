### ⚠️ 내 탐지기가 틀린 1건 — 규율 재확인

"정답 보기에 '공식이 ~라고 적습니다' 31"을 처음 `공식.{0,40}(적습니다|적는다)`로 재서
**3문항**이 나왔다. 보고와 10배 차이는 보고의 오류가 아니라 **내 탐지기가 좁다는 신호**였고,
정의를 "정답 보기에 `공식`이 들어간 문항"으로 넓히니 **정확히 31**이다. 실제 문구는
`공식은 … 적고`, `공식이 강하게 권합니다`, `공식은 … 권합니다`처럼 어미가 갈린다.
**어형이 갈리는 주장을 리터럴·좁은 정규식으로 세면 0에 가까운 수가 나온다**(2026-11-06 AIF
「PT 필수」가 「된」 한 글자로 뚫린 것과 같은 계열). **큰 격차를 만나면 보고를 의심하기 전에
자기 탐지기를 의심한다.**

## 2. 🔴 `t3-2-q12` — 보고의 근거 셋을 하나씩 가렸다

보고는 세 근거로 승인 차단을 걸었다. 재측정 결과 **①은 부분적으로만, ②는 틀렸고, ③은 맞다.**

### ② 「안내 페이지가 존재한다」 — **보고가 틀렸다** (세 방법으로 측정)

| 방법 | 결과 |
|---|---|
| `curl -sL` | `codeguru/latest/security-ug/end-of-support.html` → **`404 r=0`** |
| 〃 같은 가이드의 다른 슬러그 | `what-is-codeguru-security.html` → **`404 r=0`** |
| 〃 일부러 틀린 슬러그(대조군) | `zz-bogus-slug.html` → **`404 r=0`** (= 가이드 접두사 소멸) |
| 〃 살아 있는 가이드(대조군) | `general/latest/gr/zz-bogus-slug.html` → `200 r=1` → 인덱스 |
| AWS 문서 리더 | `Documentation page not found.` |
| docs 검색 색인 | 그 URL을 **링크하는** SDK·CLI 페이지만 나온다(C++·.NET·Kotlin·CLI 1·CLI 2) |

⚠️ **보고는 2026-11-10에 내가 기록한 함정을 그대로 밟았다** — 검색 색인이 **삭제된 공식
페이지의 내용을 보여 준다**(그 SDK 문서들이 종료 공지문과 URL을 본문에 인용한다). 본문을
읽으면 페이지가 살아 있는 것처럼 보이지만 **그 URL은 열리지 않는다.** 그래서 현재 해설의
「종료 공지 페이지조차 남아 있지 않다」는 **측정된 사실이고 그대로 맞다.**

### ① 「대안으로 Q Developer와 Inspector Code Security 둘 다 든다」 — **부분적으로 맞다**

그 서술이 실재하는 **살아 있는** 페이지를 찾았다: `codecommit/latest/userguide/
how-to-amazon-codeguru-reviewer.html` — "For code review and security scanning
capabilities, consider the following alternatives: **Amazon Q Developer** … **Amazon
Inspector** (Code Security)".

⚠️ **다만 그 페이지는 CodeGuru _Reviewer_(2025-11-07 유지 관리) 쪽이고 CodeGuru _Security_가
아니다.** CodeGuru Security 전용 대체 서술은 지금 열리는 공식 페이지에 없다(안내 페이지가
사라졌기 때문이다). 따라서 현재 오답 근거 `W[2]`(「Q Developer가 CodeGuru 보안을 대체한다는
공식 서술이 아니다」)는 **문자 그대로는 여전히 참**이다.

⭐ **그런데 보고의 직관은 옳다** — AWS 자신이 CodeGuru 계열의 후속으로 **그 둘을 나란히**
권하므로, 보기 [2]와 [3]의 정답·오답을 **Reviewer / Security 구분에 걸어 두는 것은 시험이
묻지 않는 자리**다. 정답키는 방어 가능하지만 **문항이 약하다.**

### ③ 「해설에 저작 메모가 그대로 있다」 — **맞다**

현재 해설(실측 **456자**, 보고의 514자는 과대)에 「사용자 안내서는 전 페이지가 응답하지
않고」·「목록에 없다는 것이 살아 있다는 뜻은 아닙니다」가 있다. 전자는 **내가 어제 측정한
과정**이고 후자는 **저작 규율 메모**다. 학습자에게 필요한 것은 「지원 종료라 설계의 축으로
삼지 않는다」까지다.

### 판정

**재작성한다**(보고 결론에 동의). 다만 사유는 「해설이 공식과 다르다」가 아니라
**메타 문항 + 저작 메모 + 길이 단서**다 — 정답 보기가 110자인데 나머지 셋은 30자 안팎으로
이 뱅크의 **길이 단서 극단 사례**다.

⭐ **재작성에 쓸 정본을 함께 찾았다**: `inspector/latest/user/code-security-assessments.html`
이 "Code Security scans **first-party application source code, third-party application
dependencies, and Infrastructure as Code**"를 그대로 적는다(실측 `200 r=0`). 현재 출처
`findings-types.html`보다 정확하다.
⚠️ 보고의 수정안에 적힌 `inspector/latest/user/code-security.html`은 **죽은 슬러그**다
(`200 r=1` → 가이드 인덱스).

## 5. 1단계를 하다 찾은 라이브 결함 — 프런트매터 `sources` 유실 (2026-11-11)

🔴 를 고치려 `scs-t3-2.md` 를 열었더니 **프런트매터가 깨져 있었다.** 2026-11-10 출처
교정(#439)이 `sources` 목록에 항목을 삽입할 때 앵커를 잘못 잡아 **`lastVerified:` 줄이
목록 중간에** 끼었다.

`lib/content/markdown_parser.dart` 의 `sources` 루프는 `- ` 로 시작하지 않는 줄에서
멈추고, 바깥 루프의 키 정규식 `^([A-Za-z][A-Za-z0-9]*):` 는 **들여쓴 줄에 걸리지
않는다.** 그래서 그 뒤의 항목이 **조용히 버려진다.**

| 파일 | 파일의 sources | 파서가 읽던 것 | 유실 |
|---|---:|---:|---:|
| `scs-t1-2.md` | 13 | 10 | **3** |
| `scs-t1-3.md` | 10 | 8 | **2** |
| `scs-t2-2.md` | 10 | 9 | **1** |
| `scs-t3-2.md` | 13 | 12 | **1** |

⚠️⚠️ **유실된 7개가 바로 #439 가 교정으로 추가한 URL 들이다** — 즉 **어제의 수정이
파싱된 문서에 들어가 있지 않았다.** `study_doc_page.dart` 가 그리는 **「출처 N」 칩**이
그만큼 작게 표시되고 있었다(라이브 문서 4편).

⚠️⚠️ **기존 가드는 전부 통과했다.** `all_content_parse_test` 는 파서가 예외 없이 돌기만
하면 되고, G-84(문항 출처 ⊆ md 출처)는 md **텍스트**를 grep 하므로 파일에 글자가 있으면
찾는다. **「파서가 읽는 것」과 「파일에 있는 것」을 맞대야** 잡힌다.

**수선**: `lastVerified:` 줄을 목록 **뒤로 옮긴다**(내용 불변 · **파일 크기가 바이트
단위로 같다**). **가드**: `content_format_test.dart` 에 파서 루프를 그대로 재현해 전
자격증 md에서 유실 0건을 단정하고, 끼어든 키를 실제로 잡는지 **합성 입력 대조군**으로
고정했다(대조군 둘: 프런트매터 보유 md ≥ 120편 · 깨진 입력에서 1, 수선한 입력에서 2).
민감도는 `git stash` 로 수선을 되돌려 **세 파일을 수치와 함께 집어내는 것**으로 증명했다.

### 함께 뒤집은 2026-11-10 판정 둘

1. ⭐⭐ **살아 있는 공식 페이지가 종료 날짜를 적는다.**
   `cli/latest/reference/codeguru-security/` 본문에 `On November 20, 2025, AWS will

   글자 그대로 있다(추출 본문 2,077자 · 대조군 `batch-get-findings` 3건 양성 ·
   `zzz-known-negative` 0건). **2026-11-10 에 나는 그 페이지의 본문을 읽지 않고**
   「명령 참조라 상태를 말하지 않는다」고 **추정**했고, 그래서 「날짜를 인용할 수 있는
   공식 페이지가 없다」는 결론까지 틀렸다. 이제 **날짜를 쓰고 그 근거를 출처로 단다.**
2. ⚠️ **`index.html` → `/` 의 `r=1` 은 후행 슬래시 정규화다.** `num_redirects` 만 보고

다시 썼다. **단정과 설명이 어긋나면 설명 쪽이 맞을 때가 있다.**

### ⚠️ 한계 — 중복은 Task 내만 본다

**지표는 하한이다** — 전수 쌍 비교는 별 스크립트가 필요하고 임계 아래 중복은 사람이
