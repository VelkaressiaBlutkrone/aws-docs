# 2026-11-17 전 콘텐츠 검증 — 공통 계약

이 문서는 **자격증별 검증 세션 8개가 모두 읽는 단일 계약**이다. 각 세션은 자기 자격증만
검증하고 **보고서 한 편만 쓴다.** 보정(수정)은 **다음 단계의 별 세션**이 하고, flip(공개)은
**사람만** 한다.

---

## 0. 단계 구조 — 지금 어느 단계인가

| 단계 | 하는 일 | 누가 |
|---|---|---|
| **1 (지금)** | 자격증별 **검증 + 보고서 작성** — 콘텐츠는 **한 글자도 고치지 않는다** | 검증 세션 8개(Fable 5.2) |
| 2 | 보고서를 읽고 **보정(수정) 반영** + 가드 추가 | 별 세션(Opus 5.5 또는 Fable 5.2) |
| 3 | **flip(공개)** | **사람만** (`review.mjs flip`) |

**지금 단계에서 콘텐츠를 고치면 2단계가 무엇이 검증 결과이고 무엇이 수정인지 가를 수 없다.**
보고서는 2단계가 **그대로 집행할 수 있는 지시서**여야 한다.

## 2. 검증 축 — 이 순서로 본다

### ① 사실 정확성 (최우선)
공식 AWS 문서와 대조한다. 지문·정답 보기·해설·오답 근거·`skill`·학습문서 본문 전부.

### ② 인용 정확성 — 「URL 은 200인데 그 페이지에 그 사실이 없다」
이 레포가 **가장 반복해 밟은 결함**이다. 출처 URL 을 열어 **그 페이지가 그 문항이 단정하는
사실을 실제로 담는지** 본다.

> ⚠️ **URL 생사(리다이렉트·404)는 2026-11-17 오늘 전수 측정됐다** — 구조 필드 2,351개 중
> 죽은 URL **0건**(정본 `docs/saa-review/2026-11-17-wa-restructure-source-audit.md`).
> **다시 재지 말고** 그 시간을 「페이지가 그 사실을 담는가」에 쓴다. 다만 **새로 제안하는
> 출처 URL 은 반드시 `curl -sL` 로 직접 재서** `200 r=0` 을 확인하고 보고에 적는다.

⚠️ **그 페이지가 다른 보기를 지지하지 않는지도 본다** — 인용 페이지가 **정답을 반증**해
정답이 둘이 된 사례가 있다(`aip-t1-4-q12`).

### ③ 정답 유일성
- 정답이 둘인가 / 정답 보기가 거짓인가
- **참인 보기를 오답으로 두면 정답이 둘이 된다** — 오답 보기 네 개의 참·거짓을 **각각** 본다
- 오답 근거(`wrongExplanations`)가 **그 보기를 틀리게 만드는 이유를 정확히** 적는가
  (「이 시나리오의 핵심이 아닙니다」 같은 **회피형 반박은 저작자도 참·거짓을 몰랐다는 신호**다)

### ④ 문서 ↔ 문항 전파
- **md 가 옳고 문항만 낡은 역방향 잔존**이 이 레포에서 가장 흔하다
- 반대로 md 만 낡은 자리도 본다 — **문항 가드는 `.md` 를 보지 않는다**
- 학습문서 자가 점검 정답이 같은 Task 문항의 정답과 **정반대**인 사례가 있었다

### ⑤ 자격증 간 불일치
같은 사실을 다른 자격증이 다르게 적는 자리. 찾으면 **레포 전역으로 grep 해** 몇 자리인지 센다.
⚠️ **다른 자격증 파일은 고치지 않고** 보고서 `§5 교차 자격증` 에 적는다(2단계가 함께 닫는다).

### ⑥ 닫힌·종료된 서비스·기능 상태
공식 `AWS Lifecycle Changes` 정본은 **하위 세 페이지**다:
`general/latest/gr/maintenance_services.html` · `sunset_services.html` · `full_shutdown_services.html`
(⚠️ 랜딩 `service-lifecycle.html` 은 **용어 정의만** 담는다 — 항목이 없다.)
- 상태 메모는 **가르치는 층**(`skill`·지문·정답 보기·`explanation`)에만 단다.
  **오답 보기를 반박하는 문장에 달면 그 상태가 그 보기를 틀리게 만든 이유처럼 읽혀 거짓이 된다.**
- ⚠️ **목록에 없다 ≠ 살아 있다**(SMS MFA·CodeGuru Security 가 목록 밖인데 종료됐다)
- ⚠️ 트리거는 **기능 이름으로 좁힌다** — `Glacier 저장소 잠금`은 닫혔지만 **S3 Glacier 스토리지
  클래스는 정상**이고, `CloudTrail Lake`는 닫혔지만 **CloudTrail 본체는 정상**이다

### ⑦ 중복·겹침
같은 사실을 두 문항이 묻는 자리. 같은 Task 안과 자격증 전수 양쪽을 본다.
⚠️ **자카드 지표는 하한이고 양방향으로 틀린다** — 0.167 이 실제 중복이고 0.294 가 중복이 아닌
사례가 있다. ⚠️ **한국어 조사 때문에 과소 측정된다**(`인덱스와` ≠ `인덱스를`) — **조사를 벗긴
변형도 함께 재고 상위 쌍은 0.15 대까지 본문을 읽는다.**

### ⑧ 저작 품질 신호
`cd flutter_app && node tool/prescreen.mjs build <cert>` 를 돌려 `build/` 산출물을 읽는다
(gitignored · 콘텐츠를 바꾸지 않는다). `qualityFlags` 내역을 보고서에 **수치로** 적는다.
- `length-cue` — 정답 보기가 최장(1.3배 초과). ⚠️ **양방향이다** — 정답만 깎아 **최단 오답보다
  짧아지는 것도 결함**이다
- `meta-phrasing` — 「공식 서술에 비추어」 같은 **자기 프레임 크러치**(지문·정답 보기만 대상.
  해설의 출처 귀속은 **정당**하다)
- `authoring-memo` — 「자주 출제」·「옛 교재」·「공부 시간」 같은 **저작 과정 메모**
- 정답 인덱스 분포 쏠림 · `difficulty` 쏠림(Task 당 `foundational` 2개 미만)

### ⑨ 범위(scope)
공식 가이드의 **「범위에 해당하지 않는 작업」·「범위 외 AWS 서비스」** 목록과 대조한다.
범위 외 서비스가 **정답**인 문항은 학습 시간 배분 결함이다.
⚠️ 두 목록 모두 스스로 `non-exhaustive` 라고 적으므로 **「목록에 없다」를 「범위 밖」으로
단정하지 않는다** — 이름이 올라 있는 것만 센다.

### ⑩ 커버리지
공식 기술·지식 번호(`exam_guides/<CODE>.json` 의 `skills`/`knowledge`)가 **전부 최소 한 문항에
덮이는가**, 반대로 **어느 번호에 쏠렸는가**.

## 3. 측정 규율 — 이걸 지키지 않은 보고는 2단계가 쓸 수 없다

1. ⚠️⚠️ **「없다」는 세 겹으로 확인한다** — ① 추출 두 방법(`curl` 본문 + AWS 문서 리더)
   ② **알려진 양성 대조군**(그 페이지에 분명히 있는 문구를 같은 방법으로 세서 잡히는지)
   ③ **다른 표현**(동의어·낱말 차이 — `attenuation` 0건인데 같은 사실이 `decays` 로 실재한 사례).
   **대조군을 통과시키기 전의 0건은 결과가 아니다.**
2. ⚠️⚠️ **표 구조로 표현된 사실은 산문 검색으로 못 잡는다** — 비교 표의 `Supported / Not
   supported` 행에만 있는 사실이 실제로 있었다. md 가 영문을 직접 인용하고 있으면 **그 인용문
   그대로** 검색한다.
3. ⚠️ **본문이 얇은 셸 HTML 인 페이지가 있다** — `200 r=0` 인데 본문이 「(moved)」 두 줄인 자리도
   있다. 추출 길이를 함께 적는다.
4. ⚠️ **목차만 담은 페이지를 사실 출처로 쓰지 않는다**(`evaluation-human.html` 606자 등).
5. ⚠️ **공식 내부가 어긋나는 자리가 많다** — 더 **구체적·전용** 페이지를 정본으로 삼고,
   **개수를 단정하지 않는다**(「범주 다섯/여섯」류). 어긋남 자체를 보고에 적는다.
6. ⚠️ **새 출처를 제안할 때 그 페이지가 그 사실을 담는지 본문으로 확인한다.** 제목이 맞아
   보여도 다른 사실인 자리가 있었다.
7. ⚠️ **`repost.aws` · 블로그 · 3자 페이지를 근거로 쓰지 않는다.** 공식 docs·서비스 페이지·
   시험 가이드만. 공식에 없으면 **「확인되지 않았다」로 적고 수정안을 내지 않는다.**
8. ⚠️ **전수로 센다.** 한 자리를 찾으면 그 문구로 **자기 자격증 md + 문항 전수**를 grep 해
   몇 자리인지 적는다 — **「N문항」 목록은 하한이고, 2단계가 그 하한만 고치면 전수 가드를
   초록으로 만들 수 없다.**
9. ⚠️ **정답 인덱스를 추측하지 말고 읽어서 적는다.** 보고가 안 적어서 2단계가 추측하다
   14건 중 6건이 틀린 선례가 있다.
10. ⚠️ **과대 보고도 결함이다.** 「틀렸다」고 적은 것이 실제로 옳아서 2단계가 **멀쩡한 문장을
    고칠** 뻔한 사례가 여러 번 있었다. 확신이 없으면 🟡 로 두고 **왜 확신이 없는지** 적는다.

### 환경
- Python 은 **`py`**(Git Bash 에서 `python` 은 exit 49). ⚠️ **`py -`(stdin) 은 REPL 로 떨어져
  멈춘다** — 스크립트는 **파일로** 쓴다.
- 콘솔이 **cp949** 라 `⚠️`·em dash 를 stdout 에 쓰면 죽는다 — **진단은 파일로, stdout 은 ASCII**.
- `curl -sL -o /dev/null -w '%{http_code} %{num_redirects} %{url_effective}'` — **`-L` 없으면
  `num_redirects` 가 항상 0** 이다.
- 작업 트리는 **CRLF**, git blob 은 **LF**.

## 4. 산출물 — 보고서 한 편

**경로**: `docs/audits/2026-11-17-full-verify/<cert>.md` (예: `saa.md` · `clf-dva.md`)

```markdown
# <CERT> 전수 검증 — 2026-11-17

## 0. 요약
| 판정 | 수 | 뜻 |
|---|---|---|
| 🔴 | n | 사실이 거짓 · 정답이 둘 · 정답이 틀림 (즉시 수정) |
| 🟡 | n | 불완전·모호·출처가 사실을 담지 않음 (수정 권고) |
| 🟢 | n | 품질(길이 단서·메타 문구·중복) — 사실은 옳다 |
| ✅ | n | 통과 |
- 공개 문항 중 🔴: n건  ← **가장 중요한 수치**
- `prescreen` qualityFlags: length-cue n · meta-phrasing n · authoring-memo n (전체 N문항)
- 검증한 출처 URL: 고유 n개 / 그중 「그 사실을 담지 않음」 n개

## 1. 🔴 (문항·학습문서)
### <id> — <한 줄 요약>
- **공개 여부**: verified true/false
- **현재 정답 인덱스**: n  ← 실측값. 추측 금지
- **결함**: 무엇이 거짓인가
- **공식 근거**: <URL> 의 원문 인용 "…"   ← 인용문을 그대로 적는다
- **수정안**: 지문/보기/해설을 이렇게 (정답 인덱스를 바꿔야 하면 **명시**)
- **전수**: 같은 문구가 자기 자격증 md n자리 · 문항 n자리  ← grep 실측

## 2. 🟡  (같은 형식)
## 3. 🟢  (같은 형식, 묶어서)
## 4. 커버리지·범위
## 5. 교차 자격증 — 다른 자격증과 어긋나는 자리 (고치지 않고 적기만)
## 6. 공식 내부 어긋남 / 「확인되지 않음」 — 수정안을 낼 수 없는 것
## 7. 2단계에 넘기는 순서 제안 (의존 관계가 있으면 명시)
```

- **항목마다 문항 ID 와 정답 인덱스 실측값**이 있어야 한다. 「N문항 묶음」만 적으면 2단계가
  전수를 다시 재야 한다.
- 결함이 0인 축도 **「0건, 이렇게 셌다」로 적는다**(2단계가 다시 재지 않도록).

## 5. 금지 — 예외 없음

1. ⛔ **콘텐츠·코드·테스트를 수정하지 않는다.** `assets/content/**` · `lib/**` · `test/**` ·
   `assets/exam_guides/**` 전부. **쓰는 파일은 자기 보고서 하나뿐이다.**
2. ⛔ **`verified: true` 를 쓰지 않는다.** flip 은 사람만 한다.
3. ⛔ **커밋·브랜치 전환·push·stash 금지.** 이 세션들은 **같은 워킹트리를 공유**한다 —
   브랜치를 바꾸면 다른 세션의 작업이 샌다.
4. ⛔ **다른 자격증을 검증하지 않는다.** 교차 참조로 읽는 것은 되지만 보고는 자기 범위만.
5. ⛔ **명세에 없는 것을 추측·즉흥으로 채우지 않는다.** 판단이 막히면 보고서에
   **`NEEDS_CONTEXT`** 로 적고 멈춘다.
6. ⛔ **`flutter test` · `flutter build` 를 돌리지 않는다**(공유 트리에서 느리고 불필요하다).
   `node tool/prescreen.mjs build <cert>` 는 허용 — `build/` 는 gitignored 다.
7. ⛔ **보고서 밖에 파일을 만들지 않는다.** 중간 산출물은 **자기 scratchpad** 에 둔다.
8. **끝나면 보고하고 정지한다.** 다른 단계(보정·flip)로 넘어가지 않는다.
