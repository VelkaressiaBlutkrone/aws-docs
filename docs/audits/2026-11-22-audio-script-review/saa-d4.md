## 컨트롤러 요청

1. **`saa-t4-2`~`t4-5`는 세그먼트 패치보다 현재 문서에서 재생성하는 쪽이 맞아 보인다 — 판단을 요청한다.** 네 편 모두 `enrichedScriptText`가 0개이고 `sourceHash`가 2026-09-03 판본의 것이다. 그 뒤 문서가 절 단위로 늘어(t4-2 §9~§11, t4-3 §6~§10, t4-4 §7~§11, t4-5는 표·함정 보강) R3이 44건이고, R5 25건의 대부분은 풍부화를 거치면 사라지는 `generate` 원본의 형태다. 패치로 가면 새 절의 세그먼트를 손으로 끼워야 하고 `sourceExcerpt`와 문서의 블록 정렬이 어차피 어긋난다. 재생성하면 R3·R5는 대부분 구조적으로 해소되지만 **R1 26건은 풍부화가 옛 문장을 되살리지 않았는지 재생성본에서 다시 대조해야 한다.** 이 판단 때문에 네 편의 R3은 삽입 발화 전문 대신 절 목록으로 적었다(계약 §4의 「제안 발화는 그대로 적용 가능」에서 벗어난 부분이다 — 패치로 결정하면 전문을 써서 보완하겠다).

2. **코드 블록이 발화에서 통째로 빠진다(5편 공통).** 세그먼트 종류에 코드 블록이 없어 문서의 ` ``` ` 블록이 대본에 들어오지 않는다. 그 결과 「예고 문장만 있고 내용이 없는」 자리가 생긴다 — t4-1 seg018(계층 일수)·seg023·seg038, t4-2 스팟 할당 전략·할인 적용 순서, t4-4 NAT 손익식, t4-5 seg023·029·043. 다른 세션 범위에도 같은 패턴이 있을 가능성이 높으니 취합 때 한 번에 볼 만하다.

3. **명칭 표기 결정 요청 — `Aurora serverless`.** `saa-t4-3.md`가 「Aurora Serverless v2」를 「Aurora serverless」(소문자, v2 없음)로 전부 바꿨다. 발화 7개 세그먼트는 옛 이름이다. 의도된 개명 반영인지, 발화에서 「오로라 서버리스」로만 읽으면 되는지 정해 주면 된다. R1이 아니라 R5로 세었다.
