# 학습문서 고도화 (Content Enrichment) — 설계 스펙

작성일: 2026-06-11
상태: 설계 승인됨(브레인스토밍) → 구현 플랜 대기
근거 결정: **모의고사 중량화·문항 증가보다 학습 내용 고도화가 우선** (사용자 지시, 2026-06-11). 고도화 완료 후 모의고사 중량·증가를 별도 검토한다.

## 1. 문제

63개 학습문서(CLF 19 · SAA 24 · SOA 20)는 일관된 7섹션 골격(체크리스트→왜→핵심 개념→시험 포인트→함정→자가 점검→출처)을 갖췄지만, **표 중심 요약**이라:

- "무엇인지(정의+표)"는 있으나 **"왜/어떻게(원리·메커니즘)"가 얇다** — "이해 중심" 브랜드와 간극.
- 본문이 **전제하는 기초 용어**(온프레미스, 프로비저닝, 엔드포인트 등)를 풀지 않아 입문자가 막힌다.
- 개념 전개가 단계적이지 않다 — 정의에서 바로 시험 키워드로 점프.

## 2. 목표 / 성공 기준

- 모든 문서가 **단계화된 개념 전개**(무엇 → 왜·원리 → 시험 적용)를 갖는다.
- 모든 문서가 도입부에 **그 문서를 읽기 위한 기초 용어**를 자기완결로 푼다.
- 검수 가능: 기존 검수 루프(AI 초안+공식 대조 → 본인 검수 → lastVerified) 그대로, diff는 추가 중심.
- 앱/렌더러 **코드 변경 0** — 순수 콘텐츠 작업.

## 3. 접근 (승인됨: A안 — 기존 골격 유지 + 내부 보강)

기존 7섹션 골격은 이미 학습 단계적(목표→동기→개념→적용→함정→점검)이므로 유지. 문제는 골격이 아니라 **📖 핵심 개념 내부의 깊이와 도입부 용어**다. 전면 재설계(B안)는 63개 전부 풀검수라 기각, 부가 레이어(C안)는 본문 파편화라 기각.

## 4. 템플릿 변경

### 4.1 신규 섹션 「🔤 먼저 알아야 할 용어」

- **위치:** `🎯 왜 중요한가` 다음, `📖 핵심 개념` 앞.
- **형식:** 표 `| 용어(한글) | 영문/약어 | 한 줄 풀이 |`. 추상 용어는 풀이에 비유 1개 허용.
- **선정 기준:** 그 문서 본문이 **전제하는** 기초 용어만, 문서당 5~10개. 그 문서가 **가르치는** 개념은 제외(핵심 개념의 몫).
- 예 (clf/t1-1): 온프레미스, 프로비저닝, 온디맨드, 종량 과금, 자본 지출(CapEx)/운영 지출(OpEx).

### 4.2 「📖 핵심 개념」 서브섹션의 3단 구조

각 `### N)` 서브섹션을 다음 단계로 재구성:

| 단계 | 내용 | 형식 |
|---|---|---|
| ① 무엇 | 정의·구성 (기존 내용 유지·보강) | 기존 표 유지 |
| ② 왜·원리 | 왜 이렇게 설계됐나 / 내부적으로 어떻게 동작하나 | **산문 3~8줄**, `> 🧠 원리:` 인용 블록 마커. 표 금지(원리는 서사) |
| ③ 시험 적용 | 시나리오 키워드 → 정답 매핑 | 기존 "시험 키워드" 강화 |

② 예시 소재: IAM 평가에서 명시 Deny가 우선인 이유, S3 11-9s 내구성의 원리(다중 AZ 복제), 탄력성이 규모의 경제와 결합하는 구조.

### 4.3 부수 보강

- `🧪 자가 점검`: **원리형 문항("왜 ~인가") 1~2개** 추가.
- `⚠️ 흔한 함정`: 각 항목이 **왜 함정인지를 ②의 원리와 연결**해 설명.
- 분량 가이드: 문서당 **+60~100줄** (CLF 평균 177 → ~250줄, SAA 수준).

## 5. 진행 절차

1. **파일럿 2개:** `clf/t1-1`(기초 개념형) + `clf/t3-1`(서비스 각론형) — 유형이 다른 둘로 템플릿 검증 → **본인 검수·템플릿 확정 게이트** (여기서 멈추고 피드백 반영).
2. **롤아웃:** CLF 나머지 17 → SAA 24 → SOA 20. **cert 단위 배치 커밋·검수.**
3. **검수 루프(기존 그대로, [[content-density-loop]] 동일):** AI 초안(공식 문서 대조 포함) → 본인 검수 → `lastVerified` 갱신. ②원리에서 추가된 사실 진술은 대조 출처를 `📌 출처`에 추가.

## 6. 문서당 완료 기준 (DoD)

- [ ] 🔤 용어 섹션 존재 (5~10개, 전제 용어만)
- [ ] 모든 개념 서브섹션에 `> 🧠 원리:` 블록 존재
- [ ] 자가 점검에 원리형 문항 ≥1 추가
- [ ] 추가 사실 진술의 출처 대조 + `lastVerified` 갱신(본인 검수 후)

## 7. 비범위

- **모의고사 문항 중량·증가** — 고도화 완료 후 별도 검토(후속 브레인스토밍).
- 섹션 앵커 딥링크(C-중량), 로드맵 카드 스텝 세분화.
- **앱/렌더러 코드 변경 없음** — `<details>`·표·인용 블록만 사용(현 렌더러 검증 범위 내).
- 신규 cert(AIF 등) 문서 작성.

## 8. 리스크 / 주의

- **검수 병목이 실제 제약** — cert 단위 배치로 완화, 파일럿 게이트로 템플릿 재작업 위험 제거.
- 철칙 유지: `verified=사람 검수만`(AI가 lastVerified를 본인 검수 없이 갱신 금지).
- 원리 서술은 시험 범위를 넘는 학술적 깊이로 가지 않는다 — "시험 시나리오를 이해로 풀 수 있는 수준"이 상한.
- 자산 크기 증가는 미미(마크다운 +60~100줄 × 63).
