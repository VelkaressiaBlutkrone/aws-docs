## 2. fatal/optional 분류표 — 비동기 페이지 7종 전수

분류 규칙(설계 §WS4): 페이지의 **주된 콘텐츠** Future 실패 = **fatal** → ErrorView+재시도.
**부가 메타** 실패 = **optional** → 기존 의도적 부분 degrade 유지(주석 보존).

| 페이지 | 메인 Future (fatal) | optional degrade (보존, 주석 위치) |
|---|---|---|
| StudyDoc | 학습문서 마크다운 로드·파싱 | 없음 |
| Quiz | 문항 뱅크 로드·차출 | 없음 |
| Exam | 문항 뱅크 로드·세션 복원 | 시험 가이드 메타(`exam_guides/*.json`) 실패 → 폴백 페이스 (exam_page `catch` 주석) |
| CertExam | 전체 풀 병합·샘플링 준비 | 개별 뱅크 로드 실패 무시(cert_exam_page "개별 뱅크 로드 실패는 무시") · 가이드 실패 → 균등 가중 폴백 |
| CertDetail | `_load()` 종합(진행률·약점 인덱스 계산) — **이번 PR에서 fatal 승격** (유일한 침묵 결함이었음, 승인된 의도적 변경 ③) | guide 로드 실패(`:39` catch) · summary 로드 실패(`:45` catch) · 개별 뱅크 실패(`:60` catch) — 전부 보존 |
| Review | 약점 인덱스 빌드 | 개별 뱅크 로드 실패 무시(review_page "개별 뱅크 로드 실패는 무시(나머지로 진행)") |
| Report | Task 점수 리포트 빌드 | 개별 뱅크 로드 실패 무시(report_page `catch (_) {}`) |

**CertExam 분기 분리(신규):** 기존엔 `hasError || data == null || total == 0`이 한 분기로
"검증된 문항이 아직 없습니다."를 표시 — 로드 실패가 빈 풀로 위장됐다. PR2에서
에러(ErrorView)와 빈 풀(EmptyView)을 분리했다(정직함의 시각화).

## 3. 빈 상태 매핑 — 카피 + CTA 목적지 (디자인 리뷰 2A)

EmptyView는 아이콘 없음(텍스트+CTA만). CTA는 와이어프레임 보드 3번 섹션의
승인 패턴(빈 이유 설명 + 다음 행동)을 따르되, 방어적 빈 상태에는 달지 않는다.

| 페이지 | 빈 조건 | CTA | 목적지 | 비고 |
|---|---|---|---|---|
| Quiz | 뱅크 비어 있음 | 없음 | — | 방어적 상태 — 노출 가드(questionCount>0에서만 버튼 노출)로 정상 진입 시 도달 불가, AppBar 뒤로가기로 복귀 |
| Exam | 뱅크 비어 있음 | 없음 | — | 동일(방어적) |
| CertExam | verified 풀 0 | 없음 | — | 노출 가드(certHasVerifiedQuestions)로 정상 진입 시 도달 불가 |
| Review | weak 문항 0 | 모의고사 시작하기 | `/cert/:code/exam` | 실사용 빈 상태(첫 방문) — 오답이 쌓이는 경로로 안내 |
| Report | 응시 기록 0 | 모의고사 시작하기 | `/cert/:code/exam` | 실사용 빈 상태(첫 방문) |
| StudyDoc / CertDetail | — | — | — | 빈 상태 없음 |
