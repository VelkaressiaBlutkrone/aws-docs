# CLF-C02 t1-1 TTS MP3 보정 문서

작성일: 2026-06-21  
대상 문서: `flutter_app/assets/content/clf/t1-1.md`  
대상 오디오: `flutter_app/assets/audio/clf/clf-t1-1/lecture.mp3`  
외부 프리뷰: 사용자 제공 S3 presigned URL(만료형 URL이므로 전문은 문서에 남기지 않음)  
상태: **검수 전 M1 픽스처. 공개 학습 오디오로 노출 금지.**

## 결론

현재 MP3는 "재생 엔진 검증용 실물 픽스처"로는 쓸 수 있지만, 학습자가 듣는 검수 완료 강의로는 아직 부족하다. 가장 큰 문제는 음성 엔진 자체보다 **마크다운 원문을 음성 대본으로 바꾸는 정제 단계**다. 표·기호·접힌 정답·출처 URL이 음성 문맥에 맞게 재작성되지 않아, 학습 흐름이 끊기거나 잘못 읽힐 가능성이 높다.

다음 생성부터는 원문을 그대로 읽히지 말고, 문서별 `script.json`을 사람 검수 가능한 음성 대본으로 만든 뒤 TTS에 넘겨야 한다.

## 확인한 근거

- 생성 스크립트 dry-run 기준: 원문 5,019자 → Polly 청크 3개.
- MP3 파일: 4,133,652 bytes, SHA-256 `97ecddaee1fa037de38e219cc70641d32a00d9077ebb8f2da2fa19e1521ac370`.
- MP3 구조: MPEG2 Layer III, 24 kHz, 48 kbps, 약 11분 28초.
- 파일 내부 `ID3` 헤더 3개: offset 0, 2,041,244, 4,036,984. 즉 청크별 MP3를 바이트 연결한 상태다.
- 세그먼트 추정 길이: 5분 40초, 5분 32초, 16초.

## P0: 공개 전 반드시 고칠 항목

### 1. 청크 MP3 단순 연결 금지

현재 파일에는 `ID3` 헤더가 3개 있다. `gen_lecture_audio.py` 주석은 "Polly mp3는 ID3 없는 프레임열이라 단순 연결"을 전제하지만, 실제 산출물은 이 전제와 다르다.

문제:
- 브라우저·플랫폼별 duration 계산이 어긋날 수 있다.
- 청크 경계에서 미세 끊김이나 메타 재해석이 발생할 수 있다.
- M1의 iOS 잠금화면 검증에서 오디오 품질 문제가 재생 엔진 문제처럼 보일 수 있다.

보정:
- Polly를 MP3가 아니라 PCM으로 받고, 최종 단계에서 1회 인코딩한다.
- 또는 각 MP3를 디코드해 WAV/PCM으로 합친 뒤 MP3 1개로 다시 인코딩한다.
- 최종 MP3 검증 게이트: `ID3`는 파일 앞 1개만 허용, 중간 `ID3` 금지.

### 2. 화살표·수식 기호를 음성 문장으로 바꾸기

현재 대본에는 `→`, `=`, `+`, `≠`, `↓`, `vs`, `§`가 남는다. 특히 `❌`, `⚠️` 같은 이모지는 제거되지만 화살표는 남아, dry-run에서 아래처럼 어색한 문장이 생긴다.

예:
- `"탄력성과 고가용성은 같은 말이다." → .`
- `고정비(자본 지출) → 변동비(운영 지출)`
- `클라우드 = 온디맨드 + 종량 과금.`
- `탄력성 = 수요에 맞춘 용량 조절(≠ 고가용성).`
- `규모의 경제 → 많은 고객이 모여 단가↓`
- `(원리: §3 — 용량 축 vs 장애 축...)`

보정 예:
- `A → B`: `A에서 B로 바뀐다는 뜻입니다.`
- `"문장" → 탄력성`: `이 시나리오의 답은 탄력성입니다.`
- `A = B`: `A는 B입니다.`
- `A + B`: `A와 B`
- `≠`: `같지 않습니다.`
- `단가↓`: `단가가 내려갑니다.`
- `vs`: `와 ...의 차이`
- `§3`: `앞의 세 번째 개념 설명`

### 3. 출처 URL을 읽히지 않기

dry-run 마지막 청크는 거의 출처 URL만 읽는다. 또한 강조 제거 정규식이 `_`를 제거해 `ko_kr`이 `kokr`로 변형된다.

문제:
- 긴 URL 낭독은 학습 가치가 낮고 청취 피로가 크다.
- URL이 정제 중 변형되면 사실성/신뢰성에 악영향이 있다.

보정:
- `### 출처` 이후는 기본적으로 음성에서 제외한다.
- 필요한 경우 한 문장으로 대체한다: `출처는 화면 하단의 공식 링크를 확인하십시오.`
- URL 문자열은 TTS 대본에 직접 넣지 않는다.

### 4. 표를 통째로 제외하면서 핵심 정보가 빠짐

스크립트는 표 행을 제외한다. 이 문서에서는 용어 표와 핵심 이점 표가 빠져, 음성에서는 "먼저 알아야 할 용어" 뒤에 용어 설명이 없고, "클라우드의 핵심 이점" 표의 4개 이점 정리가 누락된다.

보정:
- 표를 그대로 읽지 말고 음성용 요약으로 변환한다.
- 용어 표: `온프레미스는 회사가 서버를 직접 사서 운영하는 방식입니다...`
- 이점 표: `민첩성은 빠른 출시, 탄력성은 수요에 맞춘 확장과 축소, 비용 절감은 고정비를 변동비로 바꾸는 것, 글로벌 배포는 사용자 가까운 리전에 빠르게 배포하는 것입니다.`

### 5. `정답 보기`와 자가 점검을 강의 흐름에 맞게 재작성

`<details><summary>정답 보기</summary>`가 태그 제거 후 `정답 보기`로 남는다. 화면에서는 자연스럽지만 음성에서는 반복 노이즈가 된다.

보정:
- 자가 점검을 유지한다면 음성 전용 포맷으로 바꾼다.
- 예: `첫 번째 질문입니다. 잠시 멈추고 답해 보십시오. 정답은...`
- 검수 전 M1 픽스처라면 자가 점검 전체를 제외해도 된다.

## P1: 품질을 높이는 보정 항목

### 6. 메타데이터/헤더를 낭독용으로 압축

현재 시작부는 `커버하는 공식 Task — CLF-C02 · 도메인 1 ... Task 1.1 ... 1:1`처럼 문서 메타가 그대로 이어진다. 첫 20초가 학습 강의라기보다 파일 헤더처럼 들릴 가능성이 높다.

보정 예:
- `이번 강의는 CLF-C02 도메인 1의 Task 1.1, AWS 클라우드의 이점입니다. 핵심 질문은 "왜 클라우드인가"입니다.`

### 7. 약어와 영문 병기를 발음 사전에 넣기

대상 후보:
- `AWS`: `에이더블유에스`
- `CLF-C02`: `씨엘에프 씨 공이`
- `AZ`: 첫 등장 `가용 영역`, 이후 `에이제트`
- `IT`: `아이티`
- `CapEx`: `자본 지출`
- `OpEx`: `운영 지출`
- `on-demand`: `온디맨드`
- `pay-as-you-go`: `종량 과금`
- `resource pool`: `자원 풀`
- `axis`: `축`
- `single point of failure`: `단일 장애 지점`

### 8. 긴 괄호와 인용을 줄이기

문서 원문은 화면 독해에는 좋지만, 음성에서는 괄호가 너무 많다. `탄력성(용량 조절)`, `고가용성(장애 견딤)`, `pay-as-you-go` 같은 병기는 첫 등장 이후 한국어 설명만 남기는 편이 낫다.

보정:
- 첫 등장: 한국어 + 영문 병기.
- 이후: 한국어만 사용.
- 괄호가 2개 이상 겹치는 문장은 두 문장으로 나눈다.

### 9. 청크 경계에 의도된 호흡을 넣기

현재 Polly 청크 1과 2는 각각 2,400자대라 경계가 문단 흐름 중간에 생긴다. 최종 오디오가 1개 파일이어도 대본상 호흡 설계가 없다.

보정:
- 섹션 단위로 스크립트를 나눈 뒤, 섹션 사이에 400~700ms 휴지를 넣는다.
- `핵심 개념`, `시험 포인트`, `흔한 함정`, `자가 점검` 앞에는 짧은 전환 문장을 둔다.

### 10. 음질 기준을 명시

현재 48 kbps/24 kHz는 음성용으로 작고 빠르지만, 장시간 학습 오디오로는 답답하게 들릴 수 있다.

권장 게이트:
- 원천 합성은 PCM 또는 무손실 중간 산출물.
- 최종 MP3는 64~96 kbps 이상을 비교 청취 후 선택.
- loudness normalization 적용. 목표 예: 대화형 음성 기준 integrated loudness 약 -16 LUFS, true peak -1 dBTP 이하.
- 각 파일에 duration, bitrate, sample rate, SHA-256, 생성 엔진, voice, sourceHash를 기록한다.

## 대본 정제 규칙 초안

자동 변환은 아래 정적 검사를 통과해야 한다.

- 원시 URL이 없어야 한다.
- `→`, `≠`, `↓`, `§`, `|`, raw markdown link, `.questions.json`이 없어야 한다.
- `정답 보기`는 self-check 전용 문장으로 바뀌어야 한다.
- `❌`/`⚠️` 제거 뒤 `→ .` 같은 고아 문장부호가 없어야 한다.
- 표가 있는 섹션은 `skip` 또는 `audioSummary` 중 하나를 명시해야 한다.
- 출처 섹션은 기본 `skip`이어야 한다.
- 약어 사전을 적용한 뒤 남은 영문 대문자 토큰을 검수 큐에 올린다.

## 권장 산출물

오디오 옆에 아래 파일을 함께 둔다.

- `flutter_app/assets/audio/clf/clf-t1-1/script.json`
- `flutter_app/assets/audio/clf/clf-t1-1/audio_meta.json`

`script.json` 최소 필드:

```json
{
  "schemaVersion": 1,
  "docId": "clf-t1-1",
  "sourceHash": "<md sha256>",
  "generatedAt": "2026-06-21T00:00:00+09:00",
  "reviewStatus": "needs_human_review",
  "segments": [
    {
      "id": "intro",
      "source": "frontmatter+title",
      "scriptText": "이번 강의는 CLF-C02 도메인 1의 Task 1.1, AWS 클라우드의 이점입니다.",
      "skip": false
    }
  ]
}
```

`audio_meta.json` 최소 필드:

```json
{
  "docId": "clf-t1-1",
  "audio": "lecture.mp3",
  "durationSec": 688.92,
  "sampleRateHz": 24000,
  "bitrateKbps": 48,
  "sha256": "97ecddaee1fa037de38e219cc70641d32a00d9077ebb8f2da2fa19e1521ac370",
  "containerChecks": {
    "id3Count": 3,
    "midFileId3Allowed": false
  },
  "reviewStatus": "needs_human_review"
}
```

현재 파일 기준으로는 `id3Count: 3`이라 `containerChecks`가 실패해야 정상이다.

## 재생 게이트와 검수 게이트 분리

이 MP3는 M1 재생 게이트에는 사용할 수 있다. 다만 결과 해석 시 아래를 분리한다.

- 재생 엔진 게이트: iOS standalone 잠금 연속재생, 일시정지/재개, 인터럽션 후 재개.
- 호스팅 게이트: S3/GitHub Pages `Accept-Ranges`, `Content-Type`, 캐시, Range 요청.
- 콘텐츠 게이트: 이 문서의 정제 이슈 해결, 사람 청취 검수, `reviewStatus=approved`.

재생 엔진이 통과해도 콘텐츠 게이트가 통과하기 전에는 `audio_lecture=true` 공개 진입점을 열지 않는다.
