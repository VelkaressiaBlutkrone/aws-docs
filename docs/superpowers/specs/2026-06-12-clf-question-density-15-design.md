# CLF 문항 밀도 ≥15 심화 — 설계 스펙

작성일: 2026-06-12
상태: **완료 — D1~D4 develop 반영(2026-06-15), 19 Task 전부 15 verified(총 285·+57), 밀도 가드 ≥15 상향.** 구현 플랜: `docs/superpowers/plans/2026-06-15-clf-question-density-15.md`. 검수 게이트별 종합 판정 반영(t1-1 q13 보수성·q15 냉각/중복, t2-4 q14 정답 단일성, t3-4 q14 ElastiCache 단정, t4-1 q13 데이터 전송·q15 RI 교환·t4-2 q15 태그 활성화·t4-3 q13 Support 플랜명 완충).
근거 결정 체인: 문항 증량은 학습문서 고도화 완료 후로 연기(사용자, 2026-06-11) → 고도화 롤아웃 63/63 출고로 조건 충족(2026-06-12) → 백로그 ① "CLF Task당 ≥15 심화" 착수 지시(사용자, 2026-06-12).

## 1. 문제

- CLF-C02 19개 Task가 각 12 verified 문항(총 228)으로 진단 밀도 1차 목표(≥12)는 달성했지만, **난이도 분포가 foundational 222 / applied 6**으로 기초형에 쏠려 있다.
- 학습문서가 막 고도화되어(용어 표 + 🧠 원리 블록 + 함정 원리 포인터 + 원리형 Q) **원리·함정이라는 새 출제 자산**이 생겼는데, 기존 문항 풀은 이를 전혀 활용하지 못한다.
- Task당 12문항의 약점 진단을 15문항으로 끌어올리면 통계 노이즈가 더 줄고, 처방 루프(진단→문서 처방)의 정밀도가 높아진다.

## 2. 목표 / 성공 기준

- 19개 Task 전부 **15 verified** (+57문항 = 원리형 19 + 함정 혼동형 19 + 미커버 보완 19).
- 신규 문항으로 applied 비중 회복(원리형·함정형은 applied 라벨).
- **학습문서 보강 0건 보장**: 모든 신규 문항은 해당 고도화 문서(본문·원리 블록·함정)와 frontmatter 출처 범위 안에서만 출제 — 처방 링크 정합이 구조적으로 닫힘(전례 교훈: 문항이 새 개념을 도입하면 문서 9개를 사후 보강해야 했음).
- 철칙 유지: **verified=사람 검수만**. AI 초안은 verified:false로만 삽입(QuestionBank가 verified만 노출하므로 라이브에 뜨지 않음 — 안전).

## 3. 접근 (승인됨: A안 — 고도화 루프 이식)

배치 B·C에서 검증된 "AI 초안 → 독립 AI 리뷰(수정 권한) → 컨트롤러 실측 → 사람 검수 게이트" 구조를 문항 생산에 이식한다.

- 기각 B안(도메인 일괄 초안, AI 리뷰 생략): 초안 결함(재포장·범위 이탈·중복)이 사람 검수자에게 전가됨 — 고도화 전례에서 AI 리뷰가 매 문서 실질 결함을 잡았음.
- 기각 C안(컨트롤러 단독 작성): 작성자=검증자 분리가 사라져 자기 결함을 못 잡는 구조.

## 4. 문항 설계 규칙

### 4.1 Task당 +3 구성 (혼합형 — 승인됨)

| 유형 | difficulty | 소재 | 핵심 제약 |
|---|---|---|---|
| **원리형** | applied | 해당 문서 `> 🧠 원리:` 블록의 원리를 **새 시나리오에 적용**해 판단을 묻기 | 문서 자가 점검 문항 **전체**와 **소재·각도 중복 금지**(학습자가 양쪽을 다 봄). 블록 문장 재진술 금지 |
| **함정 혼동형** | applied | 문서 `⚠️ 흔한 함정` 항목의 "잘못된 통념"을 **매력적 오답**으로 배치한 시나리오형 | 함정 항목의 교정 논리가 정답 해설의 근거가 되어야 함 |
| **미커버 보완** | foundational~applied | 공식 시험 가이드 해당 Task의 skill 중 기존 12문항이 다루지 않은 소재 | **문서 범위에 없으면 같은 문서의 저커버 소재로 대체**(새 개념 도입 금지 — 승인됨. 대체 시 드래프터 보고에 사유 기록) |

### 4.2 공통 규칙

- 스키마 동일: `id`(규칙: 해당 파일의 **기존 최대 연번 다음**부터 — 통상 `clf-tX-Y-q13`~`q15`; 드래프터가 실측 확인) / `examGuideTaskId` / `skill` / `difficulty` / `stem` / `options[4]` / `correct` / `explanation` / `wrongExplanations`(정답 인덱스 제외 3키 — "왜 틀렸는지 + 어떤 혼동을 노렸는지") / `sources`(해당 문서 frontmatter 출처 범위 내) / `verified:false`.
- **기존 12문항과 정답 포인트·stem 소재 중복 금지** (리뷰어가 전수 대조).
- 보기 4개는 길이·톤 균형(정답이 표시 나지 않게).
- 사실 진술은 해당 학습문서 본문·원리 블록·함정·frontmatter 출처 범위 내 — 고도화 절제 규칙 이식(무출처 수치·내부 구현 단정·설계 의도 단정 금지).

## 5. 생산 파이프라인 (Task 단위 직렬 루프)

1. **드래프터(sonnet)**: 해당 고도화 문서 전체 + 기존 `*.questions.json`을 읽고 3문항 초안을 `questions` 배열 끝에 삽입(verified:false) → 스키마 자가 검증 + `flutter test`(기존 가드 그린 유지) → 커밋 `feat(content): clf-tX-Y 문항 +3 초안 — 원리·함정·보완 (verified:false, 검수 전)`.
2. **통합 AI 리뷰어(sonnet, 수정 권한)**: ①사실 정확성(문서·출처 대조) ②범위 이탈(문서에 없는 개념) ③중복(기존 12문항 + 문서 자가점검 Q 전수 대조) ④오답 매력도·해설 품질 ⑤스키마·id 규칙 — 위반 직접 수정 후 커밋 `fix(content): clf-tX-Y 문항 리뷰 반영 — <요지>`. 경계 사례는 게이트 플래그로 보고.
3. **컨트롤러**: JSON 파스·문항 수·verified:false 카운트 실측(스크립트) + `flutter test` + fix 디프 스팟 체크.

전 과정 테스트 그린 유지(초안은 verified:false라 노출·카운트 불변 — RED 단계 불필요).

## 6. 검수 게이트·반영 (도메인 4배치, 점진 배포 — 승인됨)

| 배치 | Task | 문항 수 |
|---|---|---|
| D1 | t1-1 ~ t1-4 | 12 |
| D2 | t2-1 ~ t2-4 | 12 |

도메인별 브랜치 `feat/clf-q15-d{1..4}`:
1. 도메인 내 Task 수만큼 §5 루프 완료 → 리뷰 파일 추출: `D:\workspace\clf-d{N}-q15-drafts_for_review.json` (전례 형식 + **문항별 근거 문서 위치(§ 표기) 병기**로 검수 시간 단축).
2. **STOP — 본인 검수** (피드백 전 진행 금지).
3. 피드백 반영 → 해당 문항 `verified:true` + 해당 Task들 `content_index.dart` questionCount 12→15 → 전체 테스트(content_index_test 정합 포함) → 커밋 `chore(content): D{N} 문항 검수 반영 — Task당 15 verified`.
4. main 병합(`--no-ff`) → 머지본 전체 테스트 → push(=배포) → 브랜치 삭제 → 다음 도메인.

## 7. 테스트·가드

- 작업 중: 기존 회귀 가드(`question_model_test`의 Task당 verified ≥12) 그린 유지.
- 검수 반영 시: content_index_test가 questionCount(12→15) 정합 검증.
- **D4 게이트 완료 후**: 회귀 가드를 `greaterThanOrEqualTo(12)` → `(15)`로 상향(밀도 목표 코드화 — ≥12 전례 동일). D4 반영 커밋에 포함.

## 8. 비범위

- SAA-C03 문항 착수(백로그 ②), C-중량 딥링크(③) — 별도 검토.
- 모의고사 모드·앱·렌더러 코드 변경(테스트 가드·questionCount 갱신 제외).

## 9. 리스크 / 주의

- **검수 병목**: 도메인 4배치 분할 + AI 리뷰 선행 + 근거 § 병기로 완화. D3(24문항)가 최대 회당 부담.
- **중복 위험**: Task당 기존 12 + 자가점검 ~5 = 17개 기출 소재와의 충돌 — 리뷰어 전수 대조 필수 항목.
- **CLF 시험 현실성**: 원리형·함정형도 CLF 수준(기초 개념의 적용)을 넘지 않게 — "시험 시나리오를 이해로 풀 수 있는 수준" 상한(고도화 스펙과 동일).
