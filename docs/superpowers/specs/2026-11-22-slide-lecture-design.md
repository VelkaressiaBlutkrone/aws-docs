# 인강형 슬라이드 학습 화면 설계 (2026-11-22)

> **상태: 사용자 승인(2026-11-23).** 긴 발화 단위는 나누지 않고 슬라이드 안에서 스크롤한다. 구현은 착수 전이고 첫 단계는 P0 검증이다.
>
> 로드맵 D3(`docs/plans/2026-11-18-productization-roadmap.md` §5-④)의 설계 문서다. 연내 범위는 이 문서의 승인까지이고, 구현은 일정이 남을 때 단계별로 한다.

## 1. 의도

앱의 학습 방식은 두 가지가 된다.

| 방식 | 상황 | 주도하는 것 |
|---|---|---|
| 음성 강의(기존) | 화면을 보지 않고 이어폰으로 듣는 자기학습 | 학습자의 귀 |
| **슬라이드 강의(신규)** | 앉아서 화면을 보며 강사에게 배우는 정규 학습 | **음성이 화면을 이끈다** |

사용자가 원하는 것은 문서를 나눠 보는 뷰어가 아니라 **인강을 듣는 느낌**이다.

- **목표:** 강사의 음성이 해당 내용에 닿을 때 슬라이드가 넘어간다. 학습자는 언제든 멈추고, 앞뒤로 이동하고, 다시 음성을 따라갈 수 있다.
- **비목표:** 재생 속도 조절(현재 재생기에 없다), 슬라이드 위치 이어 보기와 기기 간 동기, 이미지·다이어그램 신규 제작, 슬라이드용 요약문 작성, 새 음성 합성.
- **실패로 볼 것:** 음성과 **다른 내용의 슬라이드**가 보이는 것. 현재 학습문서에 없는 문장이 슬라이드에 나오는 것. 미승인 음성이 슬라이드를 통해 노출되는 것.

## 2. 확인한 사실 (2026-11-22)

| 사실 | 값 | 설계에 주는 뜻 |
|---|---|---|
| 학습문서 절 | 2,424개 · 중앙값 804자 · 1,000자 초과 928개 · 3,000자 초과 124개 | 제목 하나를 한 장에 담을 수 없다 |
| 표·접이식·코드 | 표 1,280 · 접이식 928 · 코드 106 · 이미지 0 | 표가 시각 자료의 중심이다 |

| 긴 발화 단위 | 표 374개 중 81개가 6행 초과 · 표·코드 외 227개가 원문 320자 초과(건너뛰는 세그먼트 포함 집계) | 발화 단위를 쪼개면 넘길 시각이 없다 |
| 문장 경계 | 인접 발화 3,343쌍 중 601쌍은 앞 세그먼트가 문장 부호 없이 끝난다 | `sentence` 표시만으로는 시작을 놓칠 수 있다 |

| Polly 음성 표시 | neural 지원 · 오디오 없이 JSON 반환 · `time` 은 ms · `start`/`end` 는 **바이트** 오프셋 | 시각은 mp3 를 바꾸지 않고 받는다 |
| 비용 | 43편 발화 764,329자 × neural $16/100만 자 ≈ **$12.2** | 무료 구간 제외, 1회 요청 기준 |
| 재생기 | `LecturePlaylist` 는 전역 하나 · `openDoc` 은 idle 일 때만 트랙 변경 · 기본 `autoAll` · 속도 조절 없음 | 진입과 종료 규칙이 필요하다 |

공식 근거: [Speech marks](https://docs.aws.amazon.com/polly/latest/dg/speechmarks.html) · [Speech mark output](https://docs.aws.amazon.com/polly/latest/dg/output.html) · [Polly 요금](https://aws.amazon.com/polly/pricing/)

## 3. 접근 (사용자 선택: 문장 시각 동기)

| 접근 | 장단점 | 판정 |
|---|---|---|
| **문장 시각 동기** | 인강에 가장 가깝다. 시각 생성 도구와 정확도 검증이 필요하다 | **채택** |
| 제목 단위 동기 | 새 데이터가 없다. 긴 절에서 화면이 멈춘다 | 실패 시 후퇴 경로 |
| 글자 수 비율 추정 | 쉽지만 강의체 대본 때문에 다른 슬라이드가 보일 수 있다 | 기각 |

## 4. 구조

```text
현재 학습문서 .md ──▶ parseStudyDoc ──▶ buildLectureDeck ──▶ 슬라이드
                                              ▲
script.json + Polly speech marks ──▶ slide_timeline.json (큐)
                                              │
LecturePlaylist.position ─────────────▶ 현재 슬라이드 계산
```

- **화면 내용의 정본은 현재 학습문서 하나다.** 대본 문장은 화면에 쓰지 않는다.
- 큐는 「이 시각에 이 문서 블록을 말하기 시작한다」만 담는다.

### 4-1. 슬라이드 나누기: `buildLectureDeck(blocks, cues)`

UI 없는 순수 함수이고 `cues` 는 없을 수 있다.

1. 모든 H2 와 앵커가 있는 H3 은 새 슬라이드를 시작한다. 앵커 없는 H3 은 현재 슬라이드에 이어진다.
2. **발화 단위는 쪼개지 않는다.** 한 큐가 덮는 블록은 같은 슬라이드에 둔다. 큐가 없으면 `MdBlock` 하나가 최소 단위다.
3. 인접 단위를 **본문 320자 이내**로 묶는다. 한 단위가 320자를 넘으면 혼자 한 장을 쓰고 **슬라이드 안에서 스크롤**한다.
4. 표와 코드는 단독 슬라이드이고 행으로 나누지 않는다. 넘치면 슬라이드 안에서 스크롤한다.
5. 이어지는 슬라이드에는 제목을 작게 `(계속)`과 함께 다시 보여 준다.
6. 「자가 점검」은 강의 끝의 **확인 문제 슬라이드**로 접이식 정답을 유지한다. 음성이 없는 구간이다.
7. 「출처」와 검증일은 마지막 슬라이드에 둔다.

문장을 고치거나 줄이지 않는다. 한 덱은 화면 크기와 무관하게 같아서 슬라이드 번호와 큐가 회전이나 창 크기에 따라 바뀌지 않는다.

### 4-2. 시각 데이터: `slide_timeline.json`

경로는 `assets/audio/<cert>/<docId>/slide_timeline.json`이고 Git 에 커밋한다.

```json
{
  "schemaVersion": 1,
  "docId": "saa-t3-7",
  "audioSha8": "893d30a8",
  "cues": [
    { "startMs": 0, "section": null, "match": "정규화한원문앞24자" },
    { "startMs": 179000, "section": "core-concepts", "match": "정규화한원문앞24자" }
  ]
}
```

- 큐는 **발화 세그먼트마다 하나**다. `section` 은 그 세그먼트가 속한 앵커이고 첫 앵커 이전은 `null` 이다.
- `match` 는 `sourceExcerpt` 에서 공백·목록·인용 기호와 인라인 표기(`**`·백틱)를 뺀 앞 24자다. 표는 **헤더 셀을 이은 문자열**이 키다.
- Dart 는 같은 규칙으로 블록을 찾고, 같은 키가 여럿이면 **문서 순서상 다음 일치**를 쓴다.
- 전환 문구는 큐를 만들지 않고 앞 슬라이드에 머문다.
- 표·코드는 `audioSummary` 발화의 시작이 그 블록의 큐다.

**도구:** `tool/gen_slide_timeline.py <docId>`

1. 기존 `split_sections`·`chunk_text` 로 합성 때와 **같은 입력 조각**을 만든다.
2. 조각마다 Polly 에 `OutputFormat=json`, `SpeechMarkTypes=["sentence","word"]`, 같은 음성·엔진으로 요청한다.
3. 바이트 오프셋을 UTF-8 기준으로 세그먼트에 대응시킨다. 시작은 **세그먼트 첫 낱말의 `word` 표시**다. 문장 부호가 없는 제목 뒤에서도 시작을 잡기 위해서다.
4. 구간 시작 시각은 `chapters.fraction × 실제 mp3 길이`로 정한다.
5. 한 구간이 여러 조각이면 조각별 표시를 그 구간의 실측 길이에 맞게 비례 보정한다.
6. 시작 낱말을 찾지 못한 세그먼트는 큐를 만들지 않아 앞 슬라이드에 머문다.

mp3·대본·`reviewStatus` 는 바꾸지 않는다.

### 4-3. 동기 규칙

| 상황 | 동작 |
|---|---|
| 재생 중, 따라가기 켜짐 | `position` 이 큐를 지나면 해당 슬라이드로 넘어간다 |
| 큐 있는 슬라이드로 이동 | 슬라이드를 옮기고 **음성도 그 시작으로 이동**한다 |
| 재생 중 큐 없는 슬라이드(확인 문제·출처)로 이동 | **따라가기를 끄고** 음성은 계속되며 「강의 위치로」 버튼을 보여 준다 |
| 「강의 위치로」 | 현재 재생 위치의 슬라이드로 돌아가 따라가기를 켠다 |
| 일시정지 중 이동 | 슬라이드와 재생 위치만 옮기고 재생하지 않는다 |
| 진행 막대 이동 | 그 시각의 슬라이드로 바뀌고 따라가기를 켠다 |
| 진입 시 다른 강의가 재생·일시정지 중 | 그 음성을 끊지 않는다. 화면은 텍스트 상태이고 「이 강의로 전환」을 누르면 트랙을 바꾼다 |
| 강의가 끝남 | 슬라이드 화면에서는 다음 강의로 넘어가지 않고 확인 문제로 이동한다. 전역 재생 모드는 바꾸지 않는다 |

**후퇴 규칙.** 문서별로 다음 순서로 판정하며 사용자에게 오류를 보이지 않는다.

1. 강의가 미승인이면 **텍스트 슬라이드**다.
2. 타임라인이 없거나 `audioSha8` 이 현재 승인 음성과 다르면 **제목 단위 동기**다.
3. 큐의 `match` 를 찾지 못한 제목 구간은 **그 구간만 제목 단위 동기**다. 첫 앵커 이전 구간은 재생 시작부터 첫 챕터까지 첫 슬라이드에 머문다.

학습문서가 바뀌어 문장이 달라져도 3번이 잘못된 장면을 막는다.

- **진입:** 학습문서 상단의 「슬라이드 강의」 버튼. 라우트는 `/cert/:code/study/:taskId/lecture` 이고 `ValueKey(code/taskId/lecture)` 를 준다.
- **세로 우선**으로 설계하고, 넓은 화면은 같은 덱을 더 큰 글자로 보여 준다. 최대 폭은 `Layout.content` 다.
- **스크롤:** 긴 단위와 표는 슬라이드 안에서 스크롤한다. 음성에 맞춘 자동 스크롤은 하지 않는다.
- **목차:** 제목 목록에서 바로 이동한다.
- **끝:** 확인 문제 → 출처 → 기존 퀴즈 시작 버튼.
- **디자인:** `DESIGN.md` 를 따른다. 장식 애니메이션과 그라데이션을 쓰지 않고 전환은 짧은 페이드이며 `MediaQuery.disableAnimations` 를 존중한다.
- **접근성:** 터치 타깃 48dp · 키보드 이동 · 재생 중에는 슬라이드 변경을 스크린리더로 자동 낭독하지 않는다(강사 음성과 겹친다).

## 5. 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **P0 검증** | 대표 1편(`saa-t3-7`)의 시각 생성 | 아래 세 조건 전부 |
| **P1 덱** | `buildLectureDeck` + 텍스트 슬라이드 화면 | 등재 142편 전수 파싱, 본문 누락 0, 발화 단위 비분할 |
| **P2 시각** | 도구 + 승인된 편의 타임라인 | 큐 해석률과 시각 단조 증가 가드 |
| **P3 동기** | 재생기 연결 + 후퇴 규칙 | 표 4-3 전 상황 테스트 + 실제 재생 확인 |

**P0 합격 조건.** `fraction` 과 비교하면 자기 자신과 비교하는 셈이므로 최종 mp3 를 기준으로 삼는다.

1. 모든 제목 시작 시각이 최종 mp3 의 `ffmpeg silencedetect` 무음 끝에서 **1초 이내**다.
2. 발화 세그먼트의 **99% 이상**이 큐를 갖고 `startMs` 가 단조 증가한다.
3. 사람이 표본 10곳을 들어 슬라이드와 음성이 맞다고 확인한다.

**P0 이 실패하면** 시각 생성을 중단하고 제목 단위 동기로 출고한다. P1 은 P0 결과와 무관하게 쓸 수 있다.

**순서 제약.** P2·P3 의 대상은 현재 청취 승인 대기 중인 새 대본이다. 옛 대본에 시각을 만들면 승인 뒤 버려지므로 **승인·발행된 편부터** 만든다. P0 은 mp3 를 공개하지 않으므로 청취 전에 할 수 있다.

위젯 분할, 페이드 시간, 목차 시트의 형태, 큐 탐색 자료구조.
