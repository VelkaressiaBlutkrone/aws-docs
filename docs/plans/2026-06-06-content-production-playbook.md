## Problem

그릇은 다 만들었다. 라이브 사이트(Flutter Web) + 12개 자격증 공식 Exam Guide 구조(193 Task)가 배포돼 있다. 빠진 것은 단 하나 — **검증된 CLF 학습 콘텐츠**(학습문서 + verified 문항). 현재 CLF verified 문항 = 0.

진짜 병목은 코드가 아니라 **"사람만 할 수 있는 검수"**다. 그리고 그 검수자는 스스로 "경험이 적다"고 말한 본인이다.

## Diagnostic (이번 세션에서 확인)

1. **단위 시간:** ~15~20분/문항(추정, 저경험). CLF 완성까지 ~95~130 문항 → **~24~43시간 ≈ 2~4주**(하루 1~2시간). 감당 가능. 단, 이건 추정치이고 첫 배치를 측정해야 진짜 숫자가 나온다.
2. **엔진(가설 검증됨):** "이해하면서 만든다." 문항 제작 = CLF 공부. 따라서 24~43시간은 추가 노동이 아니라 어차피 할 공부 시간의 산출물화. → **지속 가능.**
3. **해자의 구멍:** 검수 의도는 출처 대조(b)인데 **출처 기록이 아직 없음.** 시간 압박 하에 (b)→(a)로 조용히 퇴화 위험.

## Premises (전부 합의)

- **P1.** 문항 제작 시간 = CLF 공부 시간. 별도 예산이 아니라 공부 세션을 "문항 산출 형태"로 바꾼다.
- **P2.** "정직/이해 중심" 해자는 verified 도장의 엄격함에서만 나온다. → **출처 URL을 verified의 필수 조건으로 강제.**
- **P3.** 목표는 CLF 1개를 ~95~130 검증 문항으로 끝까지. 12개 아님. (게이트 유지)
- **P4.** 초보 검수만으론 "틀린 이해 박제"를 못 잡는다. → 제작 루프 안에 값싼 2차 점검(AI 역대조) 추가.

## EUREKA — sources[]는 메타데이터가 아니라 검수 메커니즘이다

`sources[]`(D15)를 "나중에 보여줄 메타데이터"가 아니라 **검수 게이트 그 자체**로 재정의한다. verified를 찍으려면 출처 URL이 *반드시* 있어야 한다고 빌드에 강제하면, 기억으로 도장을 못 찍는다 — 링크를 붙여넣으려면 공식 문서를 열 수밖에 없다. **"출처 기록 = (b)가 (a)로 무너지는 걸 막는 강제 장치."**

## Recommended Approach — A+B 혼합 (문항)

**A(Task-by-Task 직렬)를 척추로, B(약점 우선)를 순서 우선순위로, C(AI 소크라테스 루프)는 어려운 Task 전용 옵션 도구.**

초보 + 정확성 해자이므로 틀릴 위험이 가장 큰 C를 척추로 쓰지 않는다. A가 커버리지를 보장하고 어제 만든 `examGuideTaskId` 구조와 1:1로 맞는다.

### 생산 루프 (Task 1개당)
1. 다음 Task 선택 — 학습하기 좋은 순서로, 단 **내가 약한 Task부터**(B 정신).
2. 그 Task를 공식 ko_kr Exam Guide(이미 사이트 `assets/exam_guides/CLF-C02.json`) + AWS 공식 문서로 공부.
3. 학습문서 1개 작성 (아래 템플릿, 공식 Task에 매핑).
4. 문항 ≥5개: **AI 초안 → 본인이 공식 문서 열어 정답+오답근거 대조 + 출처 URL 기록(verified 게이트) → AI 역대조(P4: "이 정답/오답해설이 공식 가이드와 어긋나는 데 있나?") → 수정 → `verified:true`.**
5. 본인이 직접 풀고, 헷갈린 지점을 `wrongExplanations`에 반영(B).

### verified 게이트 (타협 불가)
출처 URL 없음 → verified 불가 → 빌드 제외. 이게 해자의 작동 원리.

### 2차 점검 (P4)
모든 verified 문항을 AI에게 역대조시킨다: 정답·오답해설이 공식 가이드와 어긋나는 지점 탐지. 사람 검수 + AI 역대조 = 2중.

## 상세 학습 문서 결정 (D:\Download\files.zip 검토 결과)

files.zip = 본인이 이미 만든 고품질 **SAA-C03** 자료 한 벌(27 상세문서 + Mock ~110 + 종합 325 + HTML 앱). 결정은 층을 나눈다:

1. **문서 내부 템플릿 → 채택.** files.zip의 틀을 CLF 학습문서에 그대로 사용:
   `목표 체크리스트 → 🎯왜 중요한가 → 📖핵심개념(표/다이어그램) → ✍️시험 포인트 → ⚠️흔한 함정 → 🧪자가 점검(정답 토글)`.
   단, `🏢 실무·면접(DIO Implant)` 섹션은 개인 취업 맥락 → **공개 사이트엔 미게재**(개인 학습본에만).
2. **조직 축 → Phase/Step이 아니라 공식 Task에 앵커.** 사이트·문항·verified 게이트가 전부 `examGuideTaskId` 위에 있고, README가 "공식 시험 가이드 기준"을 내걸었다. 두 분류를 섞으면 "동선 부재"가 되살아난다.
   → Phase/Step은 버리지 말고 **"추천 학습 순서"(로드맵 오버레이)**로 강등. 규칙: **학습문서 1개 ↔ 공식 Task 1개(또는 명시적 N개) 매핑.** CLF 19 Task를 학습 순서로 묶어 ~8~12개 문서, 각 문서 머리에 커버하는 Task ID 명시.
3. **게이트 경고:** files.zip은 SAA. 지금은 CLF 우선. **템플릿만 지금 빌려오고 SAA 콘텐츠는 CLF 합격 후.** 그 325 SAA 문항은 출처 기록 없는 비검증 초안 → 그대로 verified 불가, SAA 단계에서 출처 앵커 재검증 필수. (사이트 verified 게이트가 이미 차단.)

## Coverage Target (CLF)

- 19 Task × ≥5 검증 문항 = **≥95 verified** (스트레치: 모의고사 2회차 ~130).
- Task별 진척 추적(이미 `clf-c02-task-mapping.md`에 0/5 표 존재).
- 성공 기준: 본인이 사이트만으로 모의고사 정답률 ≥70% 3회 연속 → 실제 CLF 응시·합격(최종 증명).

## The Assignment (이번 주)

**CLF의 단 하나의 Task를 골라 끝까지 한 사이클을 돌려라.**

- 추천 Task: **clf-t2-1 (공동 책임 모델)** — 비중 큰 도메인 2(30%)이고, files.zip Phase-01에서 이미 다뤄봐서 빠르게 첫 성공을 만든다.
- 산출: 학습문서 1개(files.zip 템플릿, Task 매핑 머리말 포함) + **검증 문항 5개**(출처 URL 기록 + AI 역대조 포함).
- **타이머로 실제 1문항 시간을 측정**하라. 감 말고 숫자.

이 1 Task가 (a) 진짜 분당 단가를 알려주고, (b) 나머지 18 Task의 복제 템플릿이 되며, (c) verified 게이트·출처 기록 규율이 실전에서 도는지 검증한다. 하나가 돌면 전부 돈다.

## What I noticed about how you think

- "이해하면서 만드냐"는 질문에 즉답으로 "이해하면서 만든다" — 가설을 행동으로 증명하는 사람. 말이 아니라 실제로 그렇게 하고 있다.
- P4(본인 게이트를 건드리는 2차 점검)를 즉시 수용했다. 자기가 만든 규칙보다 품질 기준이 앞선다.
- files.zip — 이미 SAA 한 벌을 끝까지 만들어 둔 사람이다. 계획만 하는 사람이 아니라 끝내는 사람.
- "출처 기록은 아직"을 숨기지 않고 인정했다. 정직이 제품 가치이자 본인 성향이다.
