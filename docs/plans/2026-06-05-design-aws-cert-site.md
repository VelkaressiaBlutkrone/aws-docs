## Problem Statement

AWS 자격증을 준비하는 한국어 사용자는 다음 네 가지 고통을 동시에 겪는다:
1. 좋은 자료는 대부분 영어다 (Maarek, Tutorials Dojo, 공식 문서)
2. 덤프(ExamTopics 등)는 정답만 있고 "왜"가 없다 — 시험은 통과해도 실력이 안 남는다
3. 강의·문서·모의고사가 제각각 흩어져 있어 하나의 동선이 없다
4. 좋은 자료는 유료이고, 시험 개정보다 늦게 업데이트되기도 한다

목표: **한국어 · 이해 중심 · 통합 로드맵 · 무료/최신** — 이 사이트의 내용만으로 원하는 AWS 자격증을 취득할 수 있는 학습 사이트 + 모의고사. GitHub Pages 정적 배포.

## Demand Evidence

- 1차 사용자 = 제작자 본인. 목적의 궤적: "내 공부 + 포트폴리오 → 자격증 취득(직접 응시) → 진짜 제품".
- 외부 수요 증거는 아직 없음 (전제: 본인 합격이 첫 증거가 된다).
- 시장 자체의 수요는 검증됨 — Tutorials Dojo, Maarek 등이 이미 사업으로 존재. 미충족 수요는 "한국어 + 이해 중심 + 통합 + 무료"의 교집합.

## Status Quo

- 현재 한국어 학습자의 워크플로: Udemy 영어 강의(자막) + ExamTopics 덤프 암기 + 흩어진 블로그 글. 비용 발생, 이해 없는 암기, 동선 부재.
- 이 저장소의 현재 상태: Vite+TS 정적 사이트, GitHub Pages 배포 파이프라인 완성, 12개 자격증 데이터 모델 정의 완료, SAA 학습문서 29개(진짜 콘텐츠, INDEX·로드맵 포함).
- 문항 현황 (적대적 리뷰에서 정정됨): **SAA는 이미 손으로 작성한 실문항 325개(5세트×65, `src/content/saaQuestions.ts`)를 보유**하고, `main.ts`의 SAA 전용 하드코딩 분기(`cert.id === "solutions-architect-associate"`, line 138/149/446)로 노출 중. **나머지 11개 자격증(CLF 포함)은 절차 생성 템플릿(`makeQuestionBank`) 문항으로 실제 시험 가치 0.**
- 단, SAA 실문항의 해설은 한 줄 요약("호스트/경로+인증+WebSocket=ALB")이고 오답해설이 없음 — "이해 중심" 기준에는 아직 미달.

## Target User & Narrowest Wedge

- 타깃: 한국어로 AWS 자격증을 준비하는 사람. 첫 번째 구체적 인간 = 제작자 본인.
- 쐐기: **CLF-C02 1개를 끝까지 완성** (학습문서 + 검증된 문제 + 본인 실제 합격) → 그다음 SAA-C03 (기존 문서 29개 + 실문항 325개 활용). 12개 동시 진행 금지. **SAA 콘텐츠 작업(해설 업그레이드, stepIds 연결)은 CLF 합격 후에만 시작한다 — CLF 집중을 지키는 명시적 게이트. 단, 코드 공통화에 필요한 최소 이전(SAA를 공통 팩토리 경로로 이동 + 회귀 테스트)은 게이트 예외다.**
- CLF 먼저인 이유: 범위가 좁아 "처음부터 끝까지 100%"가 현실적으로 가능. 포맷이 통한다는 첫 증명. SAA는 깊이의 증명.

## Constraints

- GitHub Pages 정적 사이트 (서버 없음, DB 없음) — 모든 콘텐츠는 빌드 타임에 포함
- 1인 제작, 콘텐츠 검수는 사람(본인)만 가능
- 실제 AWS 시험 문항은 NDA — 복제 금지. 공식 Exam Guide의 도메인/Task/Skill 기반 자작 문항만
- 제작 속도가 본인 학습 속도에 묶임 (전략 C의 의도된 제약)

## Premises (사용자 전부 동의, 2026-06-05)

1. 진짜 병목은 코드가 아니라 콘텐츠 품질이다. 구조는 ~90% 완성.
2. 절차 생성 문제(`makeQuestionBank`)는 자산이 아니라 부채다. 가짜 문제는 거짓 자신감을 주므로 0보다 나쁘다. 폐기 대상. *(적용 범위 정정: SAA를 제외한 11개 자격증에 해당 — SAA는 이미 실문항 325개를 별도 경로로 사용 중)*
3. "12개 전부"는 지금 목표가 아니다. CLF 1개의 끝까지 완성이 목표.
4. "이해 중심 + 한국어"를 지키려면 문항마다 진짜 "왜"가 필요하고, AI 초안은 가능하나 사실 검수는 사람이 해야 한다.
5. 성공 기준은 측정 가능해야 한다: 본인이 이 사이트만으로 CLF 모의고사 700/1000을 반복 돌파하고 실제 시험에 합격.

## Approaches Considered

### Approach A: CLF 콘텐츠 스프린트 (최소 실행형)
구조 그대로, CLF 콘텐츠만 전력 생산. 노력 M / 위험 Low.
- 장점: 가장 빨리 진짜 가치 발생, 코드 작업 최소
- 단점: 콘텐츠가 `data.ts` TS 객체에 갇혀 12개 확장 시 재작업, 검수 추적 장치 부재

### Approach B: 검증 파이프라인 먼저 (이상적 아키텍처)
문항 파일 분리 + verified 플래그 + 빌드 타임 검증 + 커버리지 대시보드 전체 구축 후 콘텐츠 채움. 노력 L / 위험 Med.
- 장점: 12개 확장이 복제 작업이 됨, 품질이 시스템으로 보장
- 단점: 몇 주간 사용자 가치 0, "도구 만들다 콘텐츠 안 만드는" 함정

### Approach C: 공부가 곧 콘텐츠 (측면 접근)
본인의 CLF→SAA 학습 자체를 생산 루프로: 매 학습 세션 = 학습문서 1개 + 문항 ~10개. 틀린 지점이 오답해설이 됨. 실제 응시 후 갭 분석 반영. 노력 M(학습 기간 분산) / 위험 Med.
- 장점: 두 목표(내 합격 + 제품 증명) 동시 달성, 콘텐츠가 실전 검증됨
- 단점: 속도가 학습 속도에 묶임, 제작자가 멈추면 사이트도 멈춤

## Recommended Approach (사용자 승인: C + 최소 B)

**C를 작동 방식으로, A의 범위(CLF 먼저)로, B의 최소 골격만 깔고 시작한다.**

시작 전 1회성 기반 작업 (코드, ~1일 — 핵심은 신규 구축이 아니라 **기존 SAA 패턴의 일반화**):
1. **SAA 하드코딩 분기 일반화**: `main.ts`의 `cert.id === "solutions-architect-associate"` 분기(`getEffectiveExams`/`getQuestion` 등)를 "자격증별 실문항 뱅크가 있으면 그것을, 없으면 빈 상태"를 선택하는 일반 로직으로 교체.
2. **가짜 문제 생성기 폐기 + 빈 상태 안전 처리**: `makeQuestionBank` 절차 생성 제거. 구체 명세 — `buildCert`는 실문항 뱅크가 없는 자격증의 `questionBank`를 빈 배열 `[]`로 채움(타입은 `PracticeQuestion[]` 유지, optional화 불필요). `makeExamSessions`는 빈 뱅크일 때 `[]` 반환. `makeRandomExam`(main.ts:132)과 `getQuestion`(main.ts:155)의 비-SAA 경로는 빈 뱅크에서 호출되지 않도록 **모의고사 탭 렌더 함수에서 게이트**: 검증 문항 수가 임계치(1회차=65개) 미만이면 시작 버튼 비활성 + 자격증 카드·모의고사 탭에 "콘텐츠 준비 중 — 현재 검증 문항 N개" 배지.
3. **문항 포맷 확정 + 메타 필드 보강**: 기존 `SaaRawQuestion` 스키마를 공통 포맷으로 채택해 `src/content/{cert}/questions` 패턴으로 복제. 스키마에 `verified: boolean`, `examGuideDomain`(공식 Exam Guide 도메인 매핑), `sourceNote`(검수 근거), `wrongExplanations`(오답해설) 필드 추가.
4. **빌드 타임 게이트**: `verified: false` 문항은 기본 빌드에서 완전 제외. exam의 `questionIds` 생성도 verified 문항만 대상으로 하여 ID 정합성 깨짐(런타임 throw)을 원천 차단. 초안 확인 메커니즘 — URL 파라미터가 아니라 **빌드 타임 분기**: 초안 문항은 별도 파일(`questions.draft.ts`)에 두고 `import.meta.env.DEV`(또는 `VITE_INCLUDE_DRAFTS`)일 때만 조건부 import. 이렇게 해야 초안 데이터가 prod 번들에 아예 포함되지 않는다.
5. **학습문서 로딩 일반화**: `import.meta.glob("./content/saa/*.md")` 하드코딩을 정적 리터럴 단일 글롭 `import.meta.glob("./content/*/*.md")`으로 교체하고 디렉터리명으로 자격증별 그룹핑 (Vite glob 패턴은 정적 리터럴이어야 함 — `{cert}` 템플릿 보간 불가).

이후 반복 루프 (CLF 학습 기간 동안, 매 세션):
1. 공식 CLF-C02 Exam Guide의 도메인/Task 하나를 공부
2. 학습문서 1개 작성 (SAA 문서와 같은 구조: 개념 → 판단 기준 → 오답 패턴)
3. 문항 ~10개 생산: AI 초안 → 본인이 공식 문서 대조 검수 → `verified: true`
4. 본인이 직접 풀어보고 틀린 지점을 오답해설(`wrongExplanations`)에 반영
5. 도메인 커버리지 체크: Exam Guide 도메인 비중 대비 문항 수 균형 확인

증명 단계:
- CLF 모의고사 700/1000 반복 돌파 → 실제 시험 접수·응시
- 응시 후 갭 분석: 응시 경험을 바탕으로 **공식 Exam Guide의 누락 Task를 재점검**해 콘텐츠에 반영 (실제 시험 문항·주제의 기억 기반 복원은 NDA 경계 — 하지 않는다)
- 합격 → SAA로 동일 루프 (기존 문서 29개 ↔ 실문항 325개 연결 + 한 줄 해설을 오답해설 포함 "이해 중심" 해설로 업그레이드하는 작업부터. 이때 SAA-C03 공식 Exam Guide 정확한 deep link 확보 — 현재 `data.ts:412`의 officialGuide는 generic URL)

## Success Criteria

- [ ] 가짜 생성 문항이 사용자에게 노출되지 않는다 (정직한 "준비 중" 상태)
- [ ] 빌드 타임 정합성 체크 통과: 모든 exam `questionIds`가 실재하는 verified 문항을 가리킴 (런타임 throw 0건)
- [ ] CLF: Exam Guide 4개 도메인 전부에 검증된(verified) 학습문서 + 문항 존재
- [ ] CLF 검증 문항 ≥130개 (실전형 모의고사 2회차)
- [ ] 본인이 사이트만으로 모의고사 정답률 ≥70%를 3회 연속 돌파 (내부 학습 기준 — AWS 스케일드 점수 700/1000과 동일하지 않으며 근사 지표로만 사용)
- [ ] **본인이 실제 CLF-C02 시험 합격** ← 최종 증명
- [ ] 응시 후 갭 분석이 콘텐츠에 반영됨

## ENG REVIEW DECISIONS (2026-06-05, /plan-eng-review)

구현 시 이 결정들이 기반 작업을 구체화·수정한다:

- **D1**: `makeSteps`의 생성 `questionIds` 비우기 — 검증 문항 생성 시 진짜 ID로 연결
- **D2**: 가짜 학습문서도 격리 — `renderGeneratedStudyTab`/`makeGeneratedDocMarkdown` 삭제. 실문서 없는 자격증은 학습 탭 "준비 중"+공식 가이드 링크
- **D3**: `src/content/index.ts` 콘텐츠 레지스트리 `certContent: Record<certId, {questionBank, exams, docs}>` — main.ts 분기 3곳(getEffectiveExams/getQuestion/renderStudyTab) 통일
- **D4**: `buildCertContent(certId, rawQuestions, examMeta)` 공통 팩토리 (변환+회차 파생+verified 필터). SAA도 이 경로로 이전 (게이트 예외)
- **D5+D10**: 오답해설 보일러플레이트 금지. 표시 정책은 "있으면 표시" — 단 **verified:true 요건에 wrongExplanations 존재 포함** (빌드 검증으로 강제)
- **D6**: 문항 렌더링 escapeHtml 일관화 (prompt/option/caseText/피드백) + `<` 포함 문항 테스트
- **D7+D11**: vitest 도입, 커버리지 다이어그램 20개 GAP 전부 + **SAA 회귀 테스트 필수(CRITICAL)** + 무결성 체크(exam questionIds ⊆ bank), 빌드에 연결
- **D8**: 코드 스플리팅은 TODO (3번째 자격증 시 dynamic import 전환)
- **D12**: 일반화는 지금 (CLF만 하드코딩 추가안 기각)
- **D13**: CLF 콘텐츠에 `examGuide: {domain, tasks[]}` 매핑 데이터. 문항은 `examGuideTaskId`로 연결. 로드맵 = 이 데이터 렌더. 커버리지 기준 = **Task당 ≥5문항** (130문항 고정 기준 대체)
- **D14**: localStorage 응시 이력 + 모의고사 탭에 최근 응시·연속 70% 표시 (저장 실패 시 우아한 강등). *스키마는 CEO 플랜(2026-06-05-clf-learning-loop.md)이 상위 사양으로 확장: `{certId, examId, date, correct, total, wrongQuestionIds[], flaggedQuestionIds[], durationSpentSec}`*
