# 모델 배포 전략 (배포 경로 선택·LLM 고유의 배포 문제·성능과 리소스의 균형)

> **커버하는 공식 Task** — AIP-C01 · 도메인 2 「구현 및 통합」(26%) · **작업 2.2 모델 배포 전략 구현** (`aip-t2-2`)
> 이 문서는 위 한 작업에 1:1로 매핑되고 공식 기술 3개(2.2.1~2.2.3)를 모두 덮습니다. 도메인 2에서 기술이 가장 적은 작업인데, 묻는 것은 **기억할 수치가 아니라 「이 요구 조건에서 어느 배포 경로가 성립하는가」**입니다.

---

## ✅ 학습 목표 체크리스트

- [ ] FM 배포 경로 셋(**온디맨드 · PT · SageMaker AI 엔드포인트**)을 갈라 고를 수 있다
- [ ] Provisioned Throughput의 **MU와 약정**이 무엇을 정하는지 안다
- [ ] SageMaker AI 추론 옵션 **넷**을 요구 조건으로 가를 수 있다
- [ ] 비동기 추론의 **S3 경유 호출 계약**을 안다
- [ ] 서버리스 추론이 **어떤 트래픽에 맞고 무엇을 포기하는지** 안다
- [ ] LLM 배포에서 공식이 드는 **최적화 셋**을 안다
- [ ] 배치 추론이 **쓸 수 없는 조건**을 안다
- [ ] 모델 캐스케이딩의 **AWS 관리형 수단과 그 제약**을 안다

---

## 🎯 왜 중요한가

GenAI 워크로드의 배포에서 비싼 실수는 **모델을 잘못 고르는 것이 아니라 배포 경로를 잘못 고르는 것**입니다. 온디맨드로 충분한 워크로드에 약정을 걸면 **삭제할 수 없는 비용**이 생기고, 반대로 일관된 처리량이 필요한 운영 트래픽을 공유 용량에 두면 **스로틀링이 사용자에게 보입니다.**

그리고 LLM은 기존 ML 배포와 **다른 문제**를 냅니다 — 모델이 단일 가속기 메모리에 안 들어가고, 처리량의 단위가 요청이 아니라 **토큰**입니다. 공식 기술 2.2.2가 그것을 따로 적는 이유입니다.

---

## ⚡ 시험 직전 요약

- **PT(Provisioned Throughput)**의 가격은 셋이 정합니다 — **모델**(사용자 지정 모델은 기반 모델과 같은 가격) · **MU 수** · **약정 기간**(길수록 시간당 가격이 할인됩니다).
- **MU 1개가 정하는 것**은 **1분 동안 전 요청에 걸쳐 처리할 입력 토큰 수와 생성할 출력 토큰 수**입니다.
- 약정은 **없음 · 1개월 · 6개월**이고 ⚠️⚠️ **약정 기간이 끝나기 전에는 삭제할 수 없으며 삭제할 때까지 과금이 이어집니다.**
- ⚠️⚠️ **사용자 지정 모델 추론 경로는 둘**입니다 — **PT 구매** 또는 **온디맨드 추론용 배포**. ⚠️ 공식 PT 페이지는 아직 「PT를 사야 쓸 수 있다」고 적어 **문서 사이가 갈립니다.**
- SageMaker AI 추론 옵션 넷 — **실시간**(영구 엔드포인트) · **서버리스**(유휴 기간 있는 트래픽, **0으로 축소**) · **비동기**(큐, **페이로드 1GB · 처리 1시간**, **0으로 축소**) · **배치 변환**(영구 엔드포인트 불필요).
- ⚠️⚠️ **비동기 추론은 페이로드를 S3에 두고 포인터를 넘깁니다** — 호출은 **식별자와 출력 위치**를 즉시 반환하고 결과가 S3에 들어오며 통지는 **SNS**로 받습니다. ⚠️ **`AsyncInferenceConfig`가 엔드포인트 구성에 있으면 그 엔드포인트는 비동기 호출만 받습니다.**
- 서버리스 추론은 **인스턴스 유형·조정 정책을 고르지 않고** ⭐ **Lambda와 통합**돼 자동 확장되며, 예측 가능한 급증에는 **프로비저닝된 동시성**으로 **웜 상태를 유지**합니다.
- LLM 배포의 공식 최적화 셋은 **양자화 · 텐서 병렬 처리 · 연속 배칭**이고, 고르는 축은 **인스턴스 유형과 백엔드**입니다.
- ⚠️⚠️ **배치 추론은 프로비저닝된 모델에서 지원되지 않고**, `Converse` 호출 유형에서는 **도구 호출을 지원하지 않습니다**(`toolConfig`가 든 레코드는 **400**).
- ⚠️ 모델 캐스케이딩의 AWS 관리형 수단인 **지능형 프롬프트 라우팅은 같은 모델 패밀리 안에서만** 라우팅합니다.

| 용어 | 뜻 |
|---|---|
| **온디맨드** | 공유 용량에서 호출한 만큼 과금되는 기본 추론 방식 |
| **MU**(Model Unit) | PT가 사는 단위. 1분당 처리할 입력·출력 토큰 수를 정한다 |
| **약정 기간** | PT를 유지하기로 묶는 기간. 길수록 시간당 가격이 싸다 |
| **콜드 스타트** | 유휴 상태에서 첫 요청이 올 때 컴퓨팅을 띄우는 지연 |
| **프로비저닝된 동시성** | 서버리스 엔드포인트를 웜 상태로 유지하는 선택 설정 |

| **연속 배칭** | 요청을 고정 배치로 묶지 않고 끝난 자리에 새 요청을 채우는 방식 |
| **캐스케이딩** | 싼 모델이 먼저 처리하고 필요할 때만 비싼 모델로 올리는 패턴 |

## 📖 핵심 개념

### 1) 요구 조건에 맞는 FM 배포 (기술 2.2.1) {#deploy-paths}

> 🧠 원리: 공식 기술이 드는 셋은 **같은 축의 선택지가 아닙니다** — Lambda는 **호출 방식**, PT는 **용량 확보 방식**, SageMaker AI 엔드포인트는 **호스팅 방식**입니다. 질문이 어느 축을 묻는지 가려야 보기가 갈립니다.

**① 온디맨드 호출** — 공유 용량에서 호출한 만큼 과금됩니다. 서버리스 함수(예: Lambda)가 요청마다 Bedrock을 부르는 형태가 가장 단순한 배포이고, 트래픽이 일정하지 않을 때 비용이 가장 낮습니다. ⚠️ 쿼터는 공유라 피크에 **스로틀링**이 사용자에게 보일 수 있습니다.

**② Provisioned Throughput(PT)** — **고정 비용으로 더 높은 처리량을 확보**합니다. 공식 정의부터 봐야 합니다 — **처리량은 모델이 처리·반환하는 입력과 출력의 수와 속도**입니다.

| 가격을 정하는 것 | 내용 |
|---|---|
| **모델** | 고르는 모델에 따른다(⭐ **사용자 지정 모델은 기반 모델과 같은 가격**) |
| **MU 수** | MU 1개가 **1분 동안 전 요청에 걸쳐 처리할 입력 토큰 수**와 **생성할 출력 토큰 수**를 정한다 |
| **약정 기간** | **길수록 시간당 가격이 할인**된다 |

- 약정 셋: **약정 없음**(언제든 삭제 가능) · **1개월** · **6개월**. ⚠️⚠️ 뒤의 둘은 **기간이 끝나기 전에 삭제할 수 없습니다.** 그리고 **삭제할 때까지 과금이 이어집니다** — 쓰지 않아도 멈추지 않습니다.
- 구매는 시간당 과금이고 콘솔에서 **`By Model Units`** 모드로 약정 기간과 MU 수를 고릅니다. ⚠️ **약정이 있는 모델을 프로비저닝하려면 먼저 AWS Support 센터에 구매 가능한 MU 수 증액을 요청**해야 합니다. ⚠️ **AWS GovCloud(US)에서는 약정 없는 사용자 지정 모델에만** PT를 살 수 있습니다.
- 상태는 **`Creating` → `In service`**(실패하면 `Failed`)로 갑니다.
- ⚠️⚠️ **사용자 지정 모델의 추론 경로는 둘입니다** — **PT 구매** 또는 **온디맨드 추론용 배포**. 그런데 **공식 PT 페이지는 아직 「모델을 사용자 지정했다면 그것을 쓰기 위해 PT를 구매해야 한다」고 적습니다.** 문서 사이가 갈리는 자리이므로 이 사이트는 **어느 한쪽으로 단정하지 않고 두 경로를 가르칩니다**(작업 1.2와 같은 판정입니다).

**③ SageMaker AI 엔드포인트** — 하이브리드 솔루션이나 자체 호스팅이 필요할 때입니다. 공식 추론 옵션은 넷입니다.

| 옵션 | 언제 | 공식이 적는 경계 |
|---|---|---|
| **실시간 추론** | 낮은 지연 또는 높은 처리량이 필요한 온라인 추론 | **영구적이고 완전관리형인 엔드포인트(REST API)**. 고른 인스턴스 유형이 뒤를 받친다 |
| **서버리스 추론** | **간헐적이거나 예측 불가능한** 트래픽 패턴 | 인프라를 **전혀 관리하지 않고** **쓴 만큼만 과금**(유휴 시간 과금 없음). 페이로드 **최대 4MB**, 처리 **최대 60초** |
| **배치 변환** | 데이터가 미리 다 있고 **영구 엔드포인트가 필요 없는** 오프라인 처리 | 데이터세트 전처리에도 쓴다. **며칠 걸리는 처리**를 감당한다 |
| **비동기 추론** | 요청을 **큐에 넣고** 큰 페이로드를 긴 처리 시간으로 | 페이로드 **최대 1GB**, 처리 **최대 1시간**. **요청이 없으면 엔드포인트를 0으로 축소** |

- ⚠️⚠️ **실시간 추론의 페이로드 상한은 공식 안에서 갈립니다** — 추론 옵션 페이지는 **최대 25MB**(스트리밍 응답은 8분까지)로 적는데 지원 기능 표는 **6MB 미만**으로 적습니다. 그래서 이 사이트는 **그 수치를 묻지 않고** 옵션 사이의 **상대적 경계**(서버리스 4MB·60초 ↔ 비동기 1GB·1시간)와 **성질**로 가릅니다.
- **비동기 추론의 호출 계약**이 비자명합니다 — 엔드포인트 구성에 **`AsyncInferenceConfig`**를 지정해 만들고, ⚠️⚠️ **요청 페이로드를 S3에 둔 뒤 `InvokeEndpointAsync`에 그 포인터를 넘깁니다.** 호출은 **식별자와 출력 위치를 응답으로 즉시 반환**하고, 처리가 끝나면 SageMaker가 **결과를 S3에** 둡니다. 성공·오류 통지는 선택적으로 **SNS**로 받습니다.
- ⚠️⚠️ 그리고 **`AsyncInferenceConfig`가 엔드포인트 구성에 있다는 것은 그 엔드포인트가 비동기 호출만 받을 수 있다는 뜻**입니다 — 같은 엔드포인트를 동기로도 쓰려는 설계는 성립하지 않습니다.
- **서버리스 추론**은 **인스턴스 유형을 고르거나 조정 정책을 관리할 필요가 없고** ⭐ **AWS Lambda와 통합**돼 고가용성·내장 내결함성·자동 확장을 받습니다. **요청이 없는 동안 0으로 축소**됩니다. ⚠️ 대가는 **콜드 스타트를 감내해야 한다**는 것이고, 공식이 그 조건을 명시합니다(「트래픽 급증 사이에 유휴 기간이 있고 **콜드 스타트를 감내할 수 있는** 워크로드에 이상적」).
- 급증이 **예측 가능하면 프로비저닝된 동시성**을 켜 **엔드포인트를 웜 상태로 유지**합니다 — 할당한 만큼 컴퓨팅이 초기화돼 **밀리초 안에** 응답하고, 과금은 **밀리초 단위 컴퓨팅 + 처리 데이터량 + 프로비저닝된 동시성 사용량**(구성 메모리·프로비저닝 기간·동시성)입니다. **Application Auto Scaling**과 통합돼 **목표 지표나 일정**으로 관리합니다.
- ⚠️ 서버리스에는 **기능 제외(feature exclusions)** 목록이 있고, 비동기 추론도 **제외 목록의 기능을 쓰는 엔드포인트에서는 쓸 수 없습니다.**

### 2) LLM 배포의 고유 문제 (기술 2.2.2) {#llm-deploy}

> 🧠 원리: 기존 ML 모델은 **한 인스턴스에 올라가고** 처리량의 단위가 **요청**입니다. LLM은 둘 다 깨집니다 — 모델이 **단일 가속기 메모리를 넘고** 처리량이 **토큰**으로 셉니다. 그래서 배포 기술이 따로 필요합니다.

- 공식이 이 자리를 위해 두는 것이 **대규모 모델 추론(LMI) 컨테이너**입니다 — **LLM 추론을 위한 전용 Docker 컨테이너이고 AWS가 제공**합니다.
- ⚠️ **그 상세 문서는 AWS docs 안이 아니라 Deep Java Library 문서 사이트에 있습니다.** AWS docs에는 **개요와 그쪽을 가리키는 페이지**가 있고, 그 페이지가 적는 범위는 다음입니다:
  - LMI 컨테이너의 **구성 요소와 아키텍처**를 이해한다
  - 용례에 맞는 **인스턴스 유형과 백엔드를 고른다**
  - SageMaker AI에 LLM을 **구성·배포**한다
  - ⭐ **양자화 · 텐서 병렬 처리 · 연속 배칭** 같은 기능으로 **성능을 최적화**한다
  - 엔드포인트를 **벤치마크하고 튜닝**해 처리량·지연을 맞춘다
- 그래서 기술 2.2.2의 세 축이 이렇게 대응합니다 — **메모리 요구·모델 로딩 전략**은 모델을 여러 가속기에 쪼개는 쪽(**텐서 병렬 처리**)과 **양자화**, **GPU 사용률**은 **인스턴스 유형·백엔드 선택**, **토큰 처리 용량 최적화**는 **연속 배칭**입니다.
- ⚠️ 이 사이트는 **특정 라이브러리 이름이나 수치를 묻지 않습니다** — 그 서술의 근거가 AWS docs가 아니라 블로그와 외부 문서에 있습니다. 공식 AWS docs가 적는 **최적화 기능의 이름**과 **결정 축**까지만 다룹니다.
- ⚠️ 그리고 배포 유형과 **GPU 지원**이 엮입니다 — 지원 기능 표가 **실시간·배치 변환·비동기에 GPU 지원**을 표시하는 반면 **서버리스 추론 열에는 표시하지 않습니다.** 「GPU가 필요한 LLM을 서버리스로」라는 설계는 그 자리에서 걸립니다.

### 3) 성능과 리소스의 균형 (기술 2.2.3) {#balance}

> 🧠 원리: 이 기술이 드는 셋은 전부 **「덜 쓰고 같은 결과를 얻는」 수단**입니다 — 작업에 맞는 모델, 작은 모델, 그리고 **쉬운 요청을 싼 경로로 보내기**. 중요한 것은 셋 중 **AWS가 관리형으로 주는 것이 어디까지인가**입니다.

- **적절한 모델 선택**이 가장 큰 레버입니다. 같은 작업을 더 작은 모델이 충족하면 지연·비용·처리량이 함께 좋아집니다.
- **사전 학습된 소규모 모델**로 특정 작업을 처리하는 것이 둘째입니다. 큰 범용 모델이 필요한 작업과, 작업이 좁아 작은 모델로 충분한 것을 가르는 것이 설계입니다.
- **API 기반 모델 캐스케이딩**은 **싼 모델이 먼저 처리하고 실패·저신뢰일 때만 비싼 모델로 올리는** 패턴입니다. ⚠️ 이 패턴의 라우팅 로직 자체는 **애플리케이션이 구현**하고, AWS가 관리형으로 주는 수단은 **지능형 프롬프트 라우팅**입니다 — 단일 서버리스 엔드포인트가 요청마다 **각 모델의 응답 품질을 예측**해 더 좋은 쪽으로 보내고 **폴백 모델**과 응답 품질 차이 기준을 둡니다.
- ⚠️⚠️ 그 수단에 **결정적 제약**이 있습니다 — **같은 모델 패밀리 안에서만** 라우팅하고 **영어 프롬프트에 최적화**돼 있습니다. 「다른 패밀리의 더 싼 모델로 자동 캐스케이딩」은 이 기능으로 되지 않습니다.
- **배치 추론**은 비용을 낮추는 또 한 경로입니다 — 여러 프롬프트를 **비동기로** 처리하고 입력 파일을 **S3**에 올려 작업을 제출하면 결과가 S3에 들어옵니다. 입력 형식은 **`InvokeModel` 또는 `Converse` 형식**입니다. ⭐ 폴링 대신 **EventBridge로 작업 상태 변경 알림**을 받을 수 있습니다.
- ⚠️⚠️ 배치 추론의 조건 둘이 시험다운 자리입니다 — **프로비저닝된 모델에서는 지원되지 않고**(PT를 산 모델에 배치를 돌릴 수 없습니다), **`Converse` 호출 유형 작업에서는 도구 호출을 지원하지 않습니다**(`toolConfig`가 든 레코드는 **400으로 실패**). 도구 호출이 필요하면 **`InvokeModel` 호출 유형**으로 작업을 만들고 각 `modelInput`을 모델의 네이티브 요청 형식으로 적습니다. ⭐ **구조화된 출력은 두 호출 유형 모두** 지원됩니다.
- ⚠️ 온디맨드 쪽 비용·용량 계획에는 **토큰 선차감**이 끼어듭니다 — 요청 시작 시점에 **「입력 토큰 + `max_tokens`」가 쿼터에서 선차감**되므로, 짧게 답하게 설계해도 **큰 `max_tokens`가 쿼터를 먹습니다.** 처리량이 모자라 보일 때 PT를 사기 전에 이것을 먼저 봅니다.

## ✍️ 시험 포인트

- 「일관되고 예측 가능한 처리량이 필요하다」면 **PT**이고, 가격은 **모델·MU 수·약정 기간**이 정합니다.
- 「MU를 늘리면 무엇이 늘어나나」는 **1분당 처리 가능한 입력·출력 토큰 수**입니다.
- 「6개월 약정을 걸었는데 두 달 뒤 안 쓴다」면 **삭제할 수 없고 과금이 이어집니다.**
- 「사용자 지정 모델을 쓰려면 PT가 필수인가」는 **경로가 둘**이고, 문서 사이가 갈린다는 것까지 알아야 합니다.
- 「유휴 기간이 긴 불규칙 트래픽 + 콜드 스타트 허용」이면 **서버리스 추론**, 「예측 가능한 급증」이면 **프로비저닝된 동시성**입니다.
- 「1GB 입력을 한 시간 걸려 처리」면 **비동기 추론**이고, **S3 포인터로 호출**해 **식별자와 출력 위치**를 받습니다.
- 「같은 엔드포인트를 동기·비동기로 함께」는 **안 됩니다** — `AsyncInferenceConfig`가 있으면 비동기만 받습니다.
- 「GPU가 필요한 LLM을 서버리스 엔드포인트로」는 지원 기능 표에서 **GPU 열이 비어 있는** 자리입니다.
- 「LLM이 가속기 하나에 안 들어간다」면 **텐서 병렬 처리**, 「토큰 처리량을 올린다」면 **연속 배칭**입니다.
- 「쉬운 질문은 싼 모델로」면 캐스케이딩이고, 관리형 수단은 **지능형 프롬프트 라우팅**인데 **같은 패밀리 제약**이 있습니다.
- 「PT를 산 모델에 배치 추론을 돌린다」는 **지원되지 않습니다.**
- 「배치로 도구 호출을 쓴다」면 **`InvokeModel` 호출 유형**이어야 합니다.

## ⚠️ 흔한 함정 {#pitfalls}

- ⚠️⚠️ **약정 PT를 「쓰지 않으면 과금이 멈춘다」고 생각하기.** **삭제할 때까지** 이어지고 약정 중에는 삭제가 **불가능**합니다.
- ⚠️ **MU 수를 바로 크게 사려 하기.** 약정 있는 모델은 **먼저 Support에 MU 증액을 요청**해야 합니다.
- ⚠️⚠️ **「사용자 지정 모델 = PT 필수」로 단정하기.** 경로가 **둘**이고 공식 문서 사이가 갈립니다.
- ⚠️ **실시간 추론 페이로드 상한을 외우기.** 공식 안에서 **25MB ↔ 6MB 미만**으로 갈립니다.
- ⚠️⚠️ **비동기 추론에 페이로드를 직접 실어 보내기.** **S3에 두고 포인터**를 넘깁니다.
- ⚠️ **비동기 엔드포인트를 동기로도 쓰려 하기.** 구성에 `AsyncInferenceConfig`가 있으면 **비동기만**입니다.
- ⚠️ **서버리스 추론에서 콜드 스타트가 없다고 기대하기.** 공식이 **감내 조건**으로 적습니다.
- ⚠️ **서버리스 추론으로 GPU 워크로드를 돌리려 하기.** 지원 기능 표의 GPU 열을 봅니다.
- ⚠️⚠️ **LMI 컨테이너의 내부 라이브러리 이름·수치를 외우기.** AWS docs는 **개요와 최적화 기능 이름**까지이고 상세는 외부 문서입니다.
- ⚠️⚠️ **프롬프트 라우팅이 패밀리를 넘는다고 생각하기.** **같은 패밀리 안에서만**입니다.
- ⚠️ **PT를 산 모델에 배치 추론을 계획하기.** **지원되지 않습니다.**
- ⚠️⚠️ **`Converse` 형식 배치 작업에 `toolConfig`를 넣기.** **400으로 실패**합니다.
- ⚠️ **처리량이 모자라면 바로 PT를 사기.** **`max_tokens` 선차감**을 먼저 봅니다.

## 🧪 자가 점검

**Q1.** 운영 트래픽이 일정하고 스로틀링을 사용자에게 보이고 싶지 않습니다. PT를 고려할 때 비용을 정하는 세 가지는 무엇입니까?

<details><summary>정답 보기</summary>

**모델 · MU 수 · 약정 기간**입니다. MU 1개는 **1분 동안 전 요청에 걸쳐 처리할 입력 토큰 수와 생성할 출력 토큰 수**를 정하고, **약정이 길수록 시간당 가격이 할인**됩니다(사용자 지정 모델은 **기반 모델과 같은 가격**). ⚠️ 약정은 **없음·1개월·6개월**이고 뒤의 둘은 **기간이 끝나기 전 삭제 불가**이며 **삭제할 때까지 과금**이 이어집니다.
</details>

**Q2.** 「우리 사용자 지정 모델을 쓰려면 PT를 반드시 사야 한다」는 서술을 어떻게 다뤄야 합니까?

<details><summary>정답 보기</summary>

**단정하지 않습니다.** 사용자 지정 모델 추론 경로는 **둘**입니다 — **PT 구매** 또는 **온디맨드 추론용 배포**. ⚠️ 그런데 공식 PT 페이지는 아직 **「모델을 사용자 지정했다면 그것을 쓰기 위해 PT를 구매해야 한다」**고 적어 **문서 사이가 갈립니다.** 그래서 이 사이트는 두 경로를 함께 가르치고 어느 한쪽을 「유일한 경로」로 적지 않습니다.
</details>

**Q3.** 500MB 영상을 한 번에 처리해 결과를 받는 엔드포인트가 필요합니다. 어떤 추론 옵션이고 호출 절차는 어떻게 됩니까?

<details><summary>정답 보기</summary>

**비동기 추론**입니다(페이로드 **최대 1GB**, 처리 **최대 1시간**). 엔드포인트 구성에 **`AsyncInferenceConfig`**를 지정해 만들고, ⚠️⚠️ **페이로드를 S3에 둔 뒤 `InvokeEndpointAsync`에 그 포인터**를 넘깁니다. 호출은 **식별자와 출력 위치를 즉시 반환**하고 결과는 **S3**에 들어오며, 성공·오류 통지는 **SNS**로 받습니다. ⚠️ 그 구성이 있으면 그 엔드포인트는 **비동기 호출만** 받습니다.
</details>

**Q4.** 내부 도구가 하루에 몇 번만 호출되고 몇 초의 지연은 괜찮습니다. 비용을 최소화하는 SageMaker AI 옵션과 그 대가는 무엇입니까?

<details><summary>정답 보기</summary>

**서버리스 추론**입니다 — 인스턴스 유형·조정 정책을 고르지 않고 **쓴 만큼만** 과금되며 **요청이 없으면 0으로 축소**됩니다(페이로드 **최대 4MB** · 처리 **최대 60초**). 대가는 ⚠️ **콜드 스타트를 감내해야 한다**는 것이고 공식이 그것을 적용 조건으로 적습니다. 급증이 **예측 가능**해지면 **프로비저닝된 동시성**으로 웜 상태를 유지하고 **Application Auto Scaling**으로 목표 지표나 일정에 맞춥니다.
</details>

**Q5.** 70B 규모 LLM을 SageMaker AI에 배포합니다. 공식이 드는 최적화 셋과 고르는 축은 무엇입니까?

<details><summary>정답 보기</summary>

최적화는 **양자화 · 텐서 병렬 처리 · 연속 배칭**이고, 고르는 축은 **인스턴스 유형과 백엔드**입니다. 수단은 **대규모 모델 추론(LMI) 컨테이너**(AWS가 제공하는 LLM 추론 전용 Docker 컨테이너)이고 ⚠️ **상세 문서는 AWS docs 밖(Deep Java Library 문서 사이트)에 있어** 이 사이트는 내부 라이브러리 이름·수치를 다루지 않습니다.
</details>

**Q6.** PT를 구매한 모델에 대해 1만 건의 프롬프트를 야간 배치로 돌리려 합니다. 무엇이 문제입니까?

<details><summary>정답 보기</summary>

⚠️⚠️ **배치 추론은 프로비저닝된 모델에서 지원되지 않습니다.** 배치는 온디맨드 경로로 돌립니다 — 입력 파일을 **S3**에 올려 작업을 제출하고 결과를 S3에서 회수하며, 폴링 대신 **EventBridge**로 상태 변경을 받습니다. ⚠️ 그리고 `Converse` 호출 유형에서는 **도구 호출이 지원되지 않아** `toolConfig`가 든 레코드가 **400**으로 실패합니다 — 도구 호출이 필요하면 **`InvokeModel` 호출 유형**으로 만듭니다.
</details>

**Q7.** 「쉬운 질문은 다른 패밀리의 더 싼 모델로 보내 비용을 절반으로」라는 계획을 지능형 프롬프트 라우팅으로 구현할 수 있습니까?

<details><summary>정답 보기</summary>

할 수 없습니다. ⚠️⚠️ 지능형 프롬프트 라우팅은 **같은 모델 패밀리 안에서만** 라우팅하고 **영어 프롬프트에 최적화**돼 있습니다. 패밀리를 넘는 캐스케이딩은 **애플리케이션이나 오케스트레이터의 라우팅 로직**으로 구현합니다. 라우팅이 주는 것은 요청마다 **응답 품질을 예측**해 더 좋은 쪽으로 보내는 것과 **폴백 모델**입니다.
</details>
