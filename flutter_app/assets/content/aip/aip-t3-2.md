# 데이터 보안과 개인 정보 보호 제어 (네트워크 격리·세분화된 액세스·데이터 보존·PII 탐지·마스킹과 익명화)

> **커버하는 공식 Task** — AIP-C01 · 도메인 3 「AI 안전, 보안 및 거버넌스」(20%) · **작업 3.2 데이터 보안 및 개인 정보 보호 제어 구현** (`aip-t3-2`)
> 이 문서는 위 한 작업에 1:1로 매핑되고 공식 기술 3개(3.2.1~3.2.3)를 모두 덮습니다. 기술이 셋뿐이지만 **각 기술이 네다섯 서비스를 나란히** 들어 실제 범위는 넓습니다 — 그리고 셋의 축이 다릅니다: **환경을 가두고**(3.2.1) · **데이터를 찾아 막고**(3.2.2) · **쓸 수 있게 남기는 것**(3.2.3)입니다.

---

## ✅ 학습 목표 체크리스트

- [ ] Bedrock VPC 엔드포인트의 **접미사 종류와 기본 정책**을 안다
- [ ] Lake Formation이 **IAM과 어떤 관계**인지, 현행 세분화 수단이 무엇인지 안다
- [ ] Bedrock **데이터 보존 모드 넷**과 리전 동작을 안다
- [ ] `store=false`가 **제로 보존을 보장하지 않는** 이유를 안다
- [ ] 남용 탐지가 보존하는 것과 **크로스 리전의 영향**을 안다
- [ ] PII 탐지 수단 셋(**Guardrails·Comprehend·Macie**)을 용도로 가른다
- [ ] 마스킹과 차단의 **동작 차이**를 안다
- [ ] 보존 정책을 **S3 수명 주기**로 구현할 때의 제약을 안다

## 🎯 왜 중요한가

GenAI에 데이터를 넣는 순간 질문이 셋 생깁니다 — **어디로 가는가**(네트워크), **누가 볼 수 있는가**(액세스), **얼마나 남는가**(보존). 세 질문은 서로 독립이라 하나를 풀어도 나머지가 남습니다. VPC 엔드포인트로 트래픽을 가둬도 **보존 설정이 기본값이면** 프롬프트가 남고, 보존을 끄더라도 **IAM이 느슨하면** 누구나 모델을 부릅니다.

공식 기술 셋이 그 순서대로 묻고, 특히 **데이터 보존**은 이 자격증에서 비자명한 사실이 가장 많은 자리입니다 — 모드가 네 개이고 **리전마다 따로**이며 **설정이 요청을 차단하기까지** 합니다.

---

## ⚡ 시험 직전 요약

- Bedrock VPC 인터페이스 엔드포인트는 **인터넷 게이트웨이·NAT·VPN·Direct Connect 없이** 접근하게 하고 **퍼블릭 IP가 필요 없습니다**. 접미사가 **컨트롤 플레인·런타임·에이전트 빌드타임·에이전트 런타임** 등으로 갈립니다.
- ⚠️⚠️ **기본 엔드포인트 정책은 그 엔드포인트를 통한 Bedrock 전체 접근을 허용**합니다 — 제한하려면 **사용자 지정 엔드포인트 정책**을 붙입니다.
- ⚠️ **FIPS 엔드포인트 서비스**(`bedrock-fips`·`bedrock-runtime-fips`)는 **일부 리전에서만** 제공됩니다.
- **Lake Formation**은 **IAM 권한 모델을 증강하는 자체 권한 모델**이고 **열·행·셀 수준** 제어를 Athena·Redshift Spectrum·EMR·Glue 등에 걸쳐 적용합니다. ⚠️ **`Governed Tables`는 완전 종료**됐으므로 현행 수단은 **TBAC·행·셀 수준 보안·하이브리드 액세스 모드**입니다.
- ⚠️⚠️ **데이터 보존은 모드**(`none`·`default`·`aws_review`·레거시 `provider_data_share`)이고 **리전마다 따로**입니다. 구성하지 않은 리전은 **`inherit`**이고 **모델 기본값으로 폴백**합니다.
- ⚠️⚠️ **`none`인데 보존을 요구하는 모델을 호출하면 Bedrock이 요청을 차단하고 오류를 반환**합니다.
- ⚠️⚠️ **`store=false`는 제로 보존을 보장하지 않습니다** — 일부 모델이 안전 검토를 위해 보존하되 **고객이 가져올 수 없는** 상태가 됩니다. 보장이 필요하면 **`data_retention_mode: none`**입니다.
- ⚠️ 남용 탐지로 보존된 입출력은 **AWS가 저장·처리하고 3자 모델 공급자와 공유되지 않습니다.** ⚠️⚠️ **크로스 리전 추론이 켜져 있으면 목적지 리전(요청이 처리된 리전)에 저장**됩니다.
- PII 수단 셋을 가릅니다 — **Guardrails 민감 정보 필터**(상호 작용 시점, **차단 또는 마스킹**) · **Comprehend PII 탐지**(텍스트 분석, **영어·스페인어**) · **Macie**(S3에 **저장된** 데이터 발견).
- ⚠️⚠️ **버킷 정책으로 S3 수명 주기의 삭제·전환을 막을 수 없습니다** — 모든 주체에 모든 작업을 거부해도 수명 주기는 정상 동작합니다.

## 🔤 먼저 알아야 할 용어

| 용어 | 뜻 |
|---|---|
| **인터페이스 엔드포인트** | PrivateLink로 VPC 안에 만드는 서비스 진입점(ENI) |
| **엔드포인트 정책** | 인터페이스 엔드포인트에 붙이는 IAM 리소스 기반 정책 |
| **TBAC** | 태그 기반 액세스 제어. 태그로 데이터 권한을 관리한다 |
| **하이브리드 액세스 모드** | Lake Formation 권한과 IAM 권한을 함께 쓰는 모드 |
| **보존 모드** | 프롬프트·출력을 남길지 정하는 설정(`none`·`default`·`aws_review` 등) |
| **ZDR** | 제로 데이터 보존. 요청·응답이 내구성 스토리지에 쓰이지 않는다 |
| **관리형 데이터 식별자** | Macie가 제공하는 내장 민감 데이터 탐지 기준·기법 |
| **마스킹** | 민감 정보를 지우지 않고 유형 라벨 등으로 치환하는 것 |

## 📖 핵심 개념

### 1) 보호된 AI 환경 (기술 3.2.1) {#protected-env}

> 🧠 원리: 「보호된 환경」은 **경로 · 권한 · 데이터**의 세 겹입니다. 공식 기술이 VPC 엔드포인트 · IAM 정책 · Lake Formation · CloudWatch를 나란히 드는 것은 그 세 겹과 **그것을 지켜보는 눈**을 다 두라는 뜻입니다.

**① 네트워크 격리 — 인터페이스 VPC 엔드포인트**

- **AWS PrivateLink**로 VPC와 Bedrock 사이에 사설 연결을 만들면 **인터넷 게이트웨이·NAT 디바이스·VPN·Direct Connect 없이** Bedrock에 접근하고 ⭐ **VPC의 인스턴스에 퍼블릭 IP가 필요하지 않습니다.**
- 엔드포인트를 켠 **서브넷마다 엔드포인트 네트워크 인터페이스**가 생기고 그것이 Bedrock으로 가는 트래픽의 **진입점**입니다(요청자 관리형).
- ⚠️ **API 범주마다 접미사가 다릅니다** — 컨트롤 플레인은 **`bedrock`**, 런타임은 **`bedrock-runtime`**, 에이전트 빌드타임은 **`bedrock-agent`**, 에이전트 런타임은 **`bedrock-agent-runtime`**입니다(그 밖에 `bedrock-mantle`). **추론만 허용하려는 설계에서 어느 접미사를 만들지가 곧 통제**입니다.
- ⚠️ **FIPS 엔드포인트 서비스**(`bedrock-fips`·`bedrock-runtime-fips`)는 **일부 리전에서만** 제공됩니다(us-east-1·us-east-2·us-west-2·ca-central-1과 GovCloud 둘).
- **프라이빗 DNS 호스트 이름**을 켜면 기본 리전 DNS 이름(`bedrock-runtime.region.amazonaws.com` 등)으로 그대로 호출할 수 있어 **애플리케이션 코드를 바꾸지 않아도** 됩니다.
- ⚠️⚠️ **기본 엔드포인트 정책은 그 엔드포인트를 통한 Bedrock 전체 접근을 허용**합니다. VPC에서 나가는 접근을 좁히려면 **사용자 지정 엔드포인트 정책**을 붙이고 **주체 · 작업 · 리소스**를 적습니다 — 엔드포인트를 만든 것만으로 권한이 좁아지지 않습니다.

**② 보안 데이터 액세스 패턴 — IAM**

- Bedrock은 **기본적으로 사용자·역할에 권한이 없습니다.** 공식 모범 사례는 **관리형 정책으로 시작해 최소 권한으로 이동**하고 **조건으로 더 제한**하고 **IAM Access Analyzer로 검증**(100개 이상의 검사)하며 **MFA를 요구**하는 것입니다.
- ⚠️ **콘솔에는 최소 권한 집합이 필요**하고 그보다 제한적이면 콘솔이 의도대로 동작하지 않습니다. ⭐ 반대로 **CLI·API만 부르는 서비스 계정에는 콘솔 권한이 필요 없습니다** — 추론 전용 역할을 만들 때 정책이 그만큼 작아집니다.
- 공식 예제 묶음이 설계의 출발점입니다 — **파운데이션 모델 추론 거부** · **프로비저닝된 모델 호출 허용** · **Playground 채팅 최소 정책**.

**③ 세분화된 데이터 액세스 — Lake Formation**

- Lake Formation은 S3의 데이터 레이크 데이터와 **Glue Data Catalog의 메타데이터**에 **세분화된 액세스 제어**를 제공합니다.
- ⭐⭐ 구조가 비자명합니다 — **IAM 권한 모델을 증강하는 자체 권한 모델**이고 **부여·취소(grant·revoke) 메커니즘**이 관계형 DBMS와 비슷합니다. 즉 IAM을 대체하는 것이 아니라 **그 위에 한 겹**입니다.
- 제어 단위가 **열·행·셀 수준**이고 **Athena · Redshift Spectrum · EMR · Glue** 등 분석·ML 서비스에 걸쳐 적용됩니다. 외부 데이터 소스(Redshift 데이터 웨어하우스·DynamoDB·3자)까지 닿습니다.
- **하이브리드 액세스 모드**는 Lake Formation 권한과 **S3·Glue 작업의 IAM 권한을 함께** 쓰게 해 ⭐ **한 용례씩 선택적·점진적으로 도입**할 수 있게 합니다 — 전면 전환을 요구하지 않는 것이 도입 설계의 핵심입니다.
- 기능 목록에 **태그 기반 액세스 제어(TBAC)** · **속성 기반 액세스 제어** · **행·셀 수준 보안** · **감사 로깅** · **교차 계정 액세스**가 있습니다.
- ⚠️⚠️ **`Governed Tables in AWS Lake Formation`은 완전 종료**됐습니다(AWS Lifecycle Changes 전체 종료 목록). 「세분화된 액세스」를 설계할 때 그 기능을 고르면 안 되고, 현행 수단은 **TBAC · 행·셀 수준 보안 · 하이브리드 액세스 모드**입니다. ⭐ Lake Formation **본체는 정상**이므로 서비스 전체를 피할 이유는 없습니다.

**④ 지켜보는 눈 — 로깅**

- 공식 데이터 보호 권고가 **CloudTrail로 API·사용자 활동 로깅**을 설정하라고 적습니다. ⚠️ 그리고 ⭐⭐ **태그나 `Name` 같은 자유 형식 텍스트 필드에 기밀·민감 정보를 넣지 말라**고 명시합니다 — **그 데이터가 청구 또는 진단 로그에 쓰일 수 있기** 때문입니다. 외부 서버 URL에 **자격 증명을 넣지 말라**는 권고도 같은 절에 있습니다.
- ⚠️ 가드레일이 차단한 콘텐츠는 **모델 호출 로그를 켜 뒀다면 평문으로** 나타납니다(작업 3.1) — 모니터링을 늘리는 것이 **프라이버시 노출을 늘리는** 방향으로 작동하는 자리입니다.
- ⭐ 공식이 적는 플랫폼 쪽 사실 하나: Bedrock에는 **모델 배포 계정**이 있어 리전마다 **모델 공급자당 하나**씩 Bedrock 서비스 팀이 소유·운영하고, **모델 공급자는 그 계정에 접근할 수 없어 Bedrock 로그나 고객 프롬프트·완성에 접근할 수 없습니다.**

### 2) 민감 정보 보호 (기술 3.2.2) {#privacy}

> 🧠 원리: 「민감 정보 보호」는 **탐지 지점**으로 갈립니다 — 상호 작용이 일어나는 순간(Guardrails) · 텍스트를 분석할 때(Comprehend) · 이미 **저장된** 데이터(Macie). 셋은 경쟁이 아니라 **서로 못 보는 곳을 덮습니다.**

| 수단 | 보는 곳 | 핵심 성질 |
|---|---|---|
| **Guardrails 민감 정보 필터** | 입력 프롬프트와 모델 응답 | **차단 또는 마스킹**. 내장 PII + **사용자 지정 정규식** |
| **Comprehend PII 탐지** | 임의의 텍스트 문서 | 유형 + **문자 오프셋**과 점수. ⚠️ **영어·스페인어** |
| **Macie** | **S3에 저장된** 객체 | **ML·패턴 매칭**으로 발견하고 **조사 결과(finding)**를 낸다 |

**Guardrails 민감 정보 필터**는 **확률적 ML 기반이고 문맥 의존적**입니다 — 패턴만 보는 것이 아니라 프롬프트·응답의 문맥에서 민감 정보를 판정합니다. 모드가 둘입니다:

- **Block** — 민감 정보가 있으면 **전체 콘텐츠를 차단**하고 구성한 메시지를 돌려줍니다. 공식 용례가 「공개 문서 기반 일반 질의응답」입니다.
- **Mask** — **익명화·수정**해 **PII 유형으로 치환**합니다(예: `{NAME}`·`{EMAIL}`). 공식 용례가 「고객-상담원 대화 기록을 요약하면서 개인 정보를 가리기」입니다.
- ⭐ **자연어와 코드 도메인 양쪽**에서 동작해 **변수 이름 · 하드코딩된 자격 증명 · 코드 문서**에 박힌 PII까지 봅니다.
- ⚠️⚠️ **텍스트 콘텐츠만 평가**하므로 도구 사용 경로(`toolUse.input`·`toolResult`·`toolSpec`)의 PII는 **차단도 마스킹도 되지 않습니다**(작업 3.1과 같은 경계).

**Comprehend PII 탐지**는 텍스트를 분석해 **유형 · 점수 · 시작·끝 문자 오프셋**을 돌려줍니다. ⚠️ **영어 또는 스페인어** 문서만이고, 실시간 단일 문서는 **최대 100KB UTF-8**이며 **수정(redact)은 비동기 배치 작업**입니다. ⭐ 보편 유형에 **`AWS_ACCESS_KEY`·`AWS_SECRET_KEY`**가 있어 자격 증명 유출 탐지에도 쓰이고, 국가별 유형이 따로 있습니다.

**Macie**는 **S3 데이터 보안**입니다.

- **S3 범용 버킷 인벤토리**를 주고 보안·액세스 제어를 **자동 평가·모니터링**합니다 — 버킷이 **공개 접근 가능해지는** 등 문제가 생기면 **조사 결과**를 냅니다.
- 민감 데이터 발견이 **두 방식**입니다 — **자동 민감 데이터 발견**(인벤토리를 계속 평가하고 **샘플링**으로 대표 객체를 골라 분석 → **넓은 가시성**)과 **민감 데이터 발견 작업**(버킷·샘플링 깊이·사용자 지정 기준을 내가 정하는 **더 깊고 표적화된 분석**, **한 번 또는 반복**).
- 탐지는 **관리형 데이터 식별자**(ML·패턴 매칭의 내장 기준)와 **사용자 지정 기준**, 또는 둘의 조합으로 합니다.
- **EventBridge와 Security Hub CSPM 통합**으로 조사 결과를 다른 서비스에서 처리·수정할 수 있습니다.

**Bedrock 네이티브 데이터 프라이버시 기능 — 데이터 보존**이 이 기술에서 가장 비자명한 자리입니다.

- 프롬프트와 출력을 **남길지 명시적으로 통제**하고 **계정 수준 또는 프로젝트 수준**으로 구성하며 설정이 **Messages · Chat Completions · Responses API에 일관되게** 적용됩니다.
- ⚠️⚠️ **리전별 설정이고 다른 리전으로 전파되지 않습니다.** 구성하지 않은 리전은 **`inherit`** 상태로 남아 **각 모델의 기본값으로 폴백**합니다 — 한 리전에서 ZDR을 켠 것이 다른 리전을 보호하지 않습니다.
- 모드 넷:

| 모드 | 동작 |
|---|---|
| **`none`** | **제로 데이터 보존**. 요청·응답 데이터가 **내구성 스토리지에 쓰이지 않고** 모델 공급자와 공유되지 않는다. Responses API에서 `store`는 **기본 `false`이고 `store=true`는 거부**되며 백그라운드 모드를 쓸 수 없다 |
| **`default`** | **모델의 보존 정책이 적용**된다. **AWS가 안전·남용 방지 목적으로 보존할 수 있고 모델 공급자는 받지 않는다** |
| **`aws_review`** | 입출력이 **AWS 경계 안에서 사람 검토**를 받을 수 있다. **모델 공급자는 검토하지 않고 콘텐츠가 공유되지 않는다**. 일부 공급자가 **모델 접근 조건으로 요구**해 이 모드가 필요하다 |
| **`provider_data_share`**(레거시) | ⚠️ **오늘 Bedrock은 모델 공급자와 콘텐츠를 공유하지 않는다** — 이 모드를 설정해도 공유되지 않는다. 새 구성은 **`aws_review`**를 쓰고, 이미 설정돼 있으면 바꿀 필요가 없다 |

- ⚠️⚠️ **보존 설정이 요청을 차단할 수 있습니다** — 계정이나 프로젝트가 **`none`**인데 **보존을 요구하는 모델**을 호출하면 Bedrock이 **요청을 차단하고 오류를 반환**합니다. 「ZDR을 켰는데 특정 모델이 안 된다」는 설정 충돌이 아니라 **설계된 동작**입니다.
- ⚠️⚠️ **`store=false`가 제로 보존을 보장하지 않습니다.** 공식 Note가 일부 모델이 **안전 검토를 위해 여전히 보존**하되 그 데이터는 **고객이 `GET /v1/responses/{id}`로 가져올 수 없다**고 적습니다 — 보장이 필요하면 **`data_retention_mode`를 `none`**으로 둡니다.
- **남용 탐지**가 보존의 다른 축입니다. Bedrock은 **제로 운영자 접근(ZOA) 데이터 보안 모델**을 쓰되 **모델별 남용·CSAM 탐지는 예외**입니다.
  - 일부 모델은 **분류기가 플래그한 트래픽**을, 일부는 **전 트래픽**을 자동 오프라인 남용 탐지를 위해 보존하고 플래그된 트래픽은 **AWS의 사람 검토** 대상이 될 수 있습니다. ⚠️ 어느 모델이 어디에 해당하는지는 바뀌므로 **모델 목록을 외우지 않고** 공식 남용 탐지 페이지를 봅니다.
  - ⚠️ **보존된 입출력은 AWS가 저장·처리하고 3자 모델 공급자와 공유되지 않습니다.**
  - ⚠️⚠️ **크로스 리전 추론이 켜져 있으면 보존된 입출력이 목적지 리전(요청이 처리된 리전)에 저장**됩니다 — 데이터 거주 요건이 있으면 크로스 리전 추론과 정면으로 부딪히는 자리입니다.
  - **CSAM**은 별 취급입니다 — 이미지 입출력에서 명백한 CSAM을 탐지하면 **요청을 차단하고 `ValidationException`(HTTP 400)**을 반환하며, 플래그된 입출력을 **저장·검토**해 판정하고 **NCMEC나 관계 당국에 신고**할 수 있습니다.
  - ⚠️ 위반 가능성이 확인되면 AWS가 **계정에 연결된 이메일로 정보를 요청**하므로 **연락처를 최신으로 유지**해야 하고, 미응답·미준수 시 **모델이나 Bedrock 접근이 정지될 수 있습니다.**

**데이터 보존 정책 — S3 수명 주기**는 저장된 산출물 쪽을 맡습니다.

- 작업이 둘입니다 — **전환**(더 싼 스토리지 클래스로)과 **만료**(S3가 대신 삭제). 규제 보관 기간이 끝난 객체를 만료시키는 것이 공식 용례입니다.
- ⚠️ **수명 주기 구성을 추가하면 기존 객체와 이후 객체 모두에 적용**됩니다 — 30일 만료 규칙을 오늘 넣으면 **30일이 지난 기존 객체가 제거 큐에 들어갑니다.**
- ⚠️⚠️ **범용 버킷에서는 버킷 정책으로 수명 주기의 삭제·전환을 막을 수 없습니다** — 모든 주체에 모든 작업을 거부해도 **수명 주기는 정상 동작합니다.** 보관이 요건이면 수명 주기가 아닌 다른 수단이 필요합니다.
- 과금은 객체가 **수명 주기 작업 대상이 되는 즉시** 바뀌지만 ⚠️ **S3 Intelligent-Tiering 전환은 실제 전환된 뒤에** 바뀝니다. **전환에 데이터 검색 요금은 없지만 요청당 수집 요금**이 있고, 만료 비용은 **최소 저장 기간이 있는 클래스**에서만 발생합니다.

### 3) 프라이버시 중심의 AI 시스템 (기술 3.2.3) {#masking}

> 🧠 원리: 이 기술은 3.2.2와 **같은 도구로 다른 목표**를 봅니다. 3.2.2는 「막는다」이고 3.2.3은 **「막으면서도 쓸 수 있게 한다」**입니다 — 그래서 **차단이 아니라 마스킹·익명화**가 중심이고, 유용성을 얼마나 지키는지가 설계 기준이 됩니다.

- **차단과 마스킹의 선택이 곧 유용성 결정**입니다. 민감 정보가 든 요약 요청을 **Block**으로 두면 요약 자체가 사라지고, **Mask**로 두면 **`{NAME}`·`{EMAIL}` 같은 유형 라벨로 치환**된 요약을 받습니다. 공식이 Mask의 용례로 드는 것이 바로 **「고객-상담원 대화 기록 요약」**입니다.
- ⚠️ 마스킹은 **지우는 것이 아니라 치환**입니다 — 유형 라벨이 남으므로 하류 모델·사람이 **「여기에 이름이 있었다」**는 구조는 계속 읽을 수 있습니다. 그것이 유용성을 지키는 이유이자, **재식별 위험을 0으로 만들지는 않는 이유**입니다.
- **사용자 지정 정규식**이 조직 고유 식별자(사번·계약 번호·내부 ID)를 덮습니다. 내장 PII 목록은 **일반·금융 등 범주**로 나뉘어 있고, ⚠️ 정의를 알아야 오탐·미탐을 판단할 수 있습니다 — 예를 들어 **`AGE`는 「40 years」처럼 수량과 시간 단위를 포함**하고, **`NAME`은 Dr.·Mr. 같은 직함을 포함하지 않으며** 조직·주소의 일부인 이름에는 적용되지 않습니다(공식 예: 「John Doe Organization」은 조직, 「Jane Doe Street」은 주소).
- **익명화 전략을 어디서 적용하는지**가 두 번째 결정입니다. **상호 작용 시점**이면 Guardrails가, **저장 전 전처리**면 Comprehend의 **비동기 수정 작업**이 맞습니다(⚠️ Comprehend 수정은 **배치만**이고 **영어·스페인어**입니다). 저장된 데이터에서 **어디에 무엇이 있는지 먼저 알아야** 하면 **Macie**입니다.
- ⚠️ 세 수단을 겹칠 때 **중복 비용**을 봅니다 — Guardrails 쪽은 `ApplyGuardrail` 응답의 **정책별 단위 수**(`sensitiveInformationPolicyUnits`와 **무료 단위**가 따로 집계됩니다)로 민감 정보 정책이 얼마나 쓰이는지 측정할 수 있습니다.
- ⚠️ 그리고 **프라이버시 설계가 로깅과 충돌**합니다 — 마스킹을 켜도 **가드레일이 차단한 콘텐츠는 호출 로그에 평문으로** 남을 수 있고, **태그·`Name` 자유 형식 필드에 넣은 값은 청구·진단 로그에 쓰일 수 있습니다.** 「어디에 남는가」를 함께 설계해야 프라이버시 통제가 실제로 성립합니다.

## ✍️ 시험 포인트

- 「인터넷을 거치지 않고 Bedrock을 부른다」면 **인터페이스 VPC 엔드포인트(PrivateLink)**이고 **퍼블릭 IP가 필요 없습니다**.
- 「엔드포인트를 만들었는데 접근이 좁아지지 않았다」면 **기본 정책이 전체 허용**이기 때문입니다.
- 「추론만 허용하고 에이전트 빌드는 막아라」면 **접미사별 엔드포인트 선택**이 통제 수단입니다.
- 「열·행·셀 단위로 데이터 접근을 가른다」면 **Lake Formation**이고 **IAM을 증강하는 별 권한 모델**입니다.
- 「Governed Tables로 세분화 액세스를 설계하자」는 **완전 종료**된 기능입니다.
- 「프롬프트를 절대 남기지 말라」면 **보존 모드 `none`**이고, **리전마다** 설정해야 합니다.
- 「ZDR을 켰는데 이 모델만 오류가 난다」면 **보존을 요구하는 모델을 차단한 것**입니다.
- 「`store=false`면 안 남는다」는 **보장되지 않습니다.**
- 「크로스 리전 추론을 켰다」면 보존된 입출력이 **목적지 리전**에 저장됩니다.
- 「이미 S3에 쌓인 데이터에서 PII를 찾아라」면 **Macie**이고, 「대화 중에 가려라」면 **Guardrails**, 「문서 텍스트에서 위치를 찾아라」면 **Comprehend**입니다.
- 「요약은 받고 싶지만 이름은 가려라」면 Guardrails의 **Mask**이고 **`{NAME}`으로 치환**됩니다.
- 「버킷 정책으로 수명 주기 삭제를 막자」는 **불가능**합니다.
- 「태그에 고객 이메일을 넣어 추적하자」는 **청구·진단 로그에 쓰일 수 있어** 공식이 금지합니다.

## ⚠️ 흔한 함정 {#pitfalls}

- ⚠️⚠️ **VPC 엔드포인트를 만들면 권한이 좁아진다고 생각하기.** **기본 정책이 전체 허용**입니다.
- ⚠️ **FIPS 엔드포인트가 모든 리전에 있다고 가정하기.** **일부 리전**입니다.
- ⚠️ **Lake Formation이 IAM을 대체한다고 생각하기.** **증강**하는 별 모델입니다.
- ⚠️⚠️ **`Governed Tables`를 현행 수단으로 고르기.** **완전 종료**됐습니다.
- ⚠️⚠️ **보존 설정이 전 리전에 적용된다고 생각하기.** **리전별**이고 나머지는 **`inherit`**입니다.
- ⚠️⚠️ **`none`이면 모든 모델을 그대로 쓸 수 있다고 생각하기.** 보존을 요구하는 모델은 **차단**됩니다.
- ⚠️⚠️ **`store=false`를 ZDR로 믿기.** 보장되지 않습니다.
- ⚠️ **`provider_data_share`가 공급자와 공유한다고 생각하기.** **오늘은 공유하지 않습니다**(레거시).
- ⚠️⚠️ **크로스 리전 추론과 데이터 거주 요건을 함께 두기.** 보존분이 **목적지 리전**에 저장됩니다.
- ⚠️ **Guardrails로 S3에 저장된 데이터를 스캔하려 하기.** 그것은 **Macie**입니다.
- ⚠️ **Macie로 실시간 프롬프트를 막으려 하기.** Macie는 **S3 저장 데이터**를 봅니다.
- ⚠️ **Comprehend PII로 한국어를 처리하거나 실시간 수정을 기대하기.** **영어·스페인어**이고 수정은 **배치**입니다.
- ⚠️ **마스킹을 완전한 비식별로 생각하기.** **유형 라벨로 치환**하는 것입니다.
- ⚠️⚠️ **버킷 정책으로 수명 주기를 막으려 하기.** **정상 동작**합니다.
- ⚠️ **수명 주기 규칙이 새 객체에만 적용된다고 생각하기.** **기존 객체에도** 적용됩니다.
- ⚠️ **모니터링을 늘리는 것이 항상 안전하다고 생각하기.** 차단 콘텐츠가 **로그에 평문**으로 남습니다.

**Q1.** 금융사가 「프롬프트가 AWS 어디에도 남지 않게」를 요건으로 걸었습니다. 무엇을 설정하고, 설정 뒤 생길 수 있는 운영 변화는 무엇입니까?

<details><summary>정답 보기</summary>

**데이터 보존 모드를 `none`**(제로 데이터 보존)으로 설정합니다 — 요청·응답 데이터가 **내구성 스토리지에 쓰이지 않고** 모델 공급자와 공유되지 않습니다. ⚠️⚠️ 운영 변화 둘: ① **보존을 요구하는 모델을 호출하면 Bedrock이 요청을 차단하고 오류를 반환**합니다 ② Responses API에서 **`store`가 기본 `false`가 되고 `store=true`가 거부**되며 **백그라운드 모드를 쓸 수 없습니다.** ⚠️ 그리고 설정은 **리전별**이라 쓰는 리전마다 해야 합니다(구성하지 않은 리전은 **`inherit`**).
</details>

**Q2.** 개발자가 「Responses API에서 `store=false`로 보내니 제로 보존입니다」라고 보고합니다. 맞습니까?

<details><summary>정답 보기</summary>

틀렸습니다. ⚠️⚠️ 공식 Note가 **`store=false`가 제로 데이터 보존을 보장하지 않는다**고 적습니다 — 일부 모델은 **안전 검토를 위해 여전히 보존**하고, 그 데이터는 **고객이 `GET /v1/responses/{id}`로 가져올 수 없는** 상태로 남습니다. **보장이 필요하면 `data_retention_mode`를 `none`**으로 둡니다. `store`는 **`default` 모드에서 기본 `true`**이고 양쪽 값을 설정할 수 있습니다.
</details>

**Q3.** EU 데이터가 리전을 벗어나면 안 되는 워크로드에서 처리량을 위해 크로스 리전 추론을 켜려 합니다. 무엇을 확인해야 합니까?

<details><summary>정답 보기</summary>

⚠️⚠️ **남용 탐지로 보존되는 입출력이 목적지 리전(요청이 처리된 리전)에 저장**된다는 것입니다 — 크로스 리전 추론을 켜면 데이터가 **구성한 리전을 벗어난 곳에 남을 수 있습니다.** 보존 자체를 막으려면 **모드 `none`**이 필요하고, 그러면 **보존을 요구하는 모델이 차단**됩니다. ⭐ 보존된 데이터는 **AWS가 저장·처리하고 3자 모델 공급자와 공유되지 않으며**, Bedrock은 모델별 남용·CSAM 탐지를 제외하면 **제로 운영자 접근(ZOA)** 모델을 씁니다.
</details>

**Q4.** 세 요구가 동시에 들어왔습니다 — ① 대화 중 주민 식별 번호를 가려라 ② 사내 문서에서 PII 위치를 뽑아라 ③ S3에 이미 쌓인 로그에 PII가 있는지 알아라. 각각 무엇을 씁니까?

<details><summary>정답 보기</summary>

① **Guardrails 민감 정보 필터**의 **Mask**(유형 라벨로 치환 · 사용자 지정 정규식으로 조직 고유 식별자) ② **Comprehend PII 탐지**(유형·점수와 **시작·끝 문자 오프셋**. ⚠️ **영어·스페인어** · 실시간은 **최대 100KB** · **수정은 비동기 배치**) ③ **Macie**(S3 범용 버킷 인벤토리 + **자동 민감 데이터 발견** 또는 **발견 작업** · **관리형 데이터 식별자**). ⚠️ Guardrails는 **텍스트만** 보므로 도구 사용 경로의 PII는 다루지 못합니다.
</details>

**Q5.** 데이터 레이크에서 분석 팀마다 다른 열만 보게 하려 합니다. Lake Formation이 IAM과 어떤 관계이고, 고르면 안 되는 기능은 무엇입니까?

<details><summary>정답 보기</summary>

Lake Formation은 **IAM 권한 모델을 증강하는 자체 권한 모델**이고(대체가 아닙니다) **부여·취소 메커니즘**이 RDBMS와 비슷합니다. **열·행·셀 수준** 제어가 Athena·Redshift Spectrum·EMR·Glue 등에 걸쳐 적용되고, **하이브리드 액세스 모드**로 IAM 권한과 함께 쓰며 **한 용례씩 점진적으로** 도입할 수 있습니다. ⚠️⚠️ 고르면 안 되는 것은 **`Governed Tables`**로, **완전 종료**됐습니다 — 현행 수단은 **TBAC·행·셀 수준 보안·하이브리드 모드**입니다.
</details>

**Q6.** 규제 보관 기간이 끝난 프롬프트 로그를 자동 삭제하려 S3 수명 주기를 쓰고, 동시에 「누구도 지우지 못하게」 버킷 정책으로 삭제를 거부했습니다. 어떻게 됩니까?

<details><summary>정답 보기</summary>

⚠️⚠️ **수명 주기는 정상 동작해 삭제합니다.** 공식 Important가 범용 버킷에서 **버킷 정책으로 S3 수명 주기 규칙의 삭제·전환을 막을 수 없다**고 적습니다 — **모든 주체에 모든 작업을 거부해도** 그렇습니다. 그리고 ⚠️ **수명 주기 구성은 기존 객체에도 적용**되므로 규칙을 넣는 순간 **이미 기간이 지난 객체가 제거 큐에 들어갑니다.**
</details>

**Q7.** 보안 팀이 「추적을 위해 리소스 태그에 담당자 이메일을 넣자」고 제안합니다. 공식 권고는 무엇입니까?

<details><summary>정답 보기</summary>

**넣지 않습니다.** 공식 데이터 보호 절이 **태그나 `Name` 같은 자유 형식 텍스트 필드에 기밀·민감 정보를 넣지 말라**고 강하게 권고하고, 이유로 **그 데이터가 청구 또는 진단 로그에 쓰일 수 있다**는 것을 적습니다(콘솔·API·CLI·SDK 어디서든). 같은 절이 **외부 서버 URL에 자격 증명을 넣지 말라**고도 적습니다. 추적이 필요하면 **CloudTrail로 API·사용자 활동 로깅**을 설정하는 쪽이 공식 권고입니다.
</details>
