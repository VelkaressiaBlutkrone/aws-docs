## 📖 핵심 개념

### 1) 앱 통합 메시징 — SNS · SQS · EventBridge (★ 시험 핵심)

느슨하게 결합된(decoupled) 시스템을 잇는 세 가지 메시징/이벤트 서비스입니다.

| 서비스 | 한 줄 역할 | 전달 방식 | 떠올릴 키워드 |
|---|---|---|---|
| **Amazon SNS** | **pub/sub 알림** — 발행자가 *주제(topic)*에 보내면 여러 구독자에게 **푸시** | 하나 발행 → **여러 구독자에 복제 푸시(팬아웃)** | "*알림*", "SMS/이메일 발송", "여러 대상에 동시 전달" |
| **Amazon SQS** | **메시지 큐** — 컴포넌트를 디커플링하고 메시지를 큐에 보관 | 큐에 저장 → 소비자가 **폴링(pull)해 처리** | "*큐*", "컴포넌트 *디커플링*", "비동기 작업 버퍼" |
| **Amazon EventBridge** | **서버리스 이벤트 버스** — 이벤트를 *규칙*으로 소스→타겟 라우팅 | 이벤트 소스 → 규칙 → 타겟 | "*이벤트 버스*", "이벤트 기반", "여러 소스의 이벤트 라우팅" |

> **SNS vs SQS** (단골 비교):
> - **SNS = 발행/구독(pub/sub), 푸시.** 한 메시지를 *여러 구독자*에게 동시에 보냄(알림·팬아웃).
> - **SQS = 큐, 풀.** 메시지를 큐에 쌓아 두고 *소비자가 가져가* 처리(보통 한 소비자가 한 메시지 처리). 컴포넌트 디커플링·부하 평준화.
> - 자주 **함께** 씀: SNS 주제 → 여러 SQS 큐로 팬아웃(SNS가 뿌리고 각 SQS가 안전하게 버퍼링).

> **EventBridge**는 *이벤트 기반* 아키텍처용 — AWS 서비스·자체 앱·서드파티의 이벤트를 받아 규칙으로 여러 타겟에 라우팅합니다("이벤트 버스").

### 2) 최종 사용자 컴퓨팅 — Amazon WorkSpaces

**Amazon WorkSpaces**는 사용자에게 **가상의 클라우드 기반 데스크톱(DaaS, Desktop as a Service)**을 프로비저닝합니다.

- Windows·Linux 데스크톱을 클라우드에서 제공 — **하드웨어 조달·복잡한 SW 설치 불필요.**
- 사용자는 **여러 기기·웹 브라우저에서 어디서나** 자기 데스크톱에 접근. 사용자 추가·제거가 빠름.

> 시험 신호: **"관리형 가상 데스크톱 / 클라우드 데스크톱 / 어디서나 접근하는 사내 PC 환경"** → WorkSpaces.

### 3) IoT — AWS IoT Core

**AWS IoT Core**는 **IoT 기기를 AWS 클라우드 서비스 및 다른 기기에 연결**하는 관리형 서비스입니다.

- 기기가 안전하게 클라우드와 **메시지를 주고받음**(MQTT·HTTPS 등 프로토콜, 메시지 브로커 pub/sub).
- 센서·스마트 기기 등 대규모 IoT 기기를 연결·관리.

> 시험 신호: **"IoT 기기를 클라우드에 연결 / 기기 메시징"** → IoT Core.

### 4) 그 외 범위 내 서비스 — 위치만 알아 두기

CLF는 아래 묶음도 *대략 어디에 속하는지*를 묻습니다(깊은 지식 불필요).

| 묶음 | 대표 서비스(예) |
|---|---|
| **비즈니스 앱** | Amazon Connect(콜센터), Amazon SES(이메일 발송) |
| **개발자 도구** | CloudShell(브라우저 셸), Cloud9(IDE), CodeCommit/Build/Deploy/Pipeline, X-Ray(분산 추적) |
| **프런트엔드·모바일** | AWS Amplify, AWS AppSync |
| **고객 지원** | AWS Support, AWS IQ, AWS Managed Services(AMS) |

> 이 표는 *식별용 참고*입니다 — 시험은 "이 서비스가 어느 범주인가" 정도를 묻습니다.

### SQS 큐 유형 — 표준 vs FIFO (보강)

- **표준 큐(Standard)**: 거의 무제한 처리량, **최선 순서(best-effort ordering)**, **최소 한 번(at-least-once) 전달** — 메시지가 가끔 중복되거나 순서가 뒤바뀔 수 있습니다.
- **FIFO 큐**: **순서 보장(First-In-First-Out)** + **정확히 한 번(exactly-once) 처리**. 주문 처리처럼 순서와 중복 제거가 중요한 워크로드에 적합합니다.

> 시험 신호: "순서·정확히 한 번" → **FIFO**, "최대 처리량·순서 무관" → **표준**.
> 출처: [Amazon SQS](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/welcome.html)

## ✍️ 시험 포인트

- **SNS = 알림(pub/sub, 여러 구독자에 푸시, SMS·이메일).** **SQS = 메시지 큐(디커플링, 소비자가 폴링).** **EventBridge = 서버리스 이벤트 버스(이벤트 라우팅).**
- **SNS vs SQS**: 한 메시지를 *여러 곳에 동시에* = SNS. *큐에 쌓아 두고 처리* = SQS.
- **WorkSpaces = 관리형 가상 데스크톱(DaaS).**
- **IoT Core = IoT 기기를 클라우드에 연결·메시징.**
- 비즈니스 앱 Connect(콜센터)·SES(이메일), 개발 도구 X-Ray(추적)·CloudShell 등은 *범주만* 매칭.

---

## ⚠️ 흔한 함정

1. **"SNS와 SQS는 같은 것이다."** → ❌. **SNS = pub/sub 푸시(여러 구독자 동시)**, **SQS = 큐(소비자가 폴링)**. 모델이 다릅니다.
2. **"이메일·SMS 알림을 SQS로 보낸다."** → ❌. 다중 대상 *알림*은 **SNS**(SMS·이메일 등 엔드포인트). SQS는 *큐*.
3. **"컴포넌트를 느슨하게 결합(디커플링)하려면 SNS만 쓴다."** → ⚠️ 보통 **SQS**(큐로 버퍼링)나 SNS+SQS 조합. SQS가 디커플링의 대표.
4. **"WorkSpaces는 서버용 가상 머신(EC2)이다."** → ❌. WorkSpaces는 *최종 사용자용 가상 **데스크톱***(DaaS). 서버 컴퓨팅은 EC2.
5. **"IoT 기기 연결도 그냥 EC2로 한다."** → ⚠️ IoT 기기의 안전한 연결·메시징 관리는 **IoT Core**가 전용으로 제공.
6. **"X-Ray는 보안 서비스다."** → ❌. **X-Ray는 분산 애플리케이션 추적(디버깅)** 개발자 도구입니다.

## 🧪 자가 점검

> 아래는 학습용 자가 점검입니다. (정식 검증 문항은 `t3-8.questions.json` 참조)

**Q1.** 하나의 이벤트(예: 주문 생성)를 여러 구독자(이메일·여러 SQS 큐·Lambda)에게 동시에 푸시 알림으로 보내려면 어떤 서비스인가요?

<details><summary>정답 보기</summary>

**Amazon SNS**(pub/sub 메시징). 주제(topic)에 발행하면 여러 구독자 엔드포인트(SQS·Lambda·이메일·SMS 등)로 메시지를 복제해 푸시합니다(팬아웃).
</details>

**Q2.** 마이크로서비스 컴포넌트들을 느슨하게 결합(디커플링)하기 위해, 메시지를 큐에 보관하고 소비자가 가져가 처리하게 하려면?

<details><summary>정답 보기</summary>

**Amazon SQS**(메시지 큐). 메시지를 큐에 안전하게 저장하고 소비자가 폴링해 처리하므로, 생산자·소비자를 분리(디커플링)하고 부하를 평준화합니다.
</details>

**Q3.** 사용자에게 클라우드 기반 가상 데스크톱(Windows/Linux)을 제공해 어디서나 접근하게 하려면? 그리고 IoT 기기를 안전하게 클라우드에 연결하려면?

<details><summary>정답 보기</summary>

가상 데스크톱은 **Amazon WorkSpaces**(DaaS), IoT 기기 연결은 **AWS IoT Core**입니다.
</details>

**Q4.** SNS와 SQS의 핵심 차이를 한 문장으로?

<details><summary>정답 보기</summary>

**SNS**는 발행/구독(pub/sub)으로 한 메시지를 *여러 구독자에게 동시에 푸시*하고, **SQS**는 메시지를 *큐에 쌓아 두고 소비자가 폴링해 처리*합니다(컴포넌트 디커플링).
</details>
