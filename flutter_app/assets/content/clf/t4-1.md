# 요금 모델 (구매 옵션·데이터 전송·스토리지)

## 🎯 왜 중요한가

- 도메인 4(12%)에서 이 Task는 **"비용을 어떻게 낮추는가"**의 컴퓨팅 편입니다. 시험은 *워크로드 특성 → 적합한 구매 옵션*을 고르게 합니다.
- 핵심 4가지만 확실하면 됩니다: **On-Demand(자유·정가)**, **Savings Plans/Reserved(약정·할인)**, **Spot(미사용·최대 할인·중단)**, **Dedicated Hosts(전용·BYOL)**.

## 📖 핵심 개념

### 1) EC2 컴퓨팅 구매 옵션 (★ 시험 핵심)

| 옵션 | 약정 | 할인 | 언제 쓰나 |
|---|---|---|---|
| **On-Demand** | 없음 | 없음(정가) | 단기·예측 불가, 테스트/개발, 처음 시작 |
| **Savings Plans** | 1년 또는 3년, **시간당 일정 사용량($/h)** 약정 | **최대 72%** | 꾸준한 사용량. **EC2·Fargate·Lambda에 유연**(인스턴스 패밀리·크기·OS·리전 무관) |
| **Reserved Instances(RI)** | 1년 또는 3년, **특정 인스턴스 구성** 약정 | 큼 | 안정적·예측 가능한 정상 상태 워크로드 |
| **Spot Instances** | 없음(AWS **미사용 용량**) | **최대 90%** | **중단을 견디는** 워크로드(배치·내결함성·스테이트리스) |
| **Dedicated Hosts** | - | - | **전용 물리 서버** 필요(컴플라이언스, **기존 라이선스 BYOL**) |
| **Capacity Reservations** | - | - | 특정 AZ에 **용량을 미리 예약**(필요 시점 확보) |

> 시험 신호:
> - "예측 불가·단기·테스트" → **On-Demand**
> - "1~3년 꾸준히 쓸 것, 유연하게 할인" → **Savings Plans** (특정 구성 고정이면 **RI**)
> - "중단돼도 괜찮은 대량 배치, 가장 싸게" → **Spot**
> - "물리적으로 전용 서버 + 기존 라이선스" → **Dedicated Hosts**

> **Savings Plans vs RI:** 둘 다 1/3년 약정 할인. **Savings Plans는 더 유연**(사용량 기반, 인스턴스 패밀리·리전 바꿔도 적용, Fargate·Lambda 포함). **RI는 특정 구성**에 묶이지만 용량 예약 옵션 등 특성이 있음.

### 2) 데이터 전송 요금

- **수신(인바운드, AWS로 들어오는) 데이터**: 일반적으로 **무료**.
- **발신(아웃바운드, 인터넷으로 나가는) 데이터**: **과금**.
- **리전 간(Region 간) 전송**: 과금. 같은 AZ 내 전송은 보통 무료/저렴.

> 기억: **들어오는 건 보통 공짜, 나가는 것·리전을 넘는 것은 돈.** 아키텍처를 *데이터가 적게 나가도록* 설계하면 비용↓.

### 3) 스토리지 계층별 요금 (4.x 스토리지와 연계)

스토리지는 **접근 빈도와 비용의 트레이드오프**로 계층이 나뉩니다(자세한 건 [스토리지 3.6](#)).

- **자주 접근** → 보관 단가↑·검색 빠름·검색 수수료 없음(예: S3 Standard).
- **가끔/거의 안 접근** → 보관 단가↓·검색 수수료/시간↑(예: S3 IA, Glacier).
- **S3 수명 주기**로 시간이 지나며 더 싼 계층으로 자동 전환해 비용 최적화.

## ✍️ 시험 포인트

- **On-Demand**: 약정·선투자 없음, 정가, 자유. 예측 불가·단기.
- **Savings Plans**: 1/3년 사용량 약정, 최대 72%, **EC2·Fargate·Lambda 유연**.
- **Reserved Instances**: 1/3년 특정 구성 약정, 할인.
- **Spot**: 미사용 용량, 최대 90% 할인, **중단 가능**(견디는 워크로드).
- **Dedicated Hosts**: 전용 물리 서버, **BYOL**·컴플라이언스.
- **데이터 전송**: 수신 보통 무료, **발신·리전 간 과금**.
- **스토리지**: 접근 빈도↔비용 계층(Standard↔IA↔Glacier), Lifecycle로 자동 전환.

---

## ⚠️ 흔한 함정

1. **"Spot은 항상 써도 되는 가장 싼 옵션이다."** → ⚠️ Spot은 **AWS가 용량을 회수하면 중단**될 수 있습니다. *중단을 견디는* 워크로드에만.
2. **"Savings Plans와 Reserved Instances는 똑같다."** → ⚠️ 둘 다 약정 할인이지만 **Savings Plans가 더 유연**(사용량 기반, Fargate·Lambda 포함). RI는 특정 구성.
3. **"AWS로 데이터를 올리는 것도 비싸다."** → ❌. **수신(인바운드)은 보통 무료.** *발신·리전 간*이 과금 대상.
4. **"꾸준히 1년 넘게 쓸 워크로드도 On-Demand가 가장 싸다."** → ❌. 꾸준하면 **Savings Plans/RI**로 약정해 크게 절감.
5. **"Dedicated Hosts는 그냥 더 큰 인스턴스다."** → ❌. *전용 물리 서버*로, 컴플라이언스·**기존 라이선스(BYOL)** 활용이 목적.

## 🧪 자가 점검

> 아래는 학습용 자가 점검입니다. (정식 검증 문항은 `t4-1.questions.json` 참조)

**Q1.** 예측이 어려운 단기 테스트 워크로드에는 어떤 구매 옵션이 적합한가요? 그리고 1~3년 꾸준히 쓸 워크로드를 유연하게 할인받으려면?

<details><summary>정답 보기</summary>

예측 불가·단기는 **On-Demand**(약정 없음, 정가). 1~3년 꾸준한 사용량을 유연하게 할인받으려면 **Savings Plans**(시간당 사용량 약정, EC2·Fargate·Lambda에 유연 적용).
</details>

**Q2.** 중단되어도 재시작하면 되는 대량 배치 작업을 가장 저렴하게 처리하려면?

<details><summary>정답 보기</summary>

**Spot Instances**(AWS 미사용 용량, 최대 90% 할인). 단 AWS가 용량을 회수하면 중단될 수 있어 *중단을 견디는* 워크로드에 적합합니다.
</details>

**Q3.** AWS로 데이터를 올릴 때(수신)와 인터넷으로 내보낼 때(발신), 데이터 전송 요금은 어떻게 다른가요?

<details><summary>정답 보기</summary>

**수신(인바운드)은 일반적으로 무료**이고, **발신(아웃바운드)·리전 간 전송은 과금**됩니다. 데이터가 적게 나가도록 설계하면 비용을 줄일 수 있습니다.
</details>

**Q4.** 컴플라이언스 때문에 전용 물리 서버가 필요하고 기존 소프트웨어 라이선스를 재활용(BYOL)하려면 어떤 구매 옵션인가요?

<details><summary>정답 보기</summary>

**Dedicated Hosts**(전용 물리 EC2 서버). 기존 서버 바운드 라이선스를 사용(BYOL)하고 컴플라이언스 요건을 충족할 수 있습니다.
</details>
