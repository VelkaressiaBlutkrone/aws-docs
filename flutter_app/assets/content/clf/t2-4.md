- 이 Task는 도메인 2에서 **"실제로 무엇을 *켜고 두는가*"**에 해당합니다. 시험은 *네트워크 트래픽을 제어*하거나(보안 그룹/NACL), *웹 공격을 막거나*(WAF), *모범 사례 위반을 찾거나*(Trusted Advisor) 하는 상황을 주고 **도구를 고르게** 합니다.

## 📖 핵심 개념

### 1) VPC 네트워크 방화벽 2개 층 — 보안 그룹 vs 네트워크 ACL (★ 시험 핵심)

VPC에는 트래픽을 거르는 두 층이 있습니다. **보안 그룹은 인스턴스 앞에서, 네트워크 ACL은 서브넷 경계에서** 거릅니다.

| 구분 | **보안 그룹(Security Group)** | **네트워크 ACL(Network ACL)** |
|---|---|---|
| 적용 수준 | **인스턴스(리소스)** 수준 — 연결된 리소스의 트래픽 제어 | **서브넷** 수준 — 서브넷에 들고 나는 트래픽 제어 |
| 상태(state) | **Stateful** — 허용된 요청의 *응답은 규칙과 무관하게 자동 허용* | **Stateless** — 응답 트래픽도 *명시적 규칙이 있어야* 허용 |
| 규칙 종류 | **허용(Allow)만** 지정 가능 | **허용(Allow)과 거부(Deny) 둘 다** 지정 가능 |
| 규칙 평가 | 모든 규칙을 종합해 판단 | **번호 순서대로**(낮은 번호부터) 평가, 먼저 일치하는 규칙 적용 |
| 적용 대상 | 연결한 리소스에만 | 그 서브넷의 *모든* 리소스에 자동 |

> 한 문장 기억법:
> - **보안 그룹 = 인스턴스의 경비원, Stateful, "허용 목록"만.** (들여보낸 손님의 답장은 묻지 않고 내보냄)
> - **네트워크 ACL = 서브넷 정문, Stateless, "허용+차단" 목록.** (들어온 트래픽과 나가는 답장을 *각각* 규칙으로 확인)

> 공식 표현: 보안 그룹은 "stateful ... responses are automatically allowed", NACL은 "stateless ... responses to that traffic are not automatically allowed". 그리고 NACL은 "allows or denies specific inbound or outbound traffic at the subnet level."

> 💡 **특정 IP를 *차단*하고 싶다면?** 보안 그룹은 허용만 가능하므로 *차단(deny)* 규칙을 쓸 수 없습니다. **명시적 차단이 필요하면 네트워크 ACL**을 씁니다. (단골 함정)

### 2) AWS WAF — 웹 애플리케이션 방화벽 (애플리케이션 계층)

**AWS WAF(Web Application Firewall)**는 보호 대상 웹 리소스로 가는 **HTTP/HTTPS 요청을 모니터링**하고, 조건에 따라 접근을 제어합니다.

- 막는 것: **SQL 인젝션(SQL injection)**, **크로스 사이트 스크립팅(XSS)** 같은 흔한 *웹 애플리케이션 공격*. (IP·국가·헤더·요청 길이·문자열/정규식 패턴 등으로 규칙 작성)
- 동작 선택: 지정한 요청만 **허용 / 차단(HTTP 403) / 카운트 / CAPTCHA·챌린지**.
- 적용 대상(보호 가능 리소스): **Amazon CloudFront, Application Load Balancer(ALB), Amazon API Gateway REST API, AWS AppSync, Amazon Cognito, App Runner, Verified Access, Amplify**.
- **web ACL(웹 접근 제어 목록)** + 규칙으로 구성. AWS·Marketplace의 관리형 규칙 그룹도 사용 가능.

> **WAF vs Shield vs 보안 그룹/NACL** (자주 헷갈림):
> - **WAF** = *웹 애플리케이션 계층(L7)* 공격(SQLi·XSS·악성 요청) 필터.
> - **[Shield](#)** = *DDoS*(대량 트래픽) 보호. (도메인 2.2 참고: Standard 무료·자동, Advanced 유료)
> - **보안 그룹 / NACL** = *네트워크 계층*에서 IP·포트·프로토콜 단위 트래픽 허용/차단.

### 3) 보안 이슈를 찾아 주는 점검 도구 — AWS Trusted Advisor

**AWS Trusted Advisor**는 수십만 고객을 지원하며 얻은 **모범 사례**를 바탕으로 내 AWS 환경을 **점검(inspect)**하고, 개선 기회가 있을 때 **권고**합니다.

- 점검 영역: **비용 절감, 성능 개선, 보안 격차 해소, 내결함성(가용성), 서비스 한도(quota)** 등 모범 사례 카테고리.
- 보안 측면에서 "위험하게 열린 보안 그룹 포트", "공개된 S3 버킷 권한", "루트 계정 MFA 미설정" 같은 *보안 모범 사례 위반*을 찾아 줍니다.

> ℹ️ 참고: Trusted Advisor의 **전체 점검**은 상위 Support 플랜(Business/Enterprise 급 이상)에서 제공되고, 기본(Basic)·Developer 플랜은 **서비스 한도 전체 + 보안·내결함성 일부**만 제공됩니다. (Support 플랜 자세한 내용은 도메인 4에서.)

> 구분: **Trusted Advisor = "모범 사례대로 돼 있나?" 점검·권고.** (리소스 *구성 이력*은 [Config](#), *취약점 스캔*은 [Inspector](#), *위협 탐지*는 [GuardDuty](#) — 2.2 참고.)

### 4) 서드파티 보안 제품을 구하는 곳 — AWS Marketplace

**AWS Marketplace**는 AWS에서 동작하는 **서드파티 소프트웨어·데이터·서비스**를 찾고, 구매(구독)하고, 배포·관리하는 **큐레이트된 디지털 카탈로그**입니다.

- **보안(security)**은 Marketplace의 대표 카테고리 중 하나입니다 — 방화벽 어플라이언스, 안티바이러스, 침입 탐지 등 **독립 소프트웨어 공급자(ISV)**의 보안 제품을 구할 수 있습니다.
- 형태: **AMI**(머신 이미지), **SaaS**, CloudFormation 템플릿, AWS WAF용 규칙 등.
- 가격: 무료 체험·시간·월·연·다년·**BYOL(Bring Your Own License)** 등 유연. **요금은 AWS 청구서에 합산**(한곳에서 결제)됩니다.

> 시험 신호: **"서드파티/타사 보안 소프트웨어를 찾아 배포"** → AWS Marketplace.

### 5) 보안 정보·문서는 어디서 찾나

AWS는 보안 *도구*뿐 아니라 보안 *정보의 위치*도 알기를 기대합니다.

| 찾는 것 | 위치 |
|---|---|
| 자주 묻는 질문에 대한 **how-to·문제 해결 답변** | **AWS Knowledge Center**(re:Post 내) |
| 최신 **보안 발표·심층 모범 사례·사고 대응 가이드** | **AWS Security Blog** |
| 커뮤니티 **질문·답변**(전 AWS 포럼) | **AWS re:Post** |
| AWS의 **컴플라이언스 보고서**(SOC·PCI·ISO) | **AWS Artifact** (2.2 참고) |
| 심층 기술 백서·**보안 모범 사례 백서** | AWS 백서 페이지 |

### 보안 그룹 기본 동작 (보강)

새로 만든 **보안 그룹**은 **인바운드 규칙이 없어 들어오는 트래픽을 모두 거부**하고, **기본 아웃바운드 규칙으로 나가는 트래픽은 모두 허용**한 상태로 시작합니다. 보안 그룹은 **허용(allow) 규칙만** 지정하며 **stateful**(허용된 요청의 응답은 자동 허용)로 동작합니다. 반면 네트워크 ACL은 허용·거부를 모두 지정하고 stateless입니다.

> 시험 신호: "새 보안 그룹의 기본 인바운드" → 거부(규칙 추가 필요). "허용 규칙만, stateful" → 보안 그룹.
> 출처: [보안 그룹으로 트래픽 제어](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html)

## ✍️ 시험 포인트

- **보안 그룹 = 인스턴스 수준 + Stateful + Allow 전용.** 보기에 "인스턴스 방화벽 / 응답 자동 허용 / 허용 규칙"이면 보안 그룹.
- **네트워크 ACL = 서브넷 수준 + Stateless + Allow와 Deny.** "서브넷 / 특정 IP *차단* / 응답도 규칙 필요"면 NACL.
- **특정 IP를 명시적으로 차단** → 보안 그룹은 불가(허용만), **NACL**로.
- **WAF** = 웹 공격(**SQL 인젝션·XSS**) 필터, *애플리케이션 계층*. **Shield** = DDoS. 헷갈리지 말 것.
- **Trusted Advisor** = AWS 환경을 모범 사례로 점검·권고(비용·성능·보안·내결함성·서비스 한도).
- **AWS Marketplace** = *서드파티(타사)* 보안 소프트웨어를 찾아 구매·배포하는 카탈로그.
- 정보 위치: how-to 답변 = **Knowledge Center**, 보안 글 = **Security Blog**, 커뮤니티 Q&A = **re:Post**.

## ⚠️ 흔한 함정

1. **"보안 그룹으로 특정 악성 IP를 차단한다."** → ❌. 보안 그룹은 **허용(Allow) 규칙만** 가능. *차단(Deny)*은 **네트워크 ACL**로.
2. **"네트워크 ACL은 Stateful이라 응답이 자동 허용된다."** → ❌. NACL은 **Stateless** — 인바운드를 허용해도 *아웃바운드(응답) 규칙을 따로* 둬야 합니다. *Stateful은 보안 그룹.*
3. **"WAF가 DDoS를 막는다."** → ⚠️ 부분적. WAF는 *웹 애플리케이션 공격(SQLi·XSS)* 필터입니다. *대량 트래픽 DDoS*의 1차 방어는 **Shield**(WAF web ACL이 보조 역할은 가능).
4. **"Trusted Advisor가 리소스 구성 변경 이력을 보여 준다."** → ❌. 그건 **AWS Config**. Trusted Advisor는 *모범 사례 점검·권고*.
5. **"보안 소프트웨어는 전부 AWS 콘솔에서 기본 제공된다."** → ❌. *타사 보안 제품*은 **AWS Marketplace**에서 구독해 배포합니다.
6. **"보안 그룹과 NACL은 같은 것이다."** → ❌. **수준(인스턴스 vs 서브넷)·상태(stateful vs stateless)·규칙(allow만 vs allow+deny)**이 다릅니다. 둘은 *함께* 다층 방어를 이룹니다.

## 🧪 자가 점검

> 아래는 학습용 자가 점검입니다. (정식 검증 문항은 `t2-4.questions.json` 참조)

**Q1.** 보안 그룹과 네트워크 ACL은 각각 어느 수준에서 동작하고, 상태(state) 면에서 어떻게 다른가요?

<details><summary>정답 보기</summary>

**보안 그룹**은 **인스턴스(리소스) 수준**에서 동작하고 **Stateful**입니다(허용한 요청의 응답이 자동 허용). **네트워크 ACL**은 **서브넷 수준**에서 동작하고 **Stateless**입니다(응답 트래픽도 별도 규칙 필요).
</details>

**Q2.** 특정 IP 주소를 명시적으로 *차단*하려면 보안 그룹과 네트워크 ACL 중 무엇을 써야 하나요? 그 이유는?

<details><summary>정답 보기</summary>

**네트워크 ACL.** 보안 그룹은 **허용(Allow) 규칙만** 지정할 수 있어 차단을 표현할 수 없습니다. 네트워크 ACL은 **허용과 거부(Deny) 규칙을 모두** 지원하므로 특정 IP를 차단할 수 있습니다.
</details>

**Q3.** 웹 애플리케이션을 SQL 인젝션과 XSS 같은 공격으로부터 보호하려면 어떤 서비스이고, 대량 트래픽 DDoS 보호와는 어떻게 다른가요?

<details><summary>정답 보기</summary>

**AWS WAF**(웹 애플리케이션 방화벽). HTTP/HTTPS 요청을 검사해 SQLi·XSS 같은 *애플리케이션 계층* 공격을 규칙으로 막습니다. *대량 트래픽 DDoS* 보호는 **AWS Shield**입니다.
</details>

**Q4.** 타사(서드파티) 침입 탐지 소프트웨어를 찾아 구매·배포하려면 어디서 하나요? 그리고 내 환경이 보안 모범 사례를 따르는지 점검·권고받으려면?

<details><summary>정답 보기</summary>

타사 제품은 **AWS Marketplace**에서 구독해 배포합니다. 모범 사례 점검·권고는 **AWS Trusted Advisor**입니다.
</details>
